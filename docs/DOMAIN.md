## 1. 土地の答え — 3 つの層

利用者の問いは 1 つ（**この土地は、昔なんだったのか？**）。
答えは**根拠の種類**で 3 つに分かれ、**確実性の高い順**に出す（[ADR 0030](adr/0030-土地の答えは確実性の高い順に3層で出す.md)）。

| | ⚠ **層が答える問い** | 根拠 | 出す条件 |
|---|---|---|---|
| 1 | **ここは、どういう土地？** | 地形分類 | ⚠ **常に** |
| 2 | **昔は、何があった？** | 明治期の低湿地データ | データがあるとき |
| 3 | **いま建っている建物は、何の上？** | 取り込み済みの建物の足元 | 建物があるとき |

⚠ **`第1層` `第2層` `第3層` は内部の呼び名。**画面に出さない。
⚠ **順序は重要度ではない。**根拠の種類と、解釈の順序。

### ⚠ 出典で気をつけること

- ⚠ **「提供実験」を「実験的で当てにならない」と読ませない。**
  提供の形式の話であって、⚠ **データの確からしさの話ではない**
- ⚠ **OpenStreetMap は ODbL。**⚠ **クレジットは、OSM を実際に載せているソースから出す**
- ⚠ **説明文は国土地理院の記述をそのまま使い、こちらで書かない**

  ⚠ **同じ土地でも答えが変わりうる**（[ADR 0021](adr/0021-同じ問いに答える実装を2つ持たない.md)）

⚠ **件数・割合・カバー範囲は [`SPEC.md`](SPEC.md) が持つ。**ここには書かない。

## 2. 語（⚠ 画面に出す語と、出さない語）

### 2-1. 第1層のもの

| 概念 | ⚠ **画面に出す語** | ⚠ **画面に出さない語**（出典・`/about`・コードでだけ） |
|---|---|---|
| 場所の指し方 | ⚠ **`この土地は`** | ⚠ `この場所は` は**使わない** |
| 成因 | 区分名そのまま（`旧水部` `扇状地` `氾濫平野・海岸平野` …） | `地形分類` `土地条件` |
| 人の手が入ったこと | ⚠ **`人の手で ○○ になっています`** | `人工地形` `artificial` |

⚠ **第1層で時間の語（`もとは` `昔は` `だった`）を使わない。**
⚠ **第1層は、いまの土地の成り立ち。**さかのぼるのは第2層で、混ざると層に分けた意味が消える。

⚠ **成因と人の手は、行を分ける。**1 行に混ぜると「もとから埋立地だった」に読める。

### 2-2. 第2層のもの

| 概念 | 画面に出す語 |
|---|---|
| 資料そのもの | `明治期の低湿地データ` |
| 時代 | ⚠ **`明治期（1868〜1912年）`**（⚠ **資料の年を作らない**） |
| 区分 | 区分名そのまま（`河川・湖沼・海面` `田` `荒地` …） |

### 2-3. 第3層のもの

| 概念 | 画面に出す語 |
|---|---|
| 建物が建っている地面 | ⚠ **`足元`** |
| 建物 1 件ずつの話であること | `建物ごと` |

## 3. 取得の結末（⚠ 3 つを混ぜない）

⚠ **同じ語を 2 つの状態に使わない**（[ADR 0029](adr/0029-画面の言葉は利用者の問いから決める.md)）。

| 内部の名前 | 何が起きたか | ⚠ 画面で言うこと | ⚠ 言ってはいけないこと |
|---|---|---|---|
| `ok` | 読めた | その値 | — |
| `ok` かつ 0 件 | 読めて、該当が無い | `記録なし` | ⚠ `判定できません` |
| `absent`（404） | ⚠ **その資料が、この土地を対象にしていない** | ⚠ **`整備対象外`**（⚠ 1 語に決める） | ⚠ **`無い`・`存在しない`** |
| `unreachable` | ⚠ **こちらが読めなかった**（通信断・時間切れ・拒否） | `読み込めませんでした` `いま出せません` | ⚠ **`無い`・`データなし`** |
| `notyet` | ⚠ **こちらがまだ用意していない** | `この場所ではまだ提供していません` | ⚠ **`取得できませんでした`**（回線のせいに読める） |

### 3-2. ⚠ 写真が「いま届いたか」（⚠ **上の 5 つとは別の軸**）

⚠ **上の 5 つは「その資料がこの土地を対象にしているか」。**
⚠ **こちらは「いま画面に届いたか」。**⚠ **混ぜない。**

| 内部の名前 | 何が起きたか | ⚠ 画面で言うこと |
|---|---|---|
| `ok` | 届いた | ⚠ **何も言わない**（出ているのが当たり前） |
| `pending` | 猶予（1.2 秒）の中 | ⚠ **何も言わない**（言うと読み込みのたびに光る） |
| `late` | ⚠ **猶予を過ぎても届かない。理由は知らない** | `まだ出ていません` |
| `fail` | ⚠ **落ちたのを実際に観測した** | `読み込めませんでした（理由）` |

⚠ **`late` と `fail` を混ぜない。**
⚠ **`late` は「まだ来ていない／404 で写真が無い」を含み、こちらは理由を知らない。**
⚠ **知らないことを「読み込めませんでした」と書かない。**

⚠ **404 は `fail` にならない。**⚠ **MapLibre は 404 を異常と見なさず、`<img>` からも理由が取れない。**
⚠ **「遅い」と区別できないので、`late` に留める。**

⚠ **接続の話は、こちらが知っている範囲でしか言わない。**
⚠ `navigator.onLine === false` のときだけ「インターネットに接続していません」と言い切り、
⚠ `true` のときは「接続を確認してください」に留める。

⚠ **層を 3 つに分けてある**（2026-08-20）。⚠ **越えない。**

```
public/photos.js   ⚠ **状態を決める。**⚠ **画面へ出す字を持たない**
public/words.js    ⚠ **字を決める。**⚠ **状態の作り方を知らない**
画面（index.html / peel3d.js）
                   ⚠ **置くだけ。**⚠ **何も判断しない**
```

⚠ **相手先の振る舞いが変わっても、直すのは `photos.js` の 1 か所。**
⚠ **言い方を変えるなら、直すのは `words.js` の 1 か所。**

---

⚠ **`absent` と `unreachable` と `notyet` は、原因の持ち主が違う。**
相手の資料の範囲 ／ 通信 ／ こちらの都合。⚠ **どれか 1 つに寄せない。**

⚠ **`⚠` は危険（災害リスク）に使う。**在庫や対応状況に使わない。

## 4. データモデル

⚠ **層を値として持つ。**⚠ **文字列を画面ごとに組み立てない。**

```
layersOf(...) → { layers: [ Layer, ... ], missing: [ Missing, ... ] }
```

⚠ `layers` は必ず層の番号順。立たない層は入らない。

**`Layer`** — `n`（内部）／ `title`（層の問い）／ `head` ／ `what` ／ `den` ／ `subs[]`

⚠ **`head` は 3 種に分ける**（1 つの文字列にしない）。

| 種 | 中身 | ⚠ 決まり |
|---|---|---|
| `pct` | 数字 | ⚠ **`den`（分母）が無ければ作れない** |
| `name` | 区分名 | 押せる（意味を出す） |
| `none` | 出せない | ⚠ **数値を作らない**（0% を出さない） |

**`Missing`** — `n` ／ `why`（`unread` / `outside` / `notyet`）／ `say`

⚠ **出ない層も、その層の位置に置く。**黙って消すと「その土地に何も無い」に読まれる。
⚠ **`say` は `WORD` が持つ。**ここで文を作らない。
