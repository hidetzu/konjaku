# 根拠のないことは書かない。断定ではなく引用のときは、出典を添えて要約しない

- 状態: 採用
- 日付: 2026-08-05（旧 §3.5）

## 何が問題だったか

「地図に時間軸を足す」という軸を選んだ時点で、**歴史語りは最もハルシネーションしやすい領域**だという前提があった。
今昔マップも地理院地図も、2枚を並べて切り替えるところまでしかやらない。
空白は「なぜこうなったか」の言語化にあるが、そこに文を置いた瞬間に、根拠から離れる。

このプロジェクトの中心は地図ではなく、**判定に根拠を要求する仕組みのほう**である。
地理院タイルは `access-control-allow-origin: *` を返すので canvas から直接ピクセルを読める。
つまり「その座標が明治期に何だったか」を、**言葉でなくデータで確定できる**。この性質の上に全部が乗っている。

## 何を測ったか

この仕組みは**実装者自身の誤りを実際に捕まえた。**

当初は「alpha > 0 なら低湿地」という二値判定だったが、凡例（`lw_legend.pdf`）を復元すると **14区分**あり、
豊洲や夢の島は「低湿地だった」のではなく **「水面だった」**と分かった。

```
豊洲の建物を1件ずつ判定 → 明治期に水だった上に建つ建物 99.6%（533件）
```

機械的に弾ける誤りとして、少なくともこれだけが実在した:
年代の逆転／整備範囲外の座標／レイヤに存在しない地物名／写真年代と記述年代の不一致。

## 決めたこと

- **生成は保証しない。検証が保証する。** 価値は生成側ではなく検証側に置く
- **出すのは判定できることだけ。** 判定できないことは、書かない
- **断定ではなく引用のときは、出典を必ず添える。** そして**要約しない** ―― 要約すると原典より強くも弱くもなる。
  災害リスクの見出しに危険の中身を書かないのはこのため
- **並べ替えの根拠も、数えた事実だけ。** 「本命」「たぶんここ」は書かない
- 共有カードは最も遠くまで届く画面なので、**ここで断定すると被害が最も大きい**。カードにも粒度を書く

## そうしなかったこと

- **今昔マップのタイルを使う** … 使用上の注意で**タイル画像の独自配信を明示的に禁止**している。埋め込み以上のことはできない。
  加えて運営表記が「谷謙二（2000〜2022年）」で、継続性リスクを背負う。土台は地理院タイルにした
- **報告書を自動生成する（地歴調査フェーズ1）** … 1件30〜50万円・2〜4週間の相場が実在し、根拠資料に戻って検証できる形なので
  噛み合うが、**見落としの責任が重い**。「調査者の下調べを速くする道具」に留める
- **生成AIで解説文を書く** … 0005 を参照

## これを守っているもの

- `public/verify.js` の原則コメント（`§3.5 / §3.20`）と事実の型
- `public/index.html` — 災害リスクは断定ではなく引用なので出典を必ず添える／見出しに危険の中身を書かない
- `public/places.js` — 出すのは数えた事実だけ
- `public/share.js` — 共有カードで断定しない
- `npm run render` の `共有カードでも、粗いときは粗いと書く`（canvas の `fillText` を横から控えて**カードの中身**を見る）
