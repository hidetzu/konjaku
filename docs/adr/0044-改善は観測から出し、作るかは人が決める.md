# 0044. 改善は観測から出し、作るかは人が決める

- 状態: 採用
- 日付: 2026-08-28

## 背景

⚠ **同じ摩擦が、⚠ 別の Issue として何度も立っていた。**

⚠ **実測（2026-08-28・`gh issue list --state all` の全 95 件・⚠ 題名だけで数えた）**:

```text
題名に「初期画面に収まるか」を持つ   4 件   hidetzu/konjaku#16 hidetzu/konjaku#167 hidetzu/konjaku#176 hidetzu/konjaku#281
題名に「色・コントラスト」を持つ     4 件   hidetzu/konjaku#96 hidetzu/konjaku#282 hidetzu/konjaku#305 hidetzu/konjaku#306
題名に「同じことを 2 か所」を持つ    8 件   hidetzu/konjaku#90 hidetzu/konjaku#98 hidetzu/konjaku#99 hidetzu/konjaku#138 hidetzu/konjaku#139 hidetzu/konjaku#142 hidetzu/konjaku#152 hidetzu/konjaku#169
```

⚠ **8 件は、⚠ 中身を読んでも全部本物だった**（⚠ 語のまぐれ当たりは 0 件）。

⚠ **これまでは、⚠ 摩擦が起きるたびに Issue を立てていた。**
⚠ **摩擦そのものを減らす仕組みは、⚠ 誰も見ていなかった。**

## 決めたこと

⚠ **観測から改善候補を出す道具を足す**（`.claude/tools/improvement.mjs`）。
⚠ **候補を出すところまで。**⚠ **Issue を作るのは人。**

```text
Telemetry     ⚠ 何が起きたかを記録する（⚠ 書く）
Eval          ⚠ 観測した事実を、⚠ Task 単位で並べる
Improvement   ⚠ 複数の結果から、⚠ 仕組みの直し先を出す   ⚠ ← 足したもの
```

## なぜ Eval / Loop Controller へ入れなかったか

⚠ **見ている単位が違う。**

```text
Eval                 1 つの Task            ⚠ 起きたことを並べる
Loop Controller      1 つの Issue           ⚠ いま進めるものを回す
Improvement          複数の Issue をまたぐ  ⚠ 繰り返しを見る
```

⚠ **Eval に入れると、⚠ 「並べる」と「解釈する」が 1 つになる。**
⚠ **`docs/adr/0036` で「Eval は観測を比べるだけ、⚠ 採点しない」と決めている。**
⚠ **改善候補は解釈なので、⚠ そこへ混ぜると境界が崩れる。**

⚠ **Loop Controller に入れると、⚠ 実行中の判断が「改善したほうがよい」に引きずられる。**
⚠ **いま頼まれた Issue を終わらせることが先**（`CLAUDE.md` §7）。

## なぜ専用 DB をまだ使わないか

⚠ **いま読む量は、⚠ 全部で 100 行の桁**（⚠ 実測: `events.jsonl` は 1 セッションで数行、
⚠ GitHub 側は 95 件）。⚠ **JSONL を読み切って算数するだけで足りる。**

⚠ **`CLAUDE.md` §3 が「Runtime 依存を増やさない」と言っている。**
⚠ **記録は `docs/adr/0035` で Git の外に置くと決めた。**⚠ **DB を足すと、⚠ 置き場と
⚠ バックアップと ⚠ 移行が要る。**⚠ **読むのが遅くなってから決める。**

## なぜ改善 Issue に `ready-for-ai` を自動で付けないか

⚠ **`CLAUDE.md` §7-2 が「付けるのは人だけ」と決めている。**
⚠ **改善 Issue は、⚠ その規則の外に出る理由が無い。**

⚠ **むしろ改善 Issue は、⚠ ふつうの Issue より危ない。**
⚠ **仕組み（Skill・Hook・検査）を触るので、⚠ 間違えると全部の作業に効く。**

```text
AI が候補を出す  →  人が Issue にする  →  issue-ready  →  必要なら Owner  →  Loop Controller
```

⚠ **既存の入口を壊さない。**

## なぜ「Owner とのやりとりを減らす」だけを目安にしないか

⚠ **減らすだけなら、⚠ 聞かずに決めれば達成できる。**⚠ **それは改悪。**

⚠ **`CLAUDE.md` §7-1 は「間違えたときに取り返しがつかないものは聞く」と決めている。**
⚠ **画面に出る言葉・範囲・仕様は、⚠ 聞くべきもの。**⚠ **回数が減ったら良い、ではない。**

⚠ **だから、⚠ この道具は「回数」を目標に置かない。**⚠ **出すのは次だけ**:

```text
何が起きたか（観測）  ／  根拠（どこから来た数字か）  ／  解釈（⚠ 確かでないことも書く）
```

⚠ **良し悪しの点を付けない**（`docs/adr/0036`）。

## なぜ tcpip-stack とまだ共通ライブラリ化しないか

⚠ **2 つ目がまだ現れていない。**⚠ **`.claude/rules/domain.md` が
「2 つ目が実際に現れてから共通化する」と決めている。**

⚠ **いま tcpip-stack 側は、⚠ この記録を 1 行も持っていない。**
⚠ **移せる形にはしてある**（⚠ 置き場は `KONJAKU_TELEMETRY_DIR` で差し替えられる。
⚠ Issue の題名で当てる部分だけが konjaku の語に依存している）。
⚠ **向こうで実際に使い、⚠ 語の当て方が違うと分かってから切り出す。**

## ⚠ 何を観測していないか

⚠ **これは仕様。**⚠ **足りないのではなく、⚠ 採らないと決めた**（`docs/adr/0035`・`0036`）。

```text
誰が答えたか                 ⚠ 採らない
問いと答えの本文             ⚠ 採らない（⚠ 長さだけ持つ）
approval か否か              ⚠ 観測していない（⚠ 本文を持たないので分けられない）
Verify / Review の判定        ⚠ 観測していない
Task の結末（merged 等）      ⚠ 採点しないと決めている
```

⚠ **道具は、⚠ これらを `{ value: null, observed: false, reason: … }` の形で出す。**
⚠ **`null` を 0 と読ませない。**⚠ **0 は「起きなかった」、⚠ `null` は「分からない」。**

## ⚠ 踏んだこと

⚠ **① 本文まで見ると、⚠ 当たりが 3〜5 倍に膨らんだ**（⚠ 実測・全 95 件）。

```text
初期画面に収まるか   題名 4 件  →  題名+本文 21 件
同じことを 2 か所    題名 8 件  →  題名+本文 31 件
```

⚠ **Issue の本文が `CLAUDE.md` の掟を引用しているため。**⚠ **題名だけを見る。**

⚠ **② 改善 Issue が、⚠ 自分の根拠に数えられていた。**
⚠ **`[AI workflow] 「初期画面に収まるか」…` を置いたら、⚠ 根拠が 4 → 5 件に増えた。**
⚠ **放っておくと、⚠ 摩擦が起きていないのに件数だけ増える。**
⚠ **題名が `[AI workflow]` で始まるものは、⚠ 根拠から外す。**
