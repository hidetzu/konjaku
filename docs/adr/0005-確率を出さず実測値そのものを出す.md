# 確信度を数値化しない。出すのは実測値そのものと、取り方と、既知の限界だけ

- 状態: 採用
- 日付: 2026-08-11（旧 §3.20）

## 何が問題だったか

外部から「土地の成り立ちワンフレーズ解説」の提案があり、**検証器を作って数値で信憑性を見せる**方向で詰めようとした。
「確信度 85%」のような数字を添える案である。

だが **確率を出すと、その数値自体が検証できない主張になる。**
85 に根拠が無いなら、それは**検証器の顔をした生成**でしかない。このプロジェクトが避けてきたものそのものになる。

## 何を測ったか

**近傍一致率は、確信度の指標にならなかった。** 区分の読み取りが境界付近で揺れるかを、近傍 15×15 画素の一致率で測った。

```
豊洲(内陸側) 100% ／ 豊洲(岸ぎわ) 100% ／ 木場(貯木場) 97.8% ／ 隅田川ぎわ 97.3%
亀戸・清澄・有明・浦安 100%
```

**ほぼ常に100%。画素の読み取りはそもそも確実で、単独では指標にならない。**

⚠ ただし実装時に訂正が入った。江東区周辺だけを見て「ほぼ常に100%」と書いたが、**大阪 此花では 71.1%** だった。

```
豊洲・亀戸・清澄白河   100%     → 断定してよい
木場・隅田川ぎわ      97〜98%   → 断定してよい
大阪 此花             71.1%    → 境目。断定してはいけない
```

一方、**標高（DEM）は強い事実層**になった。`dem5a`（5mメッシュ）から数値で取れる。

```
皇居 13.40m ／ 浦安 3.54m ／ 豊洲 1.91m ／ 大阪 此花 -0.79m ／ 亀戸 -0.57m
```

**亀戸は明治期に「田」で、いま海面下。** 事実2つが1つの物語になる。作文を足す必要がない。

そして本当の不確かさは読み取り精度ではなく、**データの性格の側**にあると分かった。

| 不確かさ | 実体 |
|---|---|
| 原典の位置誤差 | 凡例に「場所によってはかなりの位置誤差を含む」（三角点整備前の資料） |
| 「該当なし」の多義性 | 凡例に「草地・荒地は山地や台地上のものは取得しない」。**該当なし＝低湿地でなかった、ではない** |
| 整備範囲外 | 全国の主要都市周辺のみ |

## 決めたこと

出すのは、**捏造しない数値だけ**。

| 出すもの | 例 |
|---|---|
| 実測値そのもの | `rgba=147,200,254` / `標高 -0.57m` / `一致率 97.8%` / 図式コード |
| 取得方法 | 直読み / 計算 / 推定 |
| 根拠へのリンク | 参照したタイルのURL |
| 既知の限界 | 位置誤差／該当なしの多義性／整備範囲 |

- **確率・確信度は出さない**
- 一致率は「常時出す指標」ではなく、**しきい値（90%）を下回ったら言い切りをやめる**という使い方にする。
  「田でした」ではなく「**田だったとみられます（区分の境目にあたります）**」
- 事実の集合（`{ key, label, value, method, evidence, caveat, ok, state }`）を作り、文はそこからテンプレートで組む。
  **事実が正しければ文も正しい**という関係を保つ

## そうしなかったこと

- **確信度スコアを出す** … 根拠の無い数値は生成でしかない
- **一致率を常時表示する** … ほぼ100%になるので情報量が乏しく、数字があること自体が権威に見える
- **LLM で文章を書かせる** … 得るものが「読みやすさ」だけで、失うものが「正しさの保証」。
  将来入れるなら条件は2つ ―― ①事実集合（JSON）だけを渡し、それ以外を書かせない
  ②生成文を再度検証器にかけ、事実集合に無い数値・区分名が出たら捨てて再生成する。
  **先に検証器を作れば後から生成を足せる。逆はできない**

## これを守っているもの

- `public/verify.js` の冒頭の原則コメントと、事実の型（`method` / `evidence` / `caveat` / `state`）
- `public/index.html` — 「根拠は実測値そのものを出す。確率は出さない」
- `public/places.js` — 並べ替えの根拠は応答が返す4フィールドだけ。「本命」「たぶんここ」は書かない
- `npm run render` の `同じ画面で自分と食い違わない` / `取れなかったカードに「実測」と書かない`
