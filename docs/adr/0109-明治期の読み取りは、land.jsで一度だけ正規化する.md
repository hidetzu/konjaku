# 0109. 明治期の読み取りは、land.js で一度だけ正規化する

- 日付: 2026-10-03
- 状態: 採用
- 決めた人: Owner（⚠ **案 B'**）

## 何が起きていたか

⚠ **代表回答の経路に、⚠ correctness の問題が 2 件あった**（⚠ 実測で再現した）。

```text
① 読み取れなかったのに、断定していた
   見出し  ここは 区分を特定できず でした
   ⚠ 内部語が出るうえ、⚠ 「取れなかった」を「でした」と言い切っていた（掟 §1・§4）

② 線型地物を、土地の答えにしていた
   ⚠ 堤防は公式の凡例で「線型データ」（⚠ 残り 13 は「面型データ」）
   ⚠ 土地が堤防だったのではなく、⚠ そこに構築物が描かれていた
```

### ⚠ 本質は、⚠ 判定ミスではなかった

⚠ **`verify.js` は事実を返していた**（`ok: false` を立てていた）。
⚠ **画面が、⚠ その生データを勝手に解釈していた。**

```text
deep.js:91   (!m || UNREACHABLE) ? {none:"unreachable"} : ABSENT ? ... : !m.value ? ... : {value}
top.js:595   ⚠ 同じ判断が、⚠ もう 1 か所（掟 6）
deep.js:585  ⚠ 3 か所目（⚠ 年代を並べる節も `${m.value} でした` と断定していた）
```

⚠ **どこも `ok` を見ていない。**⚠ **`state` だけで分けていた。**

## 決めたこと

⚠ **`land.js` が、⚠ 一度だけ今昔の語彙へ正規化する。**

```text
verify.js   事実を返す（読めた／読めない・何に分類した・線型か）
    ↓
land.js     ⚠ ここで一度だけ正規化
    ↓
{ kind: "area",      value: "泥地" }    ⚠ 代表回答に使えるのはこれだけ
{ kind: "structure", value: "堤防" }    ⚠ 捨てない。⚠ 代表回答には使わない
{ kind: "none", reason: "unreachable" | "absent" | "unmatched" | "noClass" }
    ↓
deep.js / top.js / answer.js   ⚠ 解釈しない
```

### ⚠ `unmatched` と `noClass` を潰さない

```text
unmatched  凡例のどの色とも一致しない ＝ ⚠ 読み取れなかった
noClass    その画素に色が無い       ＝ ⚠ 低湿地に該当しなかったか、取得対象外か
```

⚠ **両方を `noClass` へ落とすと、⚠ 「読み取れなかった」が「区分が無い」になる**（掟 §1）。
⚠ **字も分ける**（Owner が決めた字）。

```text
unmatched  この地図からは、この場所の区分を読み取れませんでした
noClass    この地図に、この場所の区分はありません
```

⚠ **バッジは `words.js` の「判定できません」**（⚠ 「記録なし」と混ぜない。⚠ あちらは 0 件）。

### ⚠ 堤防は、⚠ 保持するが代表回答に使わない

⚠ **今回はそこで止める**（Owner 判断）。
⚠ **「明治期の地図では、この場所に堤防が描かれています」まで出すのは、⚠ 新しい情報設計。**
⚠ **堤防の下の土地分類は推定しない**（⚠ `value` を空にするだけで、⚠ 別の区分を当てない）。

### ⚠ `docs/adr/0101` は変えない

⚠ **明治期が優先、は維持する。**⚠ **変えたのは「何を明治期の答えとみなすか」だけ。**

## ⚠ 控えの版を上げた

⚠ **`land.js` の `V` を `v1` → `v2`。**
⚠ **上げないと、⚠ 古い控えの `value: "区分を特定できず"` が代表回答に戻る。**

## 検査

```text
静的   正規化の 6 経路を固定（area / structure / unmatched / noClass / absent / unreachable）
       ⚠ 線型と「読み取れず」が代表回答にならないこと
       ⚠ 状態を作るのは land.js の 1 か所（⚠ 画面が自分で作っていないこと）
       ⚠ MEIJI_NONE は 4 状態（⚠ 字がどれも違うこと）
実描画 凡例に無い色のタイルを返し、⚠ 内部語が出ず、⚠ 断定しないこと
```

⚠ **わざと壊して、⚠ 狙った理由で落ちることを確かめた**（2026-10-03）。

```text
kind の判定を外す        → 線型 が代表回答になっている: ここは 堤防 でした
unmatched の分岐を消す   → 正規化（読み取れず）が noClass（⚠ unmatched のはず）
verify.js を前の形へ     → 内部語が画面に出ている: ここは 区分を特定できず でした
```

## ⚠ 残件（⚠ 2026-10-03 に片付けた）

⚠ **読み取れなかったことが、⚠ 画面に出ない場合があった**（⚠ 実測・豊洲）。

```text
前   見出し  ここは、かつて水面で、その後陸地にされた土地   ⚠ 地形分類（正しい）
     断り    （出ていない）                                ⚠ 読み取れなかったことが出ない
後   断り    明治期の地図からは、この場所の区分を読み取れませんでした
```

⚠ **`answer.js` の分岐 2（`PAST_IN_TERRAIN`）だけ、⚠ 断りに明治期の限界を入れていなかった。**
⚠ **理由はどこにも書かれていない**（⚠ `docs/adr/0101` は「変えていない」とだけ）。
⚠ **分岐 3 と同じ字・同じ場所にした。**⚠ **同じ事実を答える判断を 2 通りに分けない**（掟 6）。

```text
変えていない   見出し（⚠ 昔を名指す区分は、そのまま代表回答）
変えていない   読めた資料からの答え
足した         読み取れなかった／資料の対象外／区分が無い／読み込めなかった の断り
出さない       線型（堤防）のとき（⚠ 読めている。⚠ 限界ではない）
```

⚠ **検査**: ⚠ 4 状態とも断りが出ること・⚠ ふつうの区分と同じ字であること・
⚠ 線型のときは出さないこと（静的）／⚠ 実画面で「読み取れませんでした」が出ること（実描画）。
⚠ **わざと前の形へ戻して、⚠ 狙った理由で落ちることを確かめた。**
