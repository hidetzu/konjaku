# 見え方の判断は、文章と px だけで仰がない

- 状態: 採用
- 日付: 2026-08-28

## 判断

⚠ **見え方を Owner に決めてもらうときは、⚠ いまと案を同じ切り取りで撮って並べ、
⚠ 推す案と、⚠ 何を失うかまで作ってから聞く。**

```text
問題を見つける  →  見て決める問題か分ける  →  いま／案を撮る  →  推す案を書く  →  Owner が選ぶ
```

⚠ **Owner を外すためではない。**⚠ **Owner の判断コストを下げるため。**
⚠ **決めるのは Owner のまま。**

道具は `scripts/visual-decision.mjs` の 1 本、
決め方は [`.claude/skills/visual-decision`](../../.claude/skills/visual-decision/SKILL.md)。

## なぜ

⚠ **見え方を決めた Issue のうち、⚠ 判断材料に絵があったのは 45 件中 1 件だった**
（⚠ 2026-08-28 に、⚠ 全 95 件の本文を読んで数えた。⚠ 数え方は Skill §0）。
⚠ **残りは px などの数字（34 件）か、⚠ 文章（2 件）だった。**

⚠ **同じ症状が分かれた例がある**: ⚠ 「重ねる」が初期画面から出る
（hidetzu/konjaku#176 → hidetzu/konjaku#278 → hidetzu/konjaku#279 → hidetzu/konjaku#280 → hidetzu/konjaku#281）。
⚠ **前者を閉じた翌日に、⚠ 別の条件（横向き）で後者が出た。**
⚠ **前者は 1 つの条件の px で判断していた。**

⚠ **「絵があれば防げた」とは言わない**（⚠ 確かめていない）。
⚠ **言えるのは、⚠ 判断材料が 1 条件の数字だった、ということだけ。**

## ⚠ 責務を分ける

| | ui-ux-review | visual-decision（これ） | verify |
|---|---|---|---|
| 何をするか | ⚠ **画面を見直す**（⚠ 4 幅・重複・下限） | ⚠ **決めてもらう材料を作る** | ⚠ **主張が守られているか** |
| 落ちるか | 判定を返す | ⚠ **落ちない** | ⚠ **落ちる** |
| 誰が決めるか | 実装者 | ⚠ **Owner** | 検査 |

⚠ **絵を根拠に「検査した」と言わない。**⚠ **絵は判断材料。**⚠ **主張を守るのは検査。**

## ⚠ 決めていること

- ⚠ **撮るのは要素**（⚠ `--sel`）。⚠ **`fullPage` で撮ると版面が組み直され、⚠ 座標がずれる。**
- ⚠ **「画面外へ出た」は `--fold`**（⚠ 初期画面ぜんぶを撮り、⚠ 相手がその中に在るかを言う）。
  ⚠ **相手だけ切り取ると、⚠ はみ出しは見えない。**
- ⚠ **色みは両方撮る**（⚠ 片方だけ見て決めると、⚠ もう片方で割れる。
  ⚠ hidetzu/konjaku#282 で実際に起きた）。
- ⚠ **案は撮るときだけ CSS を当てて作る**（⚠ `--css`）。⚠ **製品を書き換えない。**
  ⚠ **その絵は「案」であって実装ではない、⚠ と明記して渡す。**
- ⚠ **効かない案は出さない**（⚠ 数字が動かないものを「案」と呼ばない）。
- ⚠ **画像は repo に置かない**（⚠ `tmp/` に出して会話で渡す）。
  ⚠ **公開リポジトリの Issue / PR に、⚠ 作業環境の絶対パスを書かない**（`CLAUDE.md` §8-1）。

## ⚠ やらないこと

```text
画像の自動比較（diff）      ⚠ 人が見る
すべての Issue へ強制        ⚠ 見て決める問題だけ
Owner 判断の自動化           ⚠ 決めるのは Owner
Telemetry / Eval の項目追加  ⚠ v1 では入れない（⚠ 効果測定は別に決める）
```
