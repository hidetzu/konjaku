# Eval は観測を比べるだけで、良し悪しを決めない

- 状態: 採用
- 日付: 2026-08-24

## 判断

計測（[0035](0035-開発の計測は配信の計測と分けてGitの外に置く.md)）で残した Task を、
⚠ **種別ごとに並べて見比べられるようにする**（Eval Phase 1）。

⚠ **採点はしない。**⚠ **成功・失敗・品質・自律性を、⚠ 数字にしない。**

```text
AI Task  →  Telemetry  →  tasks.jsonl  →  Eval  →  種別ごとに見比べる
```

道具は `.claude/tools/telemetry-eval.mjs` の 1 本だけ。

```bash
node .claude/tools/telemetry-eval.mjs
node .claude/tools/telemetry-eval.mjs --json
```

## ⚠ 責務を分ける

| | Telemetry（0035） | Eval（これ） |
|---|---|---|
| 何をするか | ⚠ **観測して残す** | ⚠ **残ったものを比べる** |
| いつ動くか | Hook（`UserPromptSubmit` / `Stop`） | ⚠ **人が呼んだとき** |
| 書くか | ⚠ **書く**（追記だけ） | ⚠ **1 バイトも書かない** |

⚠ **Eval は読むだけ。**⚠ **compact も並べ替えも書き戻しもしない。**
⚠ **生の記録を触ってよいのは、⚠ 書いた側だけ**（`.claude/hooks/telemetry.mjs`）。

⚠ **同じ task_id の最後の行を、⚠ いまの状態として採る**（⚠ Telemetry 側の契約）。

## ⚠ なぜ Phase 1 で採点しないか

⚠ **観測していないから。**⚠ **それ以外の理由ではない。**

いまの記録には、次が 1 つも入っていない。

```text
コードが正しいか      Issue を達成したか      CI が通ったか
人が満足したか        余計な変更が無いか      直しが何回入ったか
```

⚠ **だから次は出さない**（⚠ **出せば、⚠ 観測していないことを言ったことになる**）。

```text
success rate ／ failure rate ／ quality score ／ agent score
productivity ／ autonomy ／ PASS・FAIL ／ GOOD・BAD ／ 総合点
```

⚠ **「1 Turn だから優秀」「短いから優秀」「Turn が多いから悪い」も言わない。**
⚠ **速いのは、⚠ 用事が小さかっただけかもしれない。**⚠ **区別できていない。**

⚠ **静的検査が、⚠ 出力に採点の欄が生えたら落とす**（`test/check/eval.mjs`）。

## ⚠ 事実と推定を混ぜない

⚠ **記録のうち、⚠ 次の 3 つは推定値**（0035）。

```text
grouping ／ task_type ／ task_type_source
```

⚠ **種別ごとの表は、⚠ この推定値で行を分けている。**
⚠ **だから、⚠ 表のすぐ上に断りを付ける。**⚠ **`--json` は `estimated_fields` で名乗る。**

⚠ **本文のどこかに書いてあるだけでは足りない**（`CLAUDE.md` §9）。
⚠ **実際に踏んだ**（2026-08-24）: 表の見出しから断りを消しても、
⚠ **下の「読み方」の別の文を拾って検査が通った。**
⚠ **いまは、⚠ 表のすぐ上に付いていることまで見る。**

### ⚠ Turn 数を種別間で比べても意味がない

⚠ **`grouping=turn` の Task は、⚠ 定義上 `turns=1`・Session 1 個になる**
（⚠ 1 プロンプト = 1 Task と決めたため。0035）。

⚠ **束ね方の帰結であって、⚠ 観測ではない。**⚠ **出力にそう書く。**

## ⚠ 母数を混ぜない

⚠ **終わりを観測できた Task だけで所要時間を出す。**
⚠ **終わっていない Task を 0 秒として平均へ混ぜない**（⚠ **一瞬で終わったことになる**）。

```text
Tasks: 20
  終わりを観測できた: 17
  終わっていない:      3
```

⚠ **数字ごとに母数を持たせる**（`CLAUDE.md` §6）。⚠ **どれも同じ母数ではない。**

- 所要時間の母数 … ⚠ 終わりを観測できたぶん
- 1 Turn 率の母数 … ⚠ Turn 数が読めたぶん
- 複数 Session 率の母数 … ⚠ Session の一覧が読めたぶん

⚠ **1 件も無いときは `null` を返す。**⚠ **`0` にしない**（⚠ **「測ったら 0 だった」に読める**）。

⚠ **読めなかった行は数えて名乗る。**⚠ **黙って捨てない**
（⚠ **捨てると、⚠ 母数が減ったことに誰も気づけない**）。

⚠ **落ちる理由が違うものは、⚠ 分けて数える。**

| 欄 | 何が起きたか |
|---|---|
| `unreadable_lines` | ⚠ **JSON として壊れている** |
| `invalid_task_rows` | ⚠ **JSON としては読めるが、⚠ `task_id` が無くて Task にできない** |

### ⚠ 見ている期間は「最古と最新の観測時刻」

⚠ **終わりの最後を終端にしない**（2026-08-24。⚠ **実際にずれた**）。

```text
Task A  20:00 開始 → 20:10 終了
Task B  21:00 開始 → ⚠ まだ終わっていない

⚠ 終わりだけを見ると        Period: 20:00 - 20:10
⚠ B も集計に入っているのに、⚠ 範囲の外に出る
```

⚠ **始まりと終わりを一緒くたに並べて、⚠ 両端を採る。**

⚠ **文字列のまま並べ替えない。**⚠ **同じ瞬間でも書き方が違う**
（`2026-08-25T00:30:00+09:00` は `2026-08-24T16:00:00Z` より ⚠ **前**。
⚠ 文字列順では後ろに見える）。⚠ **実際の瞬間で比べる。**

⚠ **p90 は補間しない。**⚠ **実際に測った値をそのまま返す**（`CLAUDE.md` §6）。

## ⚠ 次に「成功したか」を測るには

⚠ **Eval を賢くしても出てこない。**⚠ **観測していないものは、⚠ 集計しても現れない。**
⚠ **足すのは Telemetry 側。**

```text
Verify の結果（PASS / FAIL / NOT-VERIFIED）
CI の結果（全部緑か）
PR が merge されたか ／ Issue が閉じたか
人が途中で止めた回数 ／ 同じ場所を直し直した回数
```

⚠ **どれも、⚠ 足すときに「何をどう測ったか」を同時に決める。**
⚠ **`result` を `unknown` から動かすのは、⚠ そのとき。**

## 変更時の確認事項

- ⚠ **新しい数字を足すときは、⚠ 母数を先に言う**
- ⚠ **観測していないものを、⚠ 集計から作らない**
- ⚠ **推定値で行を分けるなら、⚠ その場に断りを付ける**（⚠ 遠くに書かない）
- ⚠ **生の記録へ書き戻さない**（⚠ 書くのは Telemetry 側だけ）
