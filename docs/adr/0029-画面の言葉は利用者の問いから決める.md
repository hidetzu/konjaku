# 画面の言葉は、利用者の問いから決める

- 状態: 採用
- 日付: 2026-08-17

## 決めたこと

利用者向け UI に出す言葉は、内部の分類名でも取得経路の名前でもなく、
**利用者がその画面で持っている問い**から決める。

### 1. 作り手側の分類を、そのまま画面に出さない

「自前で持っているか、外部へ渡すか」「どの経路で取ったか」は実装には要るが、
利用者の問いではない。出すなら、利用者が判断に使える形へ言い換える。
言い換えられないなら出さない。

⚠ **曖昧な言葉へ移し替えるだけにしない。** 内部語を消した結果、
何も言っていない言葉が残るなら、それは直したことにならない。

### 2. 4つの状態を、別の言葉で書き分ける

| 状態 | 何が起きたか | 何と書くか |
|---|---|---|
| 正常0件 | 読めた。該当する記録が無い | 見つかっていない、という書き方にする。「無い」と断定しない |
| 対象範囲外 | その資料がこの土地を対象にしていない | 資料の対象範囲外だと書く。その土地の性質にしない |
| 取れなかった | 通信断・時間切れ・拒否 | 読み込めなかったと書き、再試行を出す |
| 判定できない | 読めた。この地点では値が決まらない | 何が決まらないのかを書く。値を作らない |

⚠ 取得結果そのものの3状態（`ok` / `absent` / `unreachable`）は
[0001](0001-取れなかったを無いと言わない.md) が決めている。ここで足しているのは、
**`ok` の中を「該当が無い」と「値が決まらない」に分けて書く**ことと、
4つに別々の言葉を割り当てることだけ。

⚠ **同じ語を2つの状態に使わない。** 「ありません」は、正常0件にも未取得にも読める。
どちらか一方の状態に割り当て、もう一方では使わない。

### 3. 同じ概念には、トップと `/peel` で同じ語を使う

両画面が同じことをする以上、片方だけ別の名前にしない。
やむを得ず2か所に同じ文言を置くときは、機械で突き合わせる
（[0021](0021-同じ問いに答える実装を2つ持たない.md)）。

## なぜ

内部語は、書いた本人には意味が通る。だから、画面に出ていることに気づけない。
実際に「自前・根拠あり」「直読み」「未取得」が、説明なしで画面に出ていた。

そして**言い換えは、事実を弱める方向にも強める方向にも滑る**。
「取れなかった」を「ありません」と書けば、無かったことになる。
だから言い換えの規則は、好みではなく、**どの状態を指しているか**から決める。

## これを守っているもの

- `scripts/check.mjs`「9. 画面の言葉」— 画面に出ている語の棚卸しを持つ。
  ⚠ **両方向で見る。** 表が「まだ残っている」と言う語が画面から消えていても落ちる。
  片方向だと、直した先から表のほうが黙って古くなる

⚠ **画面はまだ、この決めごとに揃っていない。** 揃えるのは段階を分けて行う。
いまどの語が残っているかは、上の棚卸しが持っている（`next` の欄がその段を指す）。
ここに「揃っている」とは書かない（掟: 確認できないことを「検査済み」と呼ばない）。
