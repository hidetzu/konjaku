# POI は自前で持たない。既にあるものは Google マップへ渡す

- 状態: 採用
- 日付: 2026-08-11（旧 §3.13）

## 何が問題だったか

「場所のランチャー」構想 ―― 場所を決めて、そこについて何でも調べられる入口にする ―― 自体は正しい。
だが**そのまま作ると死ぬ。** 飲食・買い物・病院を自前で持ち始めた瞬間、
これは Google マップの core そのものになり、地図領域で最も勝てない場所に正面から入ることになる。

境界を**カテゴリ**（飲食は渡す、地図は持つ）で引くと必ず崩れる。引くべきは**情報の種類**の側だった。

## 何を測ったか

- **Google Places API: $2〜$40 / 1,000リクエスト**（SKUと層による）
- **2025年3月に $200 クレジットが廃止**され SKU ごとの無料枠に。
  Essentials 10,000/月、Pro 5,000/月、Enterprise 1,000/月
  - ⚠ **いずれも 2026-08-11 時点で公表されていた値。** 価格は変わる。
    この判断を見直すときは、**まず確かめ直すこと**
- ⚠ **他所のサービスが従量課金で行き詰まった事例は、ここに書かない。**
  匿名にしても経緯で特定できるうえ、**この判断は上の公表価格だけで成立する**
- OSM の店舗カバレッジは不均一（**2014年のローソン一括投入は差し戻されている**）
- そして「美味しい」はどのオープンデータにも存在しない。無料データでは埋まらない

## 決めたこと

境界は**カテゴリではなく「情報の種類」**で引く。

> **事実（存在・場所）は自前で持ち、公開する。**
> **評価は自前で持つが、公開しない。**
> **他人の評価は渡す。**

| | 扱い |
|---|---|
| 明治期の地形・土地の履歴 | **自前**。タイルの画素を読んで判定し、根拠を画面に出す |
| 空中写真の年代送り | **自前** |
| 自分の★とメモ | **自前だが非公開**。`localStorage` に保存し、JSON で書き出せる |
| 飲食店・スーパー・病院 | **渡す**（Google マップ）。評価・口コミは持っていない |
| ハザードマップ | **渡す**（重ねるハザードマップ） |

自前で持つかの判断基準は2つだけ ―― **①他所が持っていないか ②一次データに戻って検証できるか。**

- 自由入力は素直に Google マップへ渡す。**打てば出るので、機能は失われない**
- 上段が自前（検証あり）、下段はリンク（API料金ゼロ）と、**線を引いて見せる**
- リンクは落ちない。依存の形として一番強い

## そうしなかったこと

- **汎用POIランチャー（飲食・スーパー・病院を自前で持つ）** … コスト境界に真正面から当たり、
  無料データでは埋まらず、差別化も消える
- **Overture Maps の POI を自前配信する** … 持てることは確認したが（`confidence` 付きで来るのが決定的）、
  「美味しい」は手に入らないので、持っても Google に対する優位が生まれない
- **Google をキャッシュする** … 規約違反
- **遊び場・公園を自前で持つ** … OSM のポリゴンは使えるが優位性が薄い。渡す側へ

## これを守っているもの

- `public/index.html` — 自由入力は Google マップへ渡す。上段（自前）と下段（渡す）の線
- `public/places.js` — 外部リクエストは増やさない。1検索1リクエストのまま
- `npm run render` の `押せそうなものは、押すと何かが起きる` / `通信した先が、全部フッターに書いてある`
