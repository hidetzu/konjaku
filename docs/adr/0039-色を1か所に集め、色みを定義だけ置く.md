## 1. なぜ集めたか

⚠ **色は 3 か所に散っていた**（実測 2026-08-26・`main` = `6b0b885`）。

| どこ | 何個 |
|---|---|
| `public/css/tokens.css` | 6（`--evidence` `--estimate` `--missing` `--action` `--water` `--ink-faint`） |
| `public/index.html` の `:root` | 5（`--bg` `--surface` `--line` `--ink` `--ink-dim`） |
| `public/peel.html` の `:root` | ⚠ **同じ 5 つの名前。**⚠ **値が違う** |

⚠ **名前が同じで値が違うと、⚠ 色みを足したときに片方だけ切り替わる。**
⚠ **落ちない。**⚠ **切り替えた画面のうち 1 つだけが、前の色みのまま残るだけ。**

⚠ **色みを選べるようにするには、⚠ 色が 1 か所にまとまっている必要がある**（Issue の Background）。
⚠ **だから、⚠ 選ぶ操作より先に、⚠ 集めるほうをやった。**

## 2. 「画面ごと」ではなく「地図の上かどうか」

⚠ **`peel.html` の面が暗くて半透明なのは、⚠ `/peel` だからではない。**
⚠ **地図の上に重ねているから**（⚠ 元のコメントが「地図の上なので、面はより暗い」と書いていた）。

```text
:root                                     画面の地
:root[data-backdrop="map"]                地図の上に重ねる面（/peel）
```

⚠ **画面の名前で分けると、⚠ 3 つ目の画面が来たときに増える。**
⚠ **「地図の上か」で分けると、⚠ 同じ条件の画面はそのまま乗る。**

⚠ **値は運んだだけで、⚠ 1 つも変えていない**（⚠ 暗い色みの分）。

## 3. ⚠ なぜ、まだ切り替えられないようにしたか

⚠ **`prefers-color-scheme` を、⚠ わざと見ていない。**

⚠ **画面の色の大半は、⚠ まだこの変数を通っていない**（⚠ 実測 2026-08-26）。

```text
規則へ直に書いた色   173 か所
  index.html         106
  peel.html           30
  era-control.css     37
```

⚠ **いま端末の設定を見に行くと、⚠ 明るい設定の人だけが
「地は暗いまま・文字と操作だけ明るい」画面になる。**
⚠ **端末の設定は、⚠ 明るいほうが既定の人が多い。**⚠ **黙って壊れる人数が多い側に倒れる。**

⚠ **だから、⚠ この段は `[data-theme="light"]` の定義だけを置く。**
⚠ **付けるコードは、⚠ どこにも無い。**⚠ **定義が読めることだけを主張する**（`CLAUDE.md` §1）。

⚠ **次の段で足すもの**: `@media (prefers-color-scheme: light)` と `[data-theme="dark"]`
（＝端末の設定に従う／明るい／暗い の 3 つ）。⚠ **そのとき、⚠ 173 か所を先に寄せる。**
