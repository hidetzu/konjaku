# 同じ問いに答える実装を2つ持たない。持つなら機械で突き合わせる

- 状態: 採用
- 日付: 2026-08-12（最初の発見）／2026-08-14（型として確定）

## 何が問題だったか

繰り返し出た不具合の型が1つある。

> **同じ問いに答える実装が2つあり、片方だけ直した。**

- `isekai.html` を消したとき、`eras.html` が同じ独立コピーだと気づいていなかった。
  一度潰したはずの「通信断を『データ無し』と断定する」が、**丸ごと生き残っていた**
- トップを直すたびに `/peel` を直し忘れていた。**進行中だった**
- 事物の年の精度（`precision`）を、取り込み側は正しく扱うのに**実行時経路は `"year"` 決め打ち**だった
- 帯の差分計算を描画と「行き先探し」で別々に書いたため、**押した先が空になっていることに気づけなかった**

**どれも画面は何も言わない。** 静かにずれる。

## 何を測ったか

- `/peel` のピンが旧6件のまま: **6件中5件**が建物の索引に無く、押すと Overpass を最大20秒待つ。
  天王洲は `seeds/areas.jsonl` にも無かった
- `precision` の二重実装: 福徳神社が 静的「900 世紀」／実行時「**900年**」。
  取り込み済みは全国のごく一部なので、**公開すれば大半がこの経路**を通る
- 紀元前が桁ごと変わる: `slice(0,4)` で `"-0500-01-01"` → `"-050"` → **-50**（取り込み側は正しく -500）
- 枠外の絞りが実行時側に無く、**経度999/緯度91 が一覧に並び、印は1つも打たれない**
- `_headers` で `/data/ev/*` と `/data/*` の両方を書いていたため、Cloudflare は**一致した規則を全部連結**し、
  `cache-control: public, max-age=86400, public, max-age=0, must-revalidate` になっていた。
  **索引の穴を直すために入れた `must-revalidate` が効いている保証が無かった。**
  規則を分けて実ファイル105件に当てて確認。歯があることも確かめた（`/data/*` を戻すと**90件**を指して落ちる）
- 検査そのものも二重になっていた: 14区分表を4箇所に置いていた／
  `page.route("**://*.overpass*/**")` が**一度もマッチしていなかった**（`overpass-api.de` は先頭ラベルが overpass なので
  `*.` の前に置くものが無い）。実際には Overpass が応答して **6,439件**取れており、
  「待たせ続けない」を一度も確かめていなかった

## 決めたこと

- **同じ問いに答える実装を2つ持たない。** 切り出して1か所にする
  - 帯の差分は `hitsAt(i, all)` に切り出し、描画と行き先探しが同じ判定を使う
  - 検索の作法は `places.js` 1つ。トップも `/peel` も同じものを読む
  - 建物の詰め方は `scripts/bl-format.mjs` が唯一の定義。取り込みと詰め直しの両方がここを使う
- **やむを得ず2つある（書く側と読む側）ときは、機械で突き合わせる**
  - `check.mjs` が実際のタイル1枚を両方の手順に通して同じ形になることを見る。
    `peel.html` の関数本体を正規表現で取り出して `new Function` で動かすので、**写しではなく本物**を測る
  - 14区分表を持つ箇所の数を固定して見張る
- **ファイルを分けたら、検査の参照先も対で直す。** ずれると**緑のまま何も見ていない**状態になる
- **重なる設定を書かない。** 規則は重ならないように分け、実ファイルに当てて数える

## そうしなかったこと

- **片方を「正」と決めて、もう片方を目視で追従させる** … これが元の状態
- **検査のURLパターンをワイルドカードで書く** … 一度もマッチしないまま緑になる。URL の述語で見る
- **コピーを許して、コメントで注意を書く** … 実際に4箇所に散った

## これを守っているもの

- **年代の定義（id・ラベル・拡張子・ズーム範囲）は `public/verify.js` の1か所だけ**（2026-08-16 に追記）。
  `peel3d.js` が固定 8 段の写しを持っていたため、トップが「広島に残っているのは 5 年代」と
  正しく答えている横で、`/peel` は 9 段を出し、存在しない年代のタイルへ **404 を 202 件**送っていた
  （長崎 出島では 491 件）。`npm run check` の `年代の定義は verify.js の1か所だけ` と、
  `npm run render` の `トップと /peel が、同じ地点で同じ年代を出す（長崎 出島）` が見張る
- `scripts/bl-format.mjs`（唯一の定義）と `npm run check` の `建物の詰め方が、書く側と読む側で一致（313件で照合）`
- `npm run check` の `判定の表を持つのは peel3d.js と verify.js だけ` / `水に由来する区分の表は 3 箇所（上限 4）` /
  `_headers の規則が重なっていない（106 ファイルに当てて確認）` / `取り込みと実行時が、同じ型を拾っている（13 種）`
- `npm run render` の `世紀・年代の記録を、点の年として言い切らない` /
  `枠の外にあるものを、この範囲のものとして出さない` / `建物の索引と、事物の索引を混ぜない`
- ピンの検査は index / peel / 建物の索引の3つをまたいで見る
