# 0094. 連絡先は公開でよいかで分け、常時出る案内は増やさない

- 状態: 決めた
- 日付: 2026-09-05
- ⚠ **`contact@konjaku.hidetzu.work` を用意した**（Owner）。⚠ **どこに出すかを決める。**

## いままで（⚠ 実測 2026-09-05）

```text
名乗りのメニュー   8 画面すべてに同じ 4 つ    ⚠ 検査が「8 枚とも同じ」を固定
ページの下の案内   7 画面（⚠ 地図の画面を除く）⚠ 検査が「メニューと同じ集合」を固定
利用規約 第13条    運営者 hidetzu ／ 連絡先 GitHub の Issue
```

⚠ **GitHub は公開の場で、⚠ アカウントが要る。**⚠ **それが困る用件の行き先が無かった。**

## 何を決めたか

⚠ **`/about` に「連絡先」の節を作る**（2026-09-05。Owner 判断）。
⚠ **常時出る案内は 4 本のまま。**⚠ **増やさない**（`CLAUDE.md` §5「足す前に隠す」）。

```text
不具合・ご意見        GitHub の Issue   ⚠ 公開の場。⚠ アカウントが要る。⚠ 誰でも読める
その他のお問い合わせ  メール            ⚠ 公開の場に書きたくないこと
```

⚠ **分け方は「公開でよいか」**（Owner 判断）。⚠ **中身では分けない。**
⚠ **中身で分けると、⚠ 境目を利用者が判断できない。**

⚠ **既存の器（`.cards`）を借りた。**⚠ **新しい形を作っていない。**

## ⚠ 落とした案

```text
案A  規約と privacy にだけ書く      ⚠ 規約を読まない人には気づかれない
案B  メニューと下の案内に 1 本足す  ⚠ 常時出る案内が 4 → 5 本になる
```

## ⚠ プライバシーポリシーに書く（⚠ どの案でも要る）

⚠ **メールを受けると、⚠ 送信者のアドレスと本文がこちらに届く。**
⚠ **`/privacy` は「ここに書いていないことは、していません」と言っている。**
⚠ **書かないと嘘になる。**

⚠ **要約を 4 点 → 5 点にし、⚠ 節「5. メールはどう扱うか」を足した。**
⚠ **「以下は、上の 5 つをくわしく説明したものです。新しいことは足していません」を保つため、
⚠ 要約と節の両方を足した**（⚠ 片方だけだと、⚠ その 1 文が嘘になる）。

⚠ **書いたこと**:

```text
何が届くか      あなたが書いた本文と、送信元のアドレス
何に使うか      お問い合わせへの対応のため
渡さないか      対応以外の目的で、第三者に提供しない
消せるか        消してほしいときは、同じアドレスへ知らせてもらう
避けられないこと 配送そのものに、送信元と宛先、本文が伴う
                配送は Cloudflare のメール転送を経由する
```

### ⚠ 「返信のためだけ」と「第三者へ渡しません」をやめた（2026-09-05。Owner 指示）

⚠ **どちらも、⚠ 狭すぎるか、⚠ 実態と食い違う。**

```text
返信のためだけ      ⚠ 対応が返信だけとは限らない
第三者へ渡しません  ⚠ 配送そのものが第三者を経由する
```

⚠ **実測（2026-09-05）**: ⚠ `konjaku.hidetzu.work` の MX は
⚠ `route1.mx.cloudflare.net` / `route2` / `route3`。
⚠ **Cloudflare のメール転送を経由している。**

⚠ **だから、⚠ 目的で限る**（「対応以外の目的で、⚠ 第三者に提供しません」）。
⚠ **経由する相手も黙らない**（掟 §1）。

⚠ **検査は、⚠ 狭い言い方そのものを禁じる。**
⚠ **「対応のため」が別の文に在るだけでは足りない**（⚠ わざと戻したら素通りした。`CLAUDE.md` §9）。

⚠ **書かなかったこと**: ⚠ **いつ消すか。**⚠ **決めていないので書かない**（掟 §1）。
⚠ **「すぐ消します」「保存しません」は、⚠ 検査が落とす。**
