# 土地の答えは、確実性の高い順に 3 層で出す

- 状態: 採用
- 日付: 2026-08-19

## 決めたこと

`/peel` が「この土地は何だったのか」に答えるとき、**根拠の種類**で 3 つの層に分け、
**確実性の高い順**に出す。

| 層 | 名前 | 出す条件 | 根拠 |
|---|---|---|---|
| **第1層** | この土地について | ⚠ **常に出す** | 地形分類 |
| **第2層** | 昔の土地から見る | 明治期のデータがあるときだけ | 明治期の低湿地データ |
| **第3層** | いまの街から見る | 建物のデータがあるときだけ | 取り込み済みの建物 |

出す順は **第1層 → 第2層 → 第3層**。

⚠ **層の順序は、情報の重要度ではない。**⚠ **根拠の種類と、解釈の順序**を表す。
⚠ **第3層の値を視覚的に強調してよい**（強調を禁じると、豊洲の 99.6% が沈む）。

### どの割合が、どの層か

| | 層 | 分母 |
|---|---|---|
| 豊洲 **99.6%** | ⚠ **第3層** | 建物 533 件 |
| 名古屋 **1.7%** | ⚠ **第2層** | 範囲全体の面積 |
| 「この土地は 盛土地･埋立地」 | **第1層** | この地点 |

⚠ **99.6% と 1.7% は、別の層になる。**
同じ層に並ばないので、⚠ **同じ見た目で並べようがない**。
分母の違う数字が並ぶ問題が、**構造で片づく**。

### 出せない層は、黙って消さない

⚠ **層が立たないことと、その土地に何も無いことは別。**
出せない層は「なぜ出せないか」を、**その層の場所**で言う
（[0001](0001-取れなかったを無いと言わない.md)）。

⚠ **できないことから書き始めない。**第1層は必ず立つので、
⚠ **答えは常に「この土地について」から始まる**。

## なぜ

### 1. 実測すると、4 通りしかない（2026-08-19）

| 場所 | 建物 | 明治期 | 第1層 | 第2層 | 第3層 |
|---|---|---|---|---|---|
| 豊洲 | あり | あり | ✅ | ✅ | ✅ |
| 名古屋 | ⚠ 未対応 | あり | ✅ | ✅ | — |
| 札幌 | あり | ⚠ 対象外 | ✅ | — | ✅ |
| 那覇ほか 5 地点 | ⚠ 未対応 | ⚠ 対象外 | ✅ | — | — |

⚠ **4 通りすべてで第1層だけは必ず立つ。**
地形分類は全国 24 地点で **24/24** 取れている。
「常に出す」は、好みではなく**実測に裏づけられている**。

### 2. 層が無いと、画面ごとに順番が変わる

⚠ 実測（2026-08-19・`main` = `c8beb88`・`/peel` の `#land`）

| 場所 | 出ている順 |
|---|---|
| 豊洲 | 第3層 → 分母 → 第2層（⚠ **第1層が無い**） |
| 名古屋 | 第2層 → 出せない断り → 区分 |
| 札幌 | ⚠ **出せない断りから** → 第2層の否定 → 第1層 |
| 那覇 | ⚠ **同上**（第1層が最後） |

⚠ **1 地点もこの決めごとを満たしていない。**
文字列を画面ごとに組み立てていて、**層という値がコードに無い**ため。

### 3. 名前は、利用者の問いから取る

⚠ **`第1層` `第2層` `第3層` は内部の呼び名。**画面にも、コードの表示側にも出さない
（[0029](0029-画面の言葉は利用者の問いから決める.md)）。

⚠ **層の名前は、その層が答えている「問い」で呼ぶ**（2026-08-19 決定）。

| 層 | ⚠ **利用者の問い** | 根拠 |
|---|---|---|
| 1 | **ここは、どういう土地？** | 地形分類 |
| 2 | **昔は、何があった？** | 明治期の低湿地データ |
| 3 | **いま建っている建物は、何の上？** | 取り込み済みの建物の足元 |

### 4. 第1層の言葉（⚠ 2026-08-19・PO / UX / UI / 利用者役 4 名で決めた）

⚠ **実測**（`main` = `c8beb88`）。同じ第1層が、画面ごとに違う形で出ていた。

```
豊洲 トップ   もとは 水だった土地（旧水部）です。いまは 盛土地･埋立地 です。
札幌 トップ   この場所は 扇状地 です。
豊洲 /peel    この土地は 旧水部 ／いまは 盛土地･埋立地
```

⚠ 主語は `この場所` 1 : `この土地` 9。コード側の呼び名は **4 通り**
（`地形分類` 13 ／ `土地条件` 3 ／ `人工地形` 2 ／ `この土地は` 8）。

| # | 決めたこと | ⚠ 根拠 |
|---|---|---|
| 1 | ⚠ **主語は `この土地は` に統一** | 実測 9 : 1。⚠ **利用者役 2/4 が `この場所` と `この土地` を別物と読んだ** |
| 2 | ⚠ **`地形分類` を画面に出さない。**出典と `/about` でだけ使う | ⚠ **3/4 が「出典にあればよい」**。[0029](0029-画面の言葉は利用者の問いから決める.md) §1 |
| 3 | ⚠ **第1層で `もとは` を使わない** | ⚠ **3/4 が「もとは〜」を明治期（第2層）と取り違えた。**⚠ **第1層はいまの成り立ちで、さかのぼる話ではない** |
| 4 | ⚠ **成因と人工改変は、行を分ける** | ⚠ **4/4 が人工改変を「人が造成した」と正しく読めている。**混ぜる理由がない |
| 5 | 成因が「旧水部」でも ⚠ **原典の語をそのまま出し、意味は押したときに出す** | ⚠ **時間の語を使わずに済む**（3 の再発を避ける）。区分の説明 14 件は既にある |

⚠ **画面に出す形**

```
この土地は 旧水部
人の手で 盛土地･埋立地 になっています     ← ⚠ 人工改変があるときだけ
```

⚠ **`旧水部` は 4/4 が「読めるが意味は推測」だった。**だから**押せる**ようにする。
⚠ **押しても何も出ないなら、押せる見た目にしない**（[0026](0026-押しても何も起きない導線を置かない.md)）。

## データモデル（⚠ 2026-08-19 に合意）

⚠ **層を値として持つ。**⚠ **文字列を画面ごとに組み立てない**のが、この ADR の要。

```
layersOf(...) → { layers: [ Layer, ... ], missing: [ Missing, ... ] }
```

⚠ **`layers` は必ず層の番号順**（1 → 2 → 3）。立たない層は入らない。

**`Layer`**

| 欄 | 何 |
|---|---|
| `n` | `1` / `2` / `3`（⚠ **内部だけ。画面に出さない**） |
| `title` | 画面に出す名前（その層の**問い**から取る） |
| `head` | ⚠ **主役の値。3 種のどれか**（下記） |
| `what` | 何の値か（`の建物が、明治期には水の上だった` など） |
| `den` | ⚠ **分母。`head` が `pct` なら必須** |
| `subs[]` | 補足 |

⚠ **`head` は 3 種に分ける**（1 つの文字列にしない）。

| 種 | 中身 | ⚠ 決まり |
|---|---|---|
| `pct` | 数字 | ⚠ **`den` が無ければ作れない**（掟: 数字は主張範囲の分母で書く） |
| `name` | 区分名 | 押せる（意味を出す） |
| `none` | 出せない | ⚠ **数値を作らない。**0% を出さない |

**`Missing`**（⚠ **出ない層も、その層の位置に置く**）

| 欄 | 何 |
|---|---|
| `n` | どの層か |
| `why` | `unread`（読めていない）／ `outside`（資料の範囲外）／ `notyet`（まだ提供していない） |
| `say` | 人が読む言葉。⚠ **`WORD` が持つ**（ここで作らない） |

⚠ **`why` の 3 つを混ぜない。**
`unread` はこちらが読めていない、`outside` は相手の資料の範囲、`notyet` はこちらの都合
（[0001](0001-取れなかったを無いと言わない.md)・掟 §4-1）。

⚠ **出ない層を黙って消さない。**消すと「その土地に何も無い」に読まれる。

## ⚠ 段階を分ける（2026-08-19 の合意）

⚠ **一度にやらない。**⚠ **同時にやると、また広がる。**

| 順 | 何 | 大きさ | 状態 |
|---|---|---|---|
| **①** | ⚠ **層を値にする**（`layersOf` ＋ 組み立て側の分離） | `peel3d.js` の 1 関数 | ⚠ **これから** |
| **②** | ⚠ **取得をリポジトリに分ける**（土地 / 明治期 / 建物 / 空中写真） | ⚠ **`verify.js` と `peel3d.js` をまたぐ** | ⚠ **① のあと。Issue にしてから** |

⚠ **② は 1 リポジトリ = 1 PR の粒度で分ける。**⚠ **検査の件数も、そのつど見直す。**

⚠ **② が全部終わったら、③ として文書と ADR を要約する**（2026-08-19 の依頼）。
⚠ **いま不要なものが多く、確認に時間がかかりすぎている。**
⚠ **要約は ② のあと。**先にやると、また書き直すことになる。

⚠ **① をやっても、取得の散らばりは直らない**（`GSI` の定義が **2 か所**にある、など）。
⚠ **② をやっても、`#land` の 3 層は組み立たない。**⚠ **別の仕事。**
