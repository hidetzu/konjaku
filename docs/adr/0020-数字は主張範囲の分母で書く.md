# 数字は必ず、主張している範囲の分母で書く

- 状態: 採用
- 日付: 2026-08-14

## 何が問題だったか

「豊洲の建物の 99.6% は、明治期には水の上」という数字がある。
これは**豊洲の bbox の中の建物を1件ずつ判定した**結果で、それ以外の範囲では別の数字になる。

にもかかわらず、別の範囲の数字を同じ画面に持ち込みかけた事故が複数あった。

- 集計範囲を広げたら、**99.4% が 40.9% に化けた**（隣の街区が混ざった）
- 高さの但し書きに、取り込み全域の数字を書こうとした。
  取り込み全域（14,806件）では 93.8% が既定値だが、**豊洲の集計範囲（533件）では 80.1%**
- 3D の見出しの範囲は bbox **2.52 km²**。同じ画面の大きい写真は **0.99 km²**。**2.55倍違う**のに、
  並べると「いま見えているこの写真の中の建物の99.6%が」と読まれる。**一つも正しくない**

**数字が正しくても、分母が違えばその文は嘘になる。**

## 何を測ったか

| 範囲 | 実寸 |
|---|---|
| 土地の判定 | z16 の1画素 = **1.94 m 四方** |
| 事物一覧・大きい写真 | z16 の 2×2 = **0.99 km²** |
| 3D の 99.6% | bbox = **2.52 km²** |

豊洲の実測（533件の集計範囲）:

```
足元の判定  533 / 533 = 100%
高さ        実測 42 / 533 = 7.9%（既定値は 427 / 533 = 80.1%）
建設年      8 / 533 = 1.5%
```

配っている全体（403,397件）では、高さの既定値が 79.17%、建設年ありが 0.30%。**同じ性質でも数字が違う。**

## 決めたこと

- **数字は必ず主張範囲の分母で書く。** 別範囲の数字を書くと、それ自体が嘘になる
- 画面に出す数字は「N / M 件」の形で、分母を一緒に出す

```
建物はいまの形です。高さは 491 / 533 件が推定、建てられた年が分かるのは 8 / 533 件だけです。
```

- **注釈の寿命を、誤解を生む絵の寿命に一致させる。** 但し書きが畳まれるなら、絵も畳まれていなければならない
- 範囲の違うものを同じ画面に並べない（0003 の「2Dの判定と3Dの建物を同時に出さない」はこの帰結）

## そうしなかったこと

- **「約80%」のように丸めて分母を省く** … どの範囲の80%か分からなくなる
- **取り込み全域の数字を、1地点の画面に書く** … いちばん起こしやすい事故
- **但し書きを左パネルの中に置く** … 実測で、スマホでは初期状態で**1文字も見えていなかった**。
  利用者役のエージェント3体のうち2体が「建物の高さと年代は実データだ」と思ったまま操作した

## これを守っているもの

- `public/peel3d.js` の集計範囲のコメントと、常時表示の但し書き（畳まれない `#hud`）
- `scripts/render.mjs` の集計範囲に関する注意（「豊洲の建物の◯%」が豊洲でない範囲の割合にならないこと）
- `npm run render` の `高さが推定であることを、主張範囲の数字で言う` /
  `建物の但し書きが、スマホでも最初から見えている`（375×667）
