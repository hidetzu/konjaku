# 押しても何も起きない導線を置かない。見えていない注釈は、無いのと同じ

- 状態: 採用
- 日付: 2026-08-11（旧 §3.23 やる順番）／2026-08-14 に実測で確定

## 何が問題だったか

「取れなかったを『無い』と言わない」（0001）は、文言の話に見えて実は**画面の話**でもある。

- 押しても何も起きないものが並んでいると、利用者は「壊れている」と「答えが無い」を区別できない
- **正しい但し書きを、見えない場所に置くこと**は、書いていないのとほぼ同じ

どちらも「言っている内容は正しいのに、伝わっていない」という同じ形をしている。

## 何を測ったか

### 見えていなかったもの

| | 実測 |
|---|---|
| `/peel` の但し書き | `let panelOpen = !isNarrow` により、**スマホでは初期状態で1文字も見えない**。利用者役のエージェント**3体中2体**が「建物の高さと年代は実データだ」と思ったまま操作した |
| `/peel` の着地直後 | 375×667・390×844 とも `#panel` は閉じて着地。押せるものは5つだけ。**99.6%、`実測/推定` の4行、`427/533`、内訳、出典 — 全部 35×34px の ☰ の裏** |
| 建物を押した結果 | iPhone SE で y=672（画面外）、PC で y=721（パネル内スクロールの下端の外）。**両方の端末で外れていた**ので「気づきにくい」ではなく「見えない」 |
| 「建物をクリックすると足元を判定する」の案内 | 左パネルの中。スマホは閉じて始まり、PC は内スクロールの外。**誰も読んでいなかった** |
| `/peel` の戻る導線 | 「←今昔」315×18px・y=688（スマホでは見えていない）。しかも**ロゴに見えて、戻る操作に読めない**。**スマホでは戻る手段が画面に1つも無かった** |

直した後: 建物のカードは iPhone SE で y=137、PC で y=204（どちらも画面内）。
戻るは 38×44px・y=14（常時）。押す前の HUD 229px → 押した後 190px（画面の 34% → 28%）。

### 押しても何も起きなかったもの

- 明治期のコマから「写真のある最初の年代」へ送る一歩を作ったら、**豊洲の 1936–42 は0件**（埋立前なので当然）。
  → **中身のある最初の年代**へ送る形に直した（実測 53px、豊洲で 明治期 → 1961–69、2件）
- 広島の 1945–50（原爆直後の焼け野原）の上に現在の3,555棟が立っている画面を、
  60代の利用者は「1945年の広島の街並み」として読みかけた

## 決めたこと

- **押しても何も起きない導線を置かない。** 一歩を作るなら、**押した先が空でないこと**を検査で見る
- **注釈の寿命を、誤解を生む絵の寿命に一致させる。** 畳まれる場所に但し書きを置かない
- 結果は**押した場所に出す**（左パネルの中ではなく）
- **触る前に、押せることを伝える。ただし一度押したら消す**（役目が終わったものを常設しない）
- 指で押すものは 44px 以上（`@media (hover:none)`）
- 検査は**スマホ幅で見る**。PC 幅のままだとパネルが開いているので、この壊れ方は再現しない

## そうしなかったこと

- **空の枠を並べる** … 何も無いほうが正確
- **注記の横に別ボタンを足す** … 実測 51px → 95px。折り返しの下へ出た。**要素を増やすと高さが増える**
- **見えない当たり判定だけを広げる** … 0025 を参照。もっと分かりにくい壊れ方になる
- **「現在を重ねる」を外して 30px 回収する** … 見積もりを外した。実測 **0px**（▶ と同じ行にいて、行の高さは ▶ が決めていた）

## これを守っているもの

- `public/peel3d.js` の Popup と、畳まれない `#hud`、`public/peel.html` の `← もどる`
- `npm run render` の `押せそうなものは、押すと何かが起きる` / `明治期に着いた人に、次の一歩がある` /
  `建物を押した結果が、押した場所に見える` / `建物の但し書きが、スマホでも最初から見えている` /
  `3D から戻っても、調べていた場所が残る` / `スマホで、最初の1タップが空振りしない` / `タップ判定（スマホ幅）`
