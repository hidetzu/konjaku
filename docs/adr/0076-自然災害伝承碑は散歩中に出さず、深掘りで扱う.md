# 自然災害伝承碑は、散歩中に出さず、深掘りで扱う

- 状態: 採用
- 日付: 2026-08-31
- 範囲: v0.1.0（`public-next/`）。⚠ **深掘り（`/deep`）だけ。**⚠ **散歩中の画面には出さない。**

## 決めたこと（Owner の言葉）

> 自然災害伝承碑は全国に存在するが、散歩中の現在地点に対して提示できるほど
> 高密度ではなかったため、スマホの 1 画面目には載せず、
> PC / Deep における「周辺に残る歴史資料」として扱う。

## 何を測ったか

**分母は 15 地点**（`scripts/survey-pins.mjs` が使っている 13 地点 ＋ 豊洲 ＋ 軽井沢）。
⚠ **全国の話ではない。**

```
半径ごとに、1 件でも出る地点の数

   500m    0 / 15（ 0%）
  1000m    0 / 15（ 0%）   ← 設計の当初案。どこにも出ない
  1500m    2 / 15（13%）
  2000m    3 / 15（20%）
  5000m    8 / 15（53%）
```

いちばん近い碑まで: **春日部 1,118m ／ 豊洲 1,520m ／ 軽井沢 4,809m ／ 関宿 24,675m**。

**全国 2,469 件**（実測 2026-08-31。`scripts/ingest-monuments.mjs`）。
数はあるが、**歩いている足元に対しては薄い。**

## そうしなかったこと

- **半径を決めて、届かなければ何も出さない**（半径 2km）
  … 15 地点中 3 地点でしか出ない。**作ったものの大半が見えない**
- **いちばん近い 1 件を、距離を添えて必ず出す**
  … どこでも出るが、**4.8km・24.7km 先の碑**になる。
  「この近く」と言えないし、散歩中の画面が 3 行ぶん重くなる。
  [0063](<0063-散歩中の 1 画面目は、答えと写真だけにする.md>) に反する

## 言えること・言えないこと

⚠ **碑があることと、その地点が被災したことは別。**
言えるのは「**この近くに、その災害を伝える碑が残っている**」まで。
画面は、その断りを必ず言う。

```
出す      5.0km 以内に残っている碑です。碑があることと、この場所が被災したことは別です。
          現在地から 1.1km ／ 関東大震災伝承碑 ／ 関東大震災 (1923年9月1日)［地震］
          碑が建てられたのは 1927 年
出さない  この場所は 1923 年に被災しました
```

## 出典の字を、そのまま持つ

⚠ **実測が設計の前提を覆したので、設計のほうを直した**（2026-08-31。Owner 判断）。

```
disasterName  昭和13年洪水<br>(1938年6月ほか)   ← 表示の正本。出典の字のまま
disasterKind  地震・津波                        ← 複合のまま。分解しない
builtYear     1939                              ← 碑の建立年。災害の年ではない
derived       { years: [1938], uncertain: true } ← 検索・並び替え用。画面に出さない
```

- **年を 1 つの値へ丸めない。**災害の年は構造化されておらず、`DisasterName` の
  自由文にしかない。`(1884、他)` `(不明)` もある。**丸めると嘘になる**
- **種別も出典の字のまま。**`洪水・土砂災害` 366 件、`地震・津波` 502 件。
  **複合が多く、絵文字 1 個に割り当てられない。** 種別ごとのアイコンは作らない
- **「不明」「ほか」「以降」を落とさない。** 落とすと、幅のあるものを 1 点に見せる

```
取り出した年が 1 つ      2,256 / 2,469
取り出した年が 2 つ以上    208 / 2,469
取り出せなかった             5 / 2,469
「不明」「ほか」つき        52 / 2,469
```

## 配り方

```
public-next/data/monument/tiles.json           どのタイルに碑が在るかの表
public-next/data/monument/8/{x}/{y}.json       索引  ← 近くを探す
public-next/data/monument/8/{x}/{y}.detail.json 詳しく ← 伝承内容
```

**z8 で 58 枚**。索引はいちばん重い 1 枚が gz 7KB、詳しくが 27KB。
全国 1 枚（gz 84KB）を毎回配らない。

⚠ **`tiles.json` を一緒に配る。**⚠ **これが無いと、404 を「碑が無い」と読む**（掟 §1）。

```
表に無い          → その範囲に碑が 1 つも無い
表に在るのに取れない → 取れなかった
```

⚠ **取り込みは、1 枚でも聞けなかったら配らずに止まる。**
欠けたまま配ると「その辺りに碑は無い」に見える。

## これを守っているもの

  3 状態（`ok` / `absent` / `unreachable`）で返す（[0056](<0056-データの状態を 3 つに分けて言い分ける.md>)）

## 追記（2026-09-01）— 碑を、この地点の履歴より下へ、一段分離した

利用者役 6 名に画面だけを見せた（⚠ **実在の利用者ではない**）。
**2 名が、碑を「この地点そのものの履歴」と混ぜて読む恐れを挙げた。**

| 誰 | 何と言ったか |
|---|---|
| 46歳・ソフトウェアエンジニア | 「近くの碑は、その地点そのものの履歴ではないので、見た目でも一段分離されていた方が安心」 |
| 38歳・引っ越し先を調べている | 「碑は優先度が低い」（⚠ 昔の土地・標高・空中写真を先に読む） |

⚠ **「碑があること ≠ 被災したこと」は、⚠ この ADR の時点で既に字で言っていた。**
⚠ **足りなかったのは、⚠ 「これは周りの話だ」という構造のほう。**

```text
前   答え → どう変わったか → なぜこうなった → 近くの碑 → この一帯 → 読んだ資料
後   答え → どう変わったか → なぜこうなった → この一帯 → ──線── 近くの碑 → 読んだ資料
```

- **この地点の重要な情報（`timeSec` / `whySec` / `nearSec`）より下**へ移した。
- 節の上に **区切り線**を引き（`--line`。情報を持つ枠ではないので `--line-strong` は使わない）、
  見出しより先に **「ここから下は、この地点そのものではなく、まわりに残っている記録です」**
  と断る一行を置いた。

⚠ **検査は並びと分離の両方を見る**（`test/check/next.mjs` ⑯）:
「`monSec` が `timeSec` / `whySec` / `nearSec` より後ろ」「`sec--around` が付いている」
「見出しより先に断りの一行がある」「`sec--around` に見た目の区切りがある」。
⚠ **class だけでは分離されない**ので、⚠ CSS 側も別に見ている。

## あわせて直した — 読んだ資料が、生の URL のまま並んでいた

同じ 6 名のうち 1 名（46歳）が
「生 URL そのものではなく、**資料名を押すと出典に行ける形**だと使いやすい」と言った。

```text
前   いまの地形分類   https://maps.gsi.go.jp/xyz/experimental_landformclassification1/…
後   いまの地形分類   国土地理院「地形分類（自然地形）」
```

⚠ **行き先は変えていない。**⚠ **出典へ直接行けること**（55歳が「出典に直接行ける方が
ありがたい」と挙げた利点）は失っていない。
⚠ **資料名は、こちらで要約しない。**⚠ **`verify.js` が実際に読んでいるタイルの名乗りを書く**
（`experimental_landformclassification1` / `2` / `swale` / `dem5a`）。
