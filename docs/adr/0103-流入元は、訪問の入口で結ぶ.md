# 0103. 流入元は、訪問の入口で結ぶ

- 日付: 2026-09-08
- 状態: 採用
- 決めた人: Owner

## 何が起きていたか

**`about?from=app-village` から地図へ進むと、その先が `konjaku` になっていた。**

流入元は画面ごとに、読み込んだときに 1 回だけ決まる（`public/measure-send.js`）。
見ているのは 2 つだけ ── **その URL の `?from=`** と **`document.referrer` のホスト名**
（`public/measure.js` の `HOSTS`）。**サイト内リンクは `?from=` を運ばない**
（`public/about.html` の「地図で調べてみる →」は `href="./"`）。

実測（2026-09-08。`public/measure.js` の `流入元()` を Node から呼んだ）:

```text
about  ?from=app-village                              -> app-village
map    /            （referrer = /about?from=app-village）-> konjaku
deep   /deep?…      （referrer = /?q=…）               -> konjaku
```

**痛いのは記録そのものより、集計のほう。**
`npm run stats` の「3. どこまで進んだか」は `referrer` で束ねて訪問を数えていたので、
**同じ訪問が 2 つの流入元へ割れていた。**

```text
app-village   訪問 1   調べた 0   深掘り 0     ← 1 行目だけ
konjaku       訪問 1   調べた 1   深掘り 1     ← 2 行目から
```

**「app-village から来た人は誰も地図を使っていない」と読める。**
`CLAUDE.md` §1（観測されていない ≠ 存在しなかった）に反する。
**数え落としではなく、嘘になっていた。**訪問の数も、流入元をまたいで二重に数えていた。

## 決めたこと

**集計側で、訪問（`session_id`）の最初の行の `referrer` を、その訪問の入口とする。**

```sql
WITH 訪問の入口 AS (
  SELECT session_id, referrer FROM (
    SELECT session_id, referrer,
           ROW_NUMBER() OVER (PARTITION BY session_id ORDER BY id) AS 番
    FROM events_simple
    WHERE created_at >= date('now', '-N days') AND session_id IS NOT NULL
  ) WHERE 番 = 1
)
```

- **記録の側は変えない。**`referrer` 列の意味は「その画面を開いた直前の出どころ」のまま
- **定義は `scripts/stats.mjs` の 1 か所**（`CLAUDE.md` §3。問いごとに書くと片方だけ古くなる）
- **既にある行にも遡って効く**（2026-09-06 から溜まっている分も、入口で読み直せる）

## 選ばなかった案

**送信側で覚える**（訪問の印に流入元を入れ、その日はずっと同じ流入元で送る）。
`referrer` 列の意味が「訪問の入口」に変わるので、`docs/adr/0102` と `/privacy` の字も動く。
**既にある行は直らないので、同じ列に 2 つの意味が混ざる期間ができる。**

**サイト内リンクに `?from=` を運ぶ。**
URL が汚れる。**その URL が共有されると、共有先の人まで `app-village` になる**
（流入元が偽装される）。調べた場所の URL は共有される前提で作ってある（`docs/adr/0026`）。

## 測れないもの

**端末が印を置けないと（プライベートモードなど）、訪問として結べない。**
`session_id` が無い行は、入口で束ねた表（問い 2・3）に出ない。

**黙って落とすと、その分だけ全体が小さく見える**ので、
**問い 6 が本数を名乗る**（`CLAUDE.md` §1）。日ごとの本数（問い 1）は今までどおり全部数える。

## 何を見張るか

`test/check/safety.mjs` 1.9。**実物のスキーマ（`migrations/0003_events.sql`）と
実物の SQL を、手元の `:memory:` で実際に走らせて答えを見る**（本番の D1 は触らない）。

```text
about?from=app-village → 地図 → 深掘り の 1 訪問が、app-village のまま数えられる
途中で化けた konjaku が、別の訪問として立たない（訪問が二重にならない）
直接来た訪問は direct のまま（入口が混ざらない）
印を置けなかった行は、訪問の表から外し、本数として別に名乗る
日ごとの本数は、印の無い行も含めて全部数える
```

**5 本とも、わざと壊して、狙った理由で落ちることを確かめた**（2026-09-08）。
行ベースへ戻すと、上の「訪問 1・調べた 0・深掘り 0」がそのまま再現する。

⚠ **`node:sqlite` は Node 22 ではフラグ越しなので、子プロセスで走らせる**
（CI は Node 22・手元は 25。`CLAUDE.md` §9「手元に入っているものを、CI にもあると思わない」）。
