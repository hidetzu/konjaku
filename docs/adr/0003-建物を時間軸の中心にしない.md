# 建物を時間軸の中心にしない

- 状態: 採用（3Dは残す。ただし看板にはしない）。⚠ 撤回条件は測った結果、満たさなかった
- 日付: 2026-08-14（PLATEAU の実測を受けて 2026-08-15 に確定）

## 何が問題だったか

オーナーの提起「トップビューに時間をさかのぼる(3D)をのせるほうがよい。見せたい情報はシンプルに一つにまとめる」に対し、
PO・アーキテクト・UI/UX・検証者・利用者役のエージェント3体に独立に当たった。

**全員が統合に賛成し、全員が「3Dをトップの中心に据えること」に反対した。** 理由は5つの役すべてで違うが、収束している。

3D の主役は「年代を動かすと建物が消える」だが、**その動きを支えるデータが無かった。**

```js
if (Number.isFinite(sd)) { vanish = tFromYear(sd); exact = 1 }  // 0.30%
else { vanish = s.water ? 6.0 : 7.4; exact = 0 }                // 99.70%
```

**99.7% の建物は、時間ではなく「足元が水か陸か」の2値で消えている。**
3Dが見せているのは「時間による変化」ではなく「明治期の水域を、建物の高さで塗り分けた図」だった。

## 何を測ったか

配っている全建物（10街・z14×64タイル）:

```
建物            403,397 件
建設年あり        1,216 件 = 0.30%
  1936–1990年      342 件 = 0.08%   ← 空中写真と突き合わせられる唯一の帯
高さ default    319,381 件 = 79.17%
```

**濃い街ほど比率が下がる**（長崎 出島 0/3,914 = 0.00%、上野 4/5,694 = 0.07%、豊洲 8/544 = 1.47%）。
OSM の `start_date` の入り方の問題で、**街を増やしても改善しない。**

3D の見出しの数字（本物の `/peel` を開いて読み取り）:

```
豊洲 99.6% ／ お台場 97.1% ／ 広島 3.0% ／ 渋谷 1.5% ／ 上野 1.3% ／ 西新宿 1.3%
```

**6地点中4地点で「主張」になっていない。** そして重い土地ほど何も言わない。

同じ問いに、事物（`ev`）のほうが答えている:

| | `bld`（建物） | `ev`（年つきの事物） |
|---|---:|---:|
| 件数 | 403,397 | 2,367 |
| 年がある | 1,216（0.30%） | **2,367（100%）** |
| うち写真の帯 1936–1990 | 342 | **754** ← 170分の1の母数で2.2倍 |
| 1件ごとの出典URL | 無い（配布時に捨てた） | **100%** |
| 配信 1画面あたり | gz 約800KB | gz 最大 18.5KB |

**配信量あたりの「時間を語れる密度」で約100倍の差。**

利用者役のエージェント3体の実測: `/` は 42リクエスト・0.83MB・JS 0KB、`/peel` は 241リクエスト・8.33MB・JS 478KB。
3体とも「3Dが出した結論を上に載せるなら大賛成。3Dビューを載せるのは反対」と言った。
検証者は範囲の不一致を指摘した — 判定は z16 の1画素（1.94m四方）、写真の枠は 0.99km²、3D の 99.6% は bbox **2.52km²**。

そして年代スライダー自体は無駄ではなかった。豊洲で隣り合う年代の画素変化率を測ると、
**建物が消える演出も色調も止めても、1段あたり 42〜55% が変わり続ける**（遷移を支えているのは空中写真の入れ替えそのもので、これは100%実データ）。

## 決めたこと

- **時間を動かす主役は 2D の帯と事物一覧**（年 100%、出典URL 100%）。3Dは看板にしない
- **3D で主張するのは足元の判定**（豊洲 533/533 = 100%）。押した結果は押した場所に出す
- 建物の高さと建設年は**出所つきで、主役の下に**置く
- 建設年が分かる建物と、こちらが決めた建物を、画面で同じに見せない（押しているあいだだけ分かる側を光らせる）

## そうしなかったこと

- **3Dをトップの中心に据える** … 実測が最も薄い面を製品の定義にすることになる
- **2Dの判定と3Dの建物を同じ画面に並べる** … 範囲が 2.55倍違うのに1つの主張に読まれる（検証者の反対）
- **建設年が無い525件を半透明にする** … 98.5% が半透明になり「半透明が既定の見え方」になって区別の意味が消える
- **年代スライダーを即座に外す** … 遷移は実データで支えられている。ただし「1945年の焼け野原に現在の3,555棟が立つ」状態が
  常態化する問題は残るので、A（残して名乗りを変える）／B（外して明治期の水域だけ重ねる）／C（明治期を特別扱いしない）の
  3案は**利用者に確認するまで保留**

## 撤回条件（測った。撤回しない）

PO が「**写真の年代域（1936–1989）で建設年が分かる建物が 30% を超えたら、3Dを中心に据える判断に賛成へ回る**」と明言している。
いま **0.085%**。差は375倍。OSM の `start_date` は待っても増えない。

動かせる可能性があるのは **PLATEAU（国土交通省の3D都市モデル）** だけだった。**測った結果は 4.94%**。

⚠ **撤回条件の 30% に、6倍以上届かない。**
しかも**待っても埋まらない**。建築年は都市計画基礎調査の法定事項ではないため、
整備が進んでも入るとは限らない。

→ **この判断は撤回しない。**

⚠ この 4.94% の出どころは `scripts/check.mjs`（名乗りの検査の節）のコメントで、
**いつ・どの範囲を・どう数えたかは記録されていない**。
⚠ 3Dを中心に据える判断を蒸し返すときは、**この数字を測り直すところから始めること。**
測り方を再現できない数字は、根拠として弱い。

## これを守っているもの

- `public/peel3d.js` の `exact` の描き分け、押した場所に出す Popup、常時表示の但し書き
- `npm run render` の `建物を押した結果が、押した場所に見える` /
  `建設年が分かる建物を、こちらが決めた建物と同じに描かない` /
  `建物の但し書きが、スマホでも最初から見えている` / `高さが推定であることを、主張範囲の数字で言う`
