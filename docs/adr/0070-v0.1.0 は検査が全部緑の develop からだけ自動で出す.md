# 0070. v0.1.0 は、検査が全部緑になった `develop` からだけ自動で出す

- 状態: 採用（⚠ **決めたのは Owner。**⚠ 2026-08-29）
- 日付: 2026-08-29

## 背景

⚠ **[`0050`](<0050-v0.1.0 は別の Worker で作り、β 版に触らない.md>) では、⚠ 出し方を手で回すことにしていた。**

```text
npx wrangler deploy -c wrangler.next.jsonc
⚠ Workers Builds には足していない（2026-08-28。Owner 判断で「今は足さない」）
```

⚠ **測ったこと**（2026-08-29）:

```text
ブランチ    develop は main より 30 コミット先（git rev-list --count main..develop）
CI          check.yml の push は branches: [main] だけ
            ⚠ develop へ取り込んだあとの「全部回す実描画」が走っていない
            ⚠ 「外部リンク（全部・8本）」も走っていない（PR では走らない段）
            ⚠ 週 1 の定期実行は、既定ブランチ（main）＝ 30 コミット前を見ている
配信        dev.konjaku.hidetzu.work と develop の public-next/ が、
            ⚠ **一致していなかった**（sha256。index.html / top.js / robots.txt が違う。
              esc.js / data/muni.json は一致）
```

⚠ **手で出しているかぎり、⚠ 出ているものと `develop` はずれる。**
⚠ **そして、⚠ ずれていることに誰も気づかない**（⚠ `public-next/` は `/version.json` を持たない）。

## 決めたこと

⚠ **`develop` への push で、⚠ 検査が全部緑になったあとだけ、⚠ `konjaku-next` を自動で出す。**

```text
develop への push
  → checks（静的検査・外部リンク）／ search（検索の並び）／ render（実描画の門番）
  → 全部緑なら  npx --yes wrangler@<版> deploy -c wrangler.next.jsonc
  → ⚠ 出したものを取り直して、手元と sha256 が同じかを見る
```

1. ⚠ **`push` のトリガに `develop` を足す**（⚠ これが無いと、⚠ 出す段は一度も走らない）
2. ⚠ **`deploy-next` ジョブを、⚠ 門番 3 つの後ろに置く**（`needs:`）
3. ⚠ **`develop` への push でだけ走らせる**（⚠ PR では走らせない）
4. ⚠ **出したあと、⚠ 配った実体を全ファイル突き合わせる**
5. ⚠ **β 版（`konjaku` / `public/`）には触らない**

## ⚠ なぜ Workers Builds に足さないか（⚠ ADR 0050 の「今は足さない」を、こう覆した）

⚠ **Cloudflare 側は、⚠ GitHub の検査の緑を待てない。**⚠ **赤のまま出る。**

⚠ **このリポジトリは、⚠ 必須チェックと門番（`render` ジョブ）まで作り込んである**
（`docs/adr` ではなく `.github/workflows/check.yml` と `test/check/deliver.mjs` が持つ）。
⚠ **それを飛び越える経路を、⚠ わざわざ作らない。**

⚠ **GitHub Actions なら `needs:` で後ろに置ける。**⚠ **これが選んだ理由の全部。**

## ⚠ なぜ `/version.json` で照合しないか

⚠ **`public-next/` は `/version.json` を持たない。**⚠ あれは β 版の仕組み
（`scripts/version.mjs` が `public/version.json` を書き、⚠ Workers Builds が実行する）。

⚠ **ADR 0050 は「何も引き継がない」と決めている。**⚠ **運ぶ理由が、まだ無い。**
⚠ **だから中身そのものを突き合わせる**（⚠ `public-next/` の全ファイルの sha256）。

⚠ **実測で分かった踏み方**（2026-08-29）:

```text
⚠ /index.html は / へ送られ、本文が空で返る（-L を付けないと空文字の sha256 を読む）
⚠ ?cb=<commit> を付けないと、端の古い写しを「いまの本番」と読みうる
```

## ⚠ 代償（⚠ 承知の上で受ける）

- ⚠ **`develop` へ merge した時点で、⚠ `dev.konjaku.hidetzu.work` が入れ替わる。**
  ⚠ **`CLAUDE.md` §8 の「`git push` はそのつど許可を取る」とは、⚠ 方向が逆。**
  ⚠ **いま許容できるのは、⚠ v0.1.0 にまだ利用者がいないから**（`docs/adr/0050`）。
  ⚠ **利用者が付いたら、⚠ ここは見直す**（⚠ タグで出す形が候補）。
- ⚠ **秘密が 2 つ増える**（`CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`）。
  ⚠ **fork の PR には渡らない**（⚠ `pull_request` では走らせない・条件でも閉じている）。
  ⚠ **ただし `develop` へ push できる人は、⚠ Worker を出せる。**

## ⚠ 境界は検査が見る

⚠ **`test/check/deliver.mjs` が 8 つ見る**（⚠ どれも「落ちない壊れ方」を捕まえるためにある）。

```text
⚠ push のトリガに develop が居るか      ⚠ 居ないと、黙って何も走らない
⚠ -c wrangler.next.jsonc を渡しているか ⚠ 外すと β 版が出る（⚠ 成功してしまう）
⚠ wrangler の版が env の1か所か         ⚠ その日の最新が降ってくる
⚠ 門番 3 つを needs に持つか            ⚠ 赤のまま出る
⚠ develop への push に閉じているか      ⚠ fork の PR へ秘密を渡す口になる
⚠ 出したあと突き合わせているか          ⚠ 「デプロイ成功」は「出ている」ではない
⚠ 必須チェックに入れていないか          ⚠ PR で永久に待ちになる
⚠ 出す段そのものが在るか                ⚠ 検査が何も見なくなる
```

⚠ **8 通りの壊し方で、⚠ 8 件とも実際に落ちることを確かめた**（2026-08-29）。

## ⚠ 決めていないこと

```text
⚠ β 版（konjaku）の出し方        ⚠ Workers Builds のまま。⚠ 触らない
⚠ タグ（v0.1.x）で出す形          ⚠ 利用者が付いたときの候補
⚠ ruleset「main を守る」を develop にも当てるか
   ⚠ **これは repo の外**（⚠ GitHub の画面）。⚠ 当てないと、⚠ 検査を通さずに
     develop へ入れられ、⚠ その push でそのまま出る
```
