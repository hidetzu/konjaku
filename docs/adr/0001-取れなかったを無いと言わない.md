# 取れなかったことを「無い」と言わない

- 状態: 採用
- 日付: 2026-08-11（旧 §3.23）

## 何が問題だったか

プロダクトオーナー・UI/UX・検証者の3役を独立に走らせたところ、**3者が別々の場所で同じ根に到達した。**

| 役 | 見つけた場所 |
|---|---|
| 検証者 | `verify.js` の通信層。国土地理院への通信が落ちると、豊洲でも「整備対象外」「標高データが無い」「空中写真が残っていない」と断定。**しかも根拠UI付きで** |
| UI/UX | `peel` の集計。札幌で「0.0% — 1408件すべての足元を1件ずつ判定した実測値」（内訳は「データなし 1408/1408」） |
| PO | Overpass が両エンドポイント 504。作品（3D）が本番で成立していない |

判定関数 `meiji()` は画素の α が 0 のとき正しく黙るのに、**その手前の通信層で同じ過ちを犯していた。**
PWA でシェルをキャッシュしているため、地下鉄や機内モードで実際に踏める。

「無い」と「知らない」が同じ顔になると、**最も権威ありげな見た目で最も誤ったことを言う**状態になる。

## 何を測ったか

- `overpass-api.de` **504**（10.4秒）／ `overpass.kumi.systems` **応答なし**（40秒）
- `/peel` を90秒開いても建物が来ない。見出しは `99.4%（建物）` ではなく `95.3%（面積比）`
- **README・OGP が掲げる 99.4% が、利用者の画面に一度も出ていなかった**
- 全国24地点の判定被覆: 明治期の区分が出た 7/24（29%）／「記録がありません」7/24／「整備対象外」10/24

## 決めたこと

取得結果を**3状態**で持ち、混ぜない。

```
ok          … 読めた
absent      … サーバが「無い」と答えた（404 / 403）。事実として使える
unreachable … 読めなかった（通信断・タイムアウト・CORS拒否・5xx）
```

`unreachable` のときは、

- 断定しない。「整備対象外」「データが無い」「残っていない」と書かない
- **根拠UI（参照タイル・読んだ画素）を出さない**。根拠を出すことが断定の裏書きになる
- 状態と**復帰手段**（再試行）だけを出す
- 8秒のタイムアウトを置く（以前は上限が無く、25秒待っても復帰手段が無かった）

判定の側でも、`absent` を「陸だった」と読まない。凡例に「草地・荒地は山地や台地上のものは取得しない」とある以上、
**該当なし＝低湿地でなかった、とは限らない。**

## そうしなかったこと

- **失敗を握りつぶして「データなし」に丸める** … いちばん静かに嘘をつく形。0.0% を「実測値」と名乗ったのがこれ
- **失敗した取得をキャッシュに残す** … 残すと再試行が何もしなくなる
- **エラー文言だけ直す** … 3役が3か所で見つけた以上、通信層の型として直さないとまた別の場所に出る

## これを守っているもの

- `public/verify.js` の `OK` / `ABSENT` / `UNREACHABLE` と `readImage()`
- `public/peel3d.js` の再試行ボタン、`judged` が 0 なら % を出さない分岐
- `scripts/render.mjs` の `LIES = ["整備対象外","データが無い","記録がありません","残っていない","データなし"]`
  を使う描画検査群 — 通信を落とす／無応答にする／写真だけ落とす／検索だけ落とす、の4系統
- `scripts/db.mjs` の `dropped_at`（上流から消えたことと、見なかったことを分ける）
- `scripts/search-check.mjs` — 取れなかったことを「並びが悪い」と言い換えず、検査を保留にして落とす
