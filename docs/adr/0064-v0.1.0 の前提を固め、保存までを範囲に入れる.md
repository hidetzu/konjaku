## ⚠ 根拠の種別を書き分ける

⚠ **掟 §1 が禁じているのは「決めること」ではない。**
⚠ **禁じているのは「⚠ 推定を実測のように見せること」。**

```text

⚠ **利用者役**        ⚠ 実在の利用者ではない。⚠ 3 名に見せて答えを書き取ったもの
⚠ **一般的な判断**    ⚠ 測っていない。⚠ Owner の判断
```

⚠ **以後、v0.1.0 の前提には、⚠ この 3 つのどれかを必ず添える。**

## ⚠ なぜ「散歩中は長文を読まない」を、⚠ 測らずに決めたか

⚠ **測れないから**（⚠ 2026-08-29 に確かめた）。⚠ **3 つ理由がある。**

### ⚠ ① いちばん近い数字が、⚠ 分母として使えない

⚠ **β の D1（本番）を読んだ。**⚠ **18 日ぶん（2026-08-11 〜 08-28）。**

```text
判定が出た    348 回
深掘りを開いた 222 回   ⚠ **合計では 64%**
```

⚠ **だが 3 日で 100% を超えている**（⚠ 08-18 が 131%・08-21 が 165%・08-22 が 133%）。
⚠ **`open.peel` は 1 判定につき何回でも立つ。**⚠ **「64% の人が開いた」とは言えない。**
⚠ **人数ではなく回数。**

### ⚠ ② 誰の操作かを分けられない

```text
⚠ 348 件のうち、⚠ **およそ 300 件が 2026-08-13 〜 08-22 に集中している**
⚠ **ここは作業が集中していた期間**
⚠ **こちらの動作確認と、⚠ 利用者の操作を、⚠ 区別する口が無い**
```

### ⚠ ③ 「散歩中は」の部分は、⚠ 原理的に測れない

```text
⚠ **`worker.js` は、⚠ 地名も座標も時刻も送らない**（⚠ 「評価は自分専用」の設計）
⚠ **記録は日ごとに畳んだ件数だけ**
→ ⚠ **散歩中か、⚠ 家か、を分ける手がかりが 1 つも無い**
```

⚠ **これは不足ではなく、⚠ 意図した設計。**⚠ **測れるようにするには方針を変えることになる。**
⚠ **変えない。**

### ⚠ だから、⚠ こう扱う

```text
⚠ **決めてよい。**⚠ **ただし「実測」と書かない。**
⚠ **前提が一般的な判断でも、⚠ そこから出てきた画面のほうは実測で良くなっている**:
   ⚠ 板 388 → 271px ／ 地図 279 → 396px ／ 3/3 が 5 秒で答えた ／ 3/3 が写真を押した
```
