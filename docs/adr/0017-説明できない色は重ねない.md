# 凡例が機械可読でないものは、地図に重ねない

- 状態: 採用
- 日付: 2026-08-11（旧 §3.21）

## 何が問題だったか

明治期の低湿地の当たり率が低い（0004 の測定前は 7/24）ので、
**別のラスタで中間を埋められないか**を探した。土地条件図が候補だった。

だが地図に色を重ねるということは、**その色が何を意味するかを説明する責任を負う**ということでもある。
凡例から区分名と色を機械的に取り出せないなら、目視で色を割り当てることになり、
それは **検証できない断定** になる。0007 が禁じているものそのもの。

## 何を測ったか

- 土地条件図の正しいタイルIDは **`lcm25k_2012`**。色は平坦だが、**凡例 `lc_legend.pdf` は5ページ構成**で
  色と区分名の**機械抽出が不可**だった
- もう一方の候補 `lcmfc2` は「地図の絵」であって区分の塗り分けではなかった（等高線や注記が乗る）
- ベクトルタイル（地形分類）なら取れる、と分かったのが 0004 につながった。
  ラスタ2つは潰れ、ベクトルが通った
- 明治期の低湿地は、これに対して**凡例 `lw_legend.pdf` から14区分を色つきで抽出できた**。だから使える

参考: LLM で解説文を書かせる案を採らなかった結果、いまの応答は **0.0x 秒・費用ゼロ・根拠100%**。

## 決めたこと

- **凡例が機械可読でないラスタは重ねない。** 説明できない色を画面に出さない
- **埋められない中間は、埋めずに空けておく**（0012 と同じ側）
- 出すバッジは**すべて検証済みの材料から**作る。3つ目のバッジは「土地がどう変わったか」ではなく
  「**どの時代を自分の目で確かめられるか**」に差し替えた
- 表示は「1行の事実 ／ バッジ ／ `?` で開く根拠」の**三層**にし、根拠は既定で閉じる
- 語を並べるときも、**その区分から言えることが無いなら空けておく**。
  地形分類の36区分のうち、語を置いたのは9つだけ

## そうしなかったこと

- **土地条件図を目視で色分けして重ねる** … 検証できない断定になる
- **Workers AI で解説文を生成し、KV でキャッシュする** … 読みやすさを得て、正しさの保証を失う（0005）
- **中間バッジ（🏭 昭和: 工業／🏠 昭和: 住宅化）** … 実測で否定済み（0006）

## これを守っているもの

- `public/index.html` — 「土地条件図は重ねない。凡例が機械可読でないため、出した色を説明できない」
- `public/verify.js` — 語を置いていない27区分は空のまま（「空の区分があってよい」）
- `public/data/landform.json` — 図式コードと36区分の対応（`scripts/build-landform.mjs` が地理院の `style.js` から生成）
