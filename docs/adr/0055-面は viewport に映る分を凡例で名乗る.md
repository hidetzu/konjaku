# 0055. 面は viewport に映る分を凡例で名乗る

- 状態: 採用（⚠ **決めたのは Owner。**⚠ 2026-08-29）
- 日付: 2026-08-29

⚠ **`docs/adr/0053` が残していた「面（色）の半径」の答え。**
⚠ **半径では決めない、という形の答え。**

## 背景

⚠ **13 か所で測ったら、⚠ **面の半径は一律にできない**ことが分かった**
（⚠ `docs/adr/0053` の観測事実）。

⚠ **さらに、⚠ 足元が少数派の土地がある。**⚠ **松江で確かめた**（⚠ 実測 2026-08-29・375×667）:

```bash
node scripts/survey-face.mjs
```

```text
⚠ **どのズームでも、⚠ 足元の「旧水部」が最大にならない。**
⚠ **いちばん広く映っているのは、⚠ 足元とは別の区分。**
```

⚠ **`docs/adr/0053` の基本形（⚠ 足元を言い切る）だけだと、
⚠ **画面のごく一部の色について語ることになる**。**⚠ **色と字が結びつかない。**

## 決めたこと

### ⚠ ① 面は、⚠ 半径で切らない

```text
⚠ **viewport に映っている分類を、⚠ そのまま表示する。**
```

⚠ **地図はズームで動く。**⚠ **「半径」という決めごと自体を持たない。**

### ⚠ ② 面には、⚠ 凡例で名前を付ける（⚠ 案 B）

```text
📍 いまいる場所
ここは 旧水部
かつて水面で、その後陸地にされた土地／標高 2.7m
  ■ 旧水部　■ 水部　■ 砂州・砂丘　■ 氾濫平野
  ♡ あとで見る    PC で詳しく →
```

⚠ **凡例は「いま映っているもの」だけ。**⚠ **ズームで増減する。**
⚠ **凡例は割合を言わない。**⚠ **言わなければ嘘にならない**
（⚠ 割合を出す案は `docs/adr/0053` で落としている）。

### ⚠ ③ これで役割分離が、⚠ 3 つとも字になる

```text
足元  = 点         ⚠ 「ここは 旧水部」      ⚠ `docs/adr/0053`
面    = viewport   ⚠ **凡例**              ⚠ **ここで決めた**
ピン  = 1km        ⚠ 近い順に最大 3 件      ⚠ `docs/adr/0052`
```

⚠ **3 つとも、⚠ 別の単位で、⚠ 別の言い方をする。**⚠ **混ぜない。**

## ⚠ 落とした案と、⚠ その理由

| 案 | 判断 | 理由 |
|---|---|---|
| A 足元だけ言う（⚠ 凡例なし） | ⚠ 採らない | ⚠ **面が「色として在る」だけで「情報として在る」形にならない。**⚠ 足元が少数派の土地で、⚠ **色と字が結びつかない** |
| C 周りとの関係で言う | ⚠ 採らない | ⚠ **「まわりは いまも水面です」は危険の話に読まれうる**（⚠ `docs/adr/0053` で案 2 を落とした理由と同じ）。⚠ **足元が多数派の土地では無意味**（⚠ 浦安）。⚠ **土地によって文の形が変わる** |

⚠ **A は、⚠ 足元が多数派の土地（⚠ 浦安）なら足りる。**⚠ **足りない土地があるので採らない。**
⚠ **条件で切り替えると、⚠ 「説明がある土地」と「無い土地」の差が意味を持ってしまう**
（⚠ `public/words.js` の GROUND_GLOSS が「例外を作らない」と決めているのと同じ筋）。

## ⚠ 凡例の決めごと（⚠ 2026-08-29 に足した。Owner）

### ⚠ ① 凡例は最大 3 つ。⚠ **現在地の区分を必ず含める**

```text
⚠ **凡例は、⚠ 面積順位の表示ではない。**
⚠ **現在地の地図理解を助けるもの。**

⚠ **現在地の区分を必ず含め、⚠ 残りを面積順として、⚠ 最大 3 種を表示する。**
⚠ **残りは「ほか n 種」。**
```

⚠ **土地によらず、⚠ 凡例の高さが変わらない。**

⚠ **「面積順に 3 つ」から言い直した**（2026-08-29。Owner。⚠ 下の実測による）。

### ⚠ ② 分類情報と、⚠ データ可用性を、⚠ 同じ凡例に混ぜない

```text
⚠ **凡例に入れてよいのは、⚠ 土地の性質だけ。**
⚠ **「区分が無い」＝ 整備されていない は、⚠ 凡例に入れない。**
```

⚠ **これは掟 §1 そのもの。**⚠ **「取れなかった」を「無い」と言わない。**

⚠ **「区分が無い」を凡例に並べると、⚠ **土地の一種**に見える。**
⚠ **実際は「地理院がまだ調べていない」であって、⚠ 「そこに何も無い」ではない。**

⚠ **整備されていない土地は、⚠ 地図の上で別の見せ方をし、
⚠ その説明は凡例の外で言う**（⚠ 例: 「斜線の部分は、まだ調べられていません」）。

## ⚠ なぜ「現在地を必ず含める」か（⚠ 実測 2026-08-29・15 地点）

```bash
node scripts/survey-legend-fit.mjs
```

⚠ **数字は書き写さない。**⚠ **判断が変わったところだけ書く。**

⚠ **Owner の言葉**（2026-08-29）:

```text
⚠ 15 地点中 14 地点では現在地区分は面積上位 3 種に含まれたが、
⚠ **松江では 4 位となり、⚠ 面積上位 3 種のみでは
⚠ カードに表示した現在地区分が凡例から消えた。**

⚠ そのため、⚠ **凡例は面積順位の表示ではなく現在地の地図理解を助けるもの**とし、
⚠ **現在地区分を必ず含め、⚠ 残りを面積順として最大 3 種を表示する。**
```

### ⚠ これが解いていること

⚠ **`docs/adr/0053` で案 A（⚠ 凡例なし）を落とした理由は、
⚠ 「色と字が結びつかない」だった。**

⚠ **面積順のままだと、⚠ 松江でだけ、⚠ その問題が戻る。**
⚠ **「ここは 旧水部」と書いた色が、⚠ 凡例に無い状態になる。**

### ⚠ 「面積順でなくなる」は、⚠ 弱みではなくなった

⚠ **凡例を順位表として読ませないと決めたから。**
⚠ **役割は「地図の色に名前を付けること」であって、⚠ 「何が広いかを言うこと」ではない。**

⚠ **実測でも、⚠ 15 地点中 14 地点では見た目が変わらない**
（⚠ 現在地が 1〜2 位なので、⚠ 先頭に置いても面積順と食い違わない）。

| ⚠ 地図で縁取り、⚠ 凡例は面積順のまま | ⚠ **1 行増える。**⚠ **15 地点中 14 地点で無意味な行。**⚠ **土地によって行数が変わる**（⚠ `docs/adr/0053` の案 C を落とした理由と同じ） |


## ⚠ 凡例まわりの 3 点（⚠ 2026-08-29 に決めた。Owner）

⚠ **網走（⚠ 未整備が混ざる）と松江（⚠ 現在地が面積 4 位）の実データで、⚠ 1 枚にまとめて決めた。**

### ⚠ ① 「ほか n 種」は、⚠ 押せる導線として残す

```text
⚠ **押下で bottom sheet に全区分を表示する。**
```

⚠ **`docs/adr/0026`（⚠ 押しても何も起きない導線）に触れない形。**
⚠ **押した結果が同時に見える。**

⚠ **落とした案**:

| 案 | 理由 |
|---|---|
| ⚠ 押せない字にする | ⚠ **「ほか 4 種」が何かは分からないまま。**⚠ 出す意味が薄い |
| ⚠ 「ほか n 種」を出さない | ⚠ **まだ色が残っていることが分からない。**⚠ 凡例が全部だと誤解されうる |

### ⚠ ② 未整備は、⚠ 地図の上で斜線

```text
⚠ **未整備部分は、⚠ 地図上では斜線で示す。**
```

⚠ **色を塗らないだけにしない。**
⚠ **「色が無い土地」と「まだ分類されていない土地」が、⚠ 同じに見えてしまう**（⚠ 掟 §1）。

### ⚠ ③ 断り書きは、⚠ 未整備が在るときだけ

```text
⚠ **未整備が存在する場合のみ、⚠ 短い説明を表示する。**
```

⚠ **松江のように 0% の土地では出さない。**
⚠ **「土地によって行数が変わる」が、⚠ 掟 §1 のほうが上位。**

### ⚠ ④ 未整備は、⚠ 土地の区分一覧に混ぜない

```text
⚠ **未整備は、⚠ **データ状態**として別に扱う。**
⚠ **凡例にも、⚠ bottom sheet の区分一覧にも入れない。**
```

⚠ **`docs/adr/0058`（⚠ 可用性は出典ごとに持つ）と同じ筋。**
⚠ **区分一覧は「土地の性質」、⚠ 未整備は「データの状態」。**⚠ **別の軸。**

⚠ **絵を描いたとき、⚠ bottom sheet の区分一覧に 8 行目として並べていた**
（⚠ 2026-08-29。⚠ **描いてから気づいた**）。⚠ **区分一覧の外へ出した。**
