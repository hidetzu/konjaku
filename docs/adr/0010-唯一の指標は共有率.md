# 見る指標は共有率だけにする。そのために場所を URL に載せる

- 状態: 採用
- 日付: 2026-08-11（旧 §3.11）

## 何が問題だったか

このサービスは「地図を見るもの」ではなく、**自分の土地について何かを知って、それを人に見せる**ための装置である。
だとすると体験は一回性で、滞在時間やリテンションを見ても何も分からない。

動線は一回性を**ループ**で受ける形になる。

```
SNS で誰かの結果を見る → 「自分の家は？」 → 場所を入れる → 数字と絵が出る → 共有する → 誰かが見る
```

**このループが閉じているかどうかだけが、面白いかどうかの代理指標になる。**
そして当時、ループを閉じる部品が1つも無かった ―― URL に場所が入らず、`navigator.share` も画像書き出しも計測も実測0件。

## 何を測ったか

- 実装前の `public/` に、`navigator.share`・画像書き出し・計測が**1つも無かった**（実測0件）
- 利用者は誰もいない。共有率を**一度も観測していない**状態だった
- 参考にしたのは Raycast。**月額で売っている、毎日使う道具**。⚠ 一回性の体験とは性質が違う
  - ⚠ 他社の価格や規模は書かない（変わるうえ、この判断には要らない）

## 決めたこと

- **見る指標は共有率だけ**（`shared` / `judged.*`）。滞在時間・リテンション・PV は見ない
- そのために、**場所を URL に載せる**（`?q=` `?ll=`）。これが無いと共有できずループが閉じない。
  3D（`/peel`）も同じで、URL から場所を復元できるようにする
- 共有カードを作る。共有率の分子を作る手段が要る
- 数えるのは**開き方によらず1回**。導線からでも共有URLからでも `open.peel` が合計1回になるようにする
- **判定が100件たまるまで共有率は評価しない。** 小さい分母で次の判断を決めない
- **判定・根拠・提案の近くに、金銭的な理由を置かない。** 表示内容への信頼と収益化を混ぜない

## そうしなかったこと

- **サブスクで継続課金** … Raycast から移せない。毎日開く前提の月額を一回性の体験に持ってくると必ず失敗する
- **拡張ストア（第三者にコンテンツを作らせる）** … 郷土資料や古地図を投稿させると検証と衝突する。ループが回ってから
- **滞在時間・リテンションを指標にする** … 見なくてよい
- **現在地を検索の並べ替えに使う** … 同じURLが人によって違う場所を指し、**共有ループが壊れる**
- **判定結果に応じた提案へ商品を混ぜる** … 提案の採否基準が金銭で汚染される

## 分かった穴（2026-08-14）

`open.peel` をトップページの導線（リンクの click）から送っていたため、
**共有された 3D の URL を踏んだ人が丸ごと計測から消えていた。**
共有はこの製品の唯一の指標なので、ここが欠けると
「共有されたが誰も踏まなかった」と「踏まれたが数えていなかった」を区別できない。

→ 数えるのを `peel.html` 側へ移した。両方で送ると導線から来た人だけ2回になるので、トップ側は消した。

## これを守っているもの

- `worker.js` の冒頭（目的はひとつだけ）、`scripts/stats.mjs`
- `public/peel3d.js` — URL から復元／場所を URL に載せる
- `public/share.js` — 共有カードと共有率の計測
- `npm run render` の `共有された 3D の URL を踏んだ人も、1回だけ数える` /
  `年代を動かしたことを、1回だけ数える`（二重計上と数え落としの両方を捕まえる）
- `public/places.js` — 現在地を並べ替えに使わない
