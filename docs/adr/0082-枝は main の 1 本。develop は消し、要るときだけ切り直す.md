- 状態: 決めた
- 日付: 2026-09-01

```text
feature → main   ⚠ これだけ。⚠ 出るのも main
```

⚠ **`develop` は消した。**⚠ **大きな開発をするときだけ、⚠ `main` から切り直す。**

⚠ **[0081](<0081-本番へ出すのは main への merge。develop は取り込むだけ.md>) を、⚠ 同じ日に置き換える。**

> develop は削除して、必要になったら main から切り直すでいいよ。大きな開発をするときにしか使わないし

## なぜ 1 日で変えたか

⚠ **0081 を作った直後に、⚠ 前提が 2 つ崩れた。**⚠ **どちらも実測。**

### 1. ⚠ `main` は ruleset で守られており、⚠ squash しか通らない

⚠ **0081 を書いたとき「ブランチ保護なし」と報告した。**⚠ **これは誤りだった。**
⚠ **旧 API（`/branches/main/protection`）が 404 を返したのを、⚠ そのまま信じた。**
⚠ **ruleset は別の仕組みで、⚠ そちらを見ていなかった。**

```text
ruleset「main を守る」（⚠ 例外なし・active）
  pull_request              ⚠ 直接 push は不可
    allowed_merge_methods: ["squash"]
  required_linear_history   ⚠ merge commit も不可
  required_status_checks    静的検査・外部リンク ／ 検索の並び ／ 実描画
  deletion / non_fast_forward
```

⚠ **早送りも merge commit も、⚠ この ruleset が明示的に禁じている。**⚠ **squash だけが通る。**

### 2. ⚠ squash は、⚠ 長命な枝どうしを恒久的に分岐させる

⚠ **実測（手元で再現した）**:

```text
squash 直後            main..develop = 3 本   ⚠ 減らない
main を develop へ取り込む → 4 本            ⚠ 増える
新しく 2 本積む        → 6 本               ⚠ 古い 3 本を引きずる
```

⚠ **`main` を `develop` へ取り込んでも、⚠ 本数は 0 にならない。**
⚠ **取り込みは「`main` の側を足す」だけで、⚠ `develop` の側を消さないから。**

⚠ **取り込みで直るのは、⚠ 祖先関係とタグの到達性だけ。**

| | 取り込み前 | 取り込み後 |
|---|---|---|
| `main` は `develop` の祖先か | ⚠ いいえ | はい |
| `main` のタグを `develop` から辿れる | ⚠ 辿れない | 辿れる |
| `main..develop` の本数 | 3 | ⚠ **4**（減らない） |

⚠ **本数まで 0 にする方法は、⚠ `develop` を捨てて切り直すことだけだった。**

## 決めたこと

- ⚠ **`develop` を消す。**⚠ **中身は `main` にある**（⚠ 実測: ファイルの差 0）。
- ⚠ **push のトリガは `main` だけ。**
- ⚠ **出す枝も `main` だけ。**⚠ **`||` で枝を足さない**（⚠ どこから出たか追えなくなる）。
- ⚠ **大きな開発をするときは、⚠ `main` から切る。**⚠ **切ったら `check.yml` のトリガに足す**
  （⚠ 足さないと、⚠ その枝では何も走らない。⚠ **落ちないので気づけない**）。

## ⚠ 失うもの

⚠ **良いことだけ並べない。**

- ⚠ **「取り込んで様子を見る」場所が無くなる。**⚠ **PR が `main` へ直接向かう。**
  ⚠ **ただし ruleset が検査 3 つを必須にしているので、⚠ 赤では入らない。**
- ⚠ **今日 squash した 69 本を、⚠ 1 本ずつ辿る道が消える**（⚠ どの枝からも辿れなくなる）。
  ⚠ **中身は 1 バイトも失われない**（⚠ 実測: `main` と `develop` のファイルの差 0）。
  ⚠ **PR の参照（343 本）には残るが、⚠ GitHub が回収しうる。**
