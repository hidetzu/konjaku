# 開発の計測は、配信の計測と分けて、Git の外に置く

- 状態: 採用
- 日付: 2026-08-24

## 判断

AI へ渡した Task が **いつ始まり、いつ終わったか** を、Claude Code Hooks で
**手元の JSONL に残す**。⚠ **git に入れない。**⚠ **外へ送らない。**
⚠ **本文を持たない。**⚠ **成否を採点しない。**

書くのは `.claude/hooks/telemetry.mjs` の 1 本だけ。使う Hook は 2 つ。

```text
UserPromptSubmit  →  Turn の始まり
Stop              →  Turn の終わり
```

## ⚠ なぜ「配信の計測」と分けるか

この repo には、⚠ **すでに計測がある**（[0028](0028-配信用データと計測データを分離する.md)）。
⚠ **そちらは利用者の匿名イベント**で、Worker から D1 の `tick` / `health` へ入り、
⚠ **地名も座標も送らない**（[0008](0008-地名も座標も送らない.md)）。

⚠ **今回のものは、まったく別の話。**⚠ **測っているのは利用者ではなく、こちらの作業。**

| | 配信の計測（既存） | 開発の計測（これ） |
|---|---|---|
| 誰を測るか | 利用者 | ⚠ **作っている側** |
| どこへ行くか | Worker → D1 | ⚠ **手元のファイルだけ** |
| 誰が読めるか | 運用側 | ⚠ **その機械の持ち主だけ** |
| git | 入らない | ⚠ **入らない**（`.gitignore`） |

⚠ **同じ「計測」という語で 1 つにまとめない。**⚠ **まとめると、
開発の記録が配信の口へ流れる道ができる**（掟 §1: 取れたものを、取れる先へ全部流さない）。

## ⚠ Session を Task とみなさない

```text
Task
 └─ Claude Code Session
      ├─ UserPromptSubmit
      └─ Stop
```

⚠ **1 つの Task が、複数 Turn・複数 Session にまたがる。**
だから Task の識別を、Session ID に寄せない。

⚠ **人に Task ID を入力させない。**⚠ **プロンプトから読み取れるものだけで決める。**

| 読み取れたもの | Task のまとめ方 | `grouping` |
|---|---|---|
| Issue（`<owner>/<repo>#<番号>` か裸の番号） | ⚠ **その Issue が Task**（Session をまたいでも同じ） | `issue` |
| 何も読み取れない | ⚠ **1 プロンプト = 1 Task**（⚠ **束ねない**） | `turn` |

### ⚠ 束ねてよいのは、束ねる根拠があるときだけ

⚠ **最初は「同じ Session の連続した Turn」を 1 Task にしていた。**⚠ **やめた**（2026-08-24）。

```text
19:00 「CSS を整理して」  ┐
19:15 「README を直して」 ├→ ⚠ 1 Task・3 Turn・30 分に化ける
19:30 「この SQL どう思う？」┘
```

⚠ **Hook からは、⚠ これが 1 つの仕事の続きなのか、⚠ 別々の用事なのか分からない。**
⚠ **本文を持たないので、⚠ あとから割れない。**

⚠ **逆向きなら、⚠ あとからでも束ねられる**（⚠ 「T001 と T002 は同じ仕事だった」と言える）。
⚠ **だから、⚠ 割れる側に倒す。**⚠ **記録するのは事実だけにする。**

### ⚠ 何を根拠に決めたかを、必ず一緒に書く

⚠ **`grouping` も `task_type` も推定。**⚠ **どちらも観測値ではない。**

| 欄 | 値 | 何を見たか |
|---|---|---|
| `grouping` | `issue` | ⚠ プロンプトに Issue が書いてあった |
| | `turn` | ⚠ **根拠が無いので束ねなかった** |
| `task_type_source` | `prompt_pattern` | ⚠ Skill の名前が書いてあった |
| | `issue_ref` | ⚠ **Issue があるから `issue_execute` とみなした** |
| | `default` | ⚠ 何も読み取れなかった |

⚠ **実際に取り違える**: 「`#<番号>` について調べて」は、⚠ **中身は `issue_refine` でも
Issue があるので `issue_execute` になる。**⚠ **読む側が、⚠ それを知れるようにする。**

⚠ **この欄を消すと、推定が実測の顔をする**（`CLAUDE.md` §1）。

⚠ **裸の番号は、リポジトリが変われば別の Issue を指す**（`CLAUDE.md` §9）。
⚠ **記録に残すときは、必ずリポジトリ名を付ける。**

## ⚠ 記録しないもの

⚠ **Task の識別に要らないものは、書かない。**

```text
プロンプト本文        最後の返答本文        本文のハッシュ
transcript の中身     cwd / 環境変数        ツールの入出力
トークン数・費用      人の名前              秘密（API Key / token / password）
```

⚠ **本文の代わりに `prompt_id` を使う**（Claude Code が振る UUID）。
⚠ **本文を 1 文字も持たずに、同じプロンプトの始まりと終わりを結べる。**
⚠ **長さ（文字数）だけは残す。**あとで「長い依頼ほど Turn が増えるか」を見るため。

⚠ **ハッシュも持たない。**⚠ 短い依頼は、⚠ **総当たりで元に戻せる。**

## ⚠ 採点しない

⚠ **Phase 1 で観測できたのは「Turn が終わった」ことだけ。**
⚠ **やり遂げたかどうかは見ていない。**だから `result` は `unknown` から動かさない。

⚠ **`completed` と書き始めた瞬間に、⚠ 推定が実測の顔をする。**
⚠ **静的検査が、⚠ `unknown` 以外を書いたら落とす。**

## ⚠ 作業を止めない

⚠ **`UserPromptSubmit` と `Stop` は、exit 2 で止まる Hook。**
⚠ **前者はプロンプトごと消え、⚠ 後者は会話が終われなくなる。**

⚠ **何が起きても exit 0。**⚠ **stdout へ 1 文字も出さない**
（⚠ `UserPromptSubmit` の stdout は、⚠ **Claude への追加文脈として読まれる**）。

⚠ **観測のために作業が止まったら本末転倒。**
⚠ **計測が取れないことより、⚠ 作業が止まるほうが悪い。**

## ⚠ どう確かめるか

⚠ **字面だけで見ない。**⚠ **静的検査が、⚠ 実際に Hook を走らせて、⚠ 出てきたものを読む**
（`test/check/guard.mjs`。⚠ 書き先は `KONJAKU_TELEMETRY_DIR` ですげ替えるので、
⚠ **本物の記録は汚さない**）。

## 変更時の確認事項

- ⚠ **新しい欄を足すときは、⚠ Task の識別に本当に要るかを先に言う**
- ⚠ **本文・ハッシュ・人名を足さない**
- ⚠ **`result` を採点に使うなら、⚠ 何をどう測ったかを同時に決める**（Eval は別の判断）
- ⚠ **外へ送る話が出たら、⚠ この ADR を書き直してから**（黙って送り先を足さない）
