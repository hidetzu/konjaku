# 0056. 明治期の低湿地の状態を 3 つに分けて言い分ける

- 状態: 採用（⚠ **決めたのは Owner。**⚠ 2026-08-29。⚠ 原文は `tmp/tmp2.md`）
- 日付: 2026-08-29

⚠ **`docs/adr/0055` は「分類情報とデータ可用性を、⚠ 同じ凡例に混ぜない」と決めた。**
⚠ **では、⚠ 可用性のほうを何と言うのか。**⚠ **その答え。**

## 背景

⚠ **国土地理院の「明治期の低湿地」は 2023 年に「整備完了」とされているが、
⚠ **全国を隙間なく整備したという意味ではない**（`tmp/tmp2.md`）。**

⚠ **つまり、⚠ 少なくとも 3 つの状態がある。**

## 決めたこと ── ⚠ **3 つを別のこととして扱う**

```text
① ⚠ 整備範囲内で、⚠ 区分あり      → ⚠ 「水田」「河川」「湿地」などを表示する
② ⚠ 整備範囲内だが、⚠ 区分が無い  → ⚠ **明治期の地図はあるが、⚠ 該当分類が無い**
③ ⚠ **そもそも整備範囲外**        → ⚠ **この地域には、⚠ 明治期の低湿地データが作られていない**
```

⚠ **② と ③ を、⚠ 同じ言葉で言わない。**

```text
②  ⚠ **「この場所はまだ分類されていません」**      ⚠ ← 調べる対象ではあった
③  ⚠ **「この地域ではこの資料は作られていません」** ⚠ ← 調べる対象に入っていない
```

⚠ **決めたのは Owner**（2026-08-29）。⚠ **画面に出る言葉なので、⚠ こちらでは決めない。**

⚠ **どちらも「無い」ではない**（掟 §1）。⚠ **「取れなかった」でもない。**⚠ **別のこと。**

## ⚠ 機械で分けられる（⚠ 実測 2026-08-29・13 地点）

```bash
node scripts/survey-swale.mjs
```

⚠ **数字は書き写さない。**⚠ **判断が変わったところだけ書く。**

```text
⚠ **③ は、⚠ タイルが 404 で返る。**⚠ **那覇・稚内・高知・石垣。**
⚠ **①② は、⚠ タイルが 200 で返る。**
⚠ **200 が返る地点では、⚠ 透明画素がどこも 0%。**
```

⚠ **`HTTP 200` を「データがある」と読まない**のは変わらないが、
⚠ **`404` が「整備範囲外」の合図になる**ことが分かった。

## ⚠ 踏んだこと ── ⚠ **下地を「整備の穴」と読み違えた**

⚠ **前の測定で「凡例に当たらない画素が 9〜33% ある」と報告し、
⚠ それを「整備されていない土地」と読んでいた。**⚠ **違った。**

```text
⚠ **あれは地図の下地**（⚠ 道路・注記・背景）。
⚠ **透明画素が 0% であることが、⚠ その証拠。**
```

⚠ **`public/swale.js` は、⚠ 透明と凡例外を別々に数え、⚠ どちらも分母から外している。**
⚠ **こちらはそれを混同していた。**⚠ **走者を、⚠ 3 状態が分かる形に直した。**

## ⚠ 公開範囲図と、⚠ 配信されているタイルが一致していない

⚠ **公開範囲図では対象外に見える地点でも、⚠ 凡例色が取れる**（⚠ 網走・釧路・札幌・盛岡・長野）。

⚠ **これは測れた事実。**⚠ **どちらが正しいかは、⚠ こちらでは分からない。**
⚠ **だから「公開範囲図に載っているか」で判定しない。**⚠ **実際に取れるかで判定する。**

## ⚠ 画面がどうなるか

```text
①  豊洲    ⚠ 断り書き無し
②  網走    ⚠ 「この場所はまだ分類されていません」        ⚠ **凡例の外**（`docs/adr/0055`）
③  那覇    ⚠ 「この地域ではこの資料は作られていません」
```

⚠ **那覇なら、⚠ こう並ぶ**（Owner・2026-08-29）:

```text
足元
  標高 8.6m
  地形分類 ○○

明治期の低湿地
  ⚠ この地域ではこの資料は作られていません
```

### ⚠ これは「エラー」ではない

```text
⚠ **ひとつの資料カードの、⚠ 正常な状態。**
```

⚠ **そう捉えると、⚠ 画面設計がかなり楽になる**（Owner）。
⚠ **「読み込めませんでした」と同じ場所に置かない。**⚠ **失敗ではない。**

⚠ **③ でも、⚠ 足元と凡例はいつもどおり出る。**
⚠ **地形分類は別のデータで、⚠ 那覇でも取れることを確かめた**（⚠ 標高も取れた）。
⚠ **無いのは明治期の低湿地だけ。**

⚠ **「何も出せません」にしない。**⚠ **出せるものは出す**（`CLAUDE.md` §4-1）。

## ⚠ 訂正 ── ⚠ **口が 2 つあり、⚠ 別の口を測っていた**（⚠ 2026-08-29）

⚠ **上の測定は `/xyz/lcmfc2/` を叩いていた。**
⚠ **`public/verify.js` が実際に叩くのは `/xyz/swale/`。**⚠ **画面に出るのはこちら。**

⚠ **測り直したら、⚠ 2 つの口は範囲がほとんど重なっていなかった。**

```bash
node scripts/survey-swale.mjs
```

```text
⚠ **`swale` で取れるのに `lcmfc2` で取れない土地がある**（⚠ 高知）。
⚠ **`lcmfc2` で取れるのに `swale` で取れない土地がある**（⚠ 松江・網走・札幌・盛岡・長野・釧路・旭川）。
⚠ **どちらでも取れない土地がある**（⚠ 那覇・稚内・石垣）。
```

### ⚠ 何が間違っていたか

```text
⚠ **「明治期の低湿地は網走にもあった」と書いたが、⚠ それは `lcmfc2` の話。**
⚠ **画面が使う `swale` では、⚠ 網走は 404。**
```

⚠ **`docs/adr/0055` にも同じ誤りを書いた。**⚠ **そちらも直す。**

### ⚠ 3 状態の判定そのものは変わらない

⚠ **`404` が「整備範囲外」の合図、⚠ という結論は変わらない。**
⚠ **変わるのは「どの土地がどの状態か」。**⚠ **口によって違う。**

⚠ **画面が言うことは、⚠ 画面が使う口で決まる。**⚠ **`swale` で測る。**

### ⚠ なぜ踏んだか

```text
⚠ **`verify.js` を読まずに、⚠ 地理院のレイヤ一覧から口を選んでいた。**
⚠ **β 版が既にどこを叩いているかを、⚠ 先に見ていなかった。**
```

⚠ **`docs/adr/0059` に「作り直す前に β 版を読む」と書いたばかりだった。**⚠ **同じ形で踏んだ。**


## ⚠ この ADR は、⚠ 明治期の低湿地に閉じる

⚠ **一般化しない**（2026-08-29。Owner）。⚠ **ここで扱うのは、⚠ この 1 つの出典の観測事実だけ。**

⚠ **次に調べるべきは、⚠ **地形分類にも ③ が存在するか**。**
⚠ **ここだけ測れば、⚠ 表示モデルを抽象化できるかが決まる。**

```text
⚠ 地形分類にも同じ構造がある   → ⚠ **共通のデータ状態モデルにする値打ちがある**
                                  （⚠ AVAILABLE / UNCLASSIFIED / OUT_OF_COVERAGE / ERROR のような形）
⚠ 地形分類には ③ が無い        → ⚠ **まだ共通化しない**
```

⚠ **空中写真・建物まで、⚠ いま同じ枠に入れるのは早い。**
⚠ **一般化できると分かってから、⚠ 別 ADR で「データ可用性モデル」に上げる。**

## ⚠ この調査でいちばん大きかったこと

```text
⚠ **情報がないときにも、⚠ その理由を正しく説明すれば、⚠ 今昔の画面は成立する。**
```

⚠ **那覇を表示できるようになったこと自体より、⚠ こちらのほうが効く。**

## ⚠ 決めていないこと

```text
⚠ ③ のとき、⚠ 断り書きを常に出すか（⚠ 出すと、⚠ 那覇では毎回出る）
⚠ ~~地形分類にも ③ が在るか~~ → ⚠ **測った。**⚠ **`docs/adr/0057`**（⚠ 答えは「形が違う」）
⚠ ほかの出典（⚠ 空中写真・建物）を、⚠ 同じ枠で扱うか（⚠ **まだ早い**）
```

⚠ **地形分類に ② が在ることは分かっている**（⚠ 網走で「区分が無い」が出た）。
⚠ **③ が在るかは測っていない。**
