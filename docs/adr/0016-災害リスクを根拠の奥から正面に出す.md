# 災害リスクを、根拠パネルの奥ではなく判定カードの正面に出す

- 状態: 採用（畳むが、消さない）
- 日付: 2026-08-11（旧 §3.26）

## 何が問題だったか

一度、「防災クラスタは検証（A）側の客だから、作品（B）を選んだこの製品では狙えない」と判断した。
その判断で災害リスクの記述を根拠パネルの奥に置いていた。

**だがこの判断は、ランチャー化より前の前提に乗っていた。**
場所のランチャーになった以上（0009）、防災は「その場所に付随するもの」のひとつであって、A/B の二択の外にある。
**古い前提の上で正しかった判断を、前提が変わった後もそのまま持ち回っていた。**

## 何を測ったか

数字での実測はない。事実として確認したのは1点。

- 0004 で入れた**地形分類には、国土地理院自身が書いた災害リスクの文が付いている**
  （`public/data/landform.json` の 36区分すべてに `why`（成因）と `risk`（災害リスク））

つまりこちらが何も書かなくても、**出典の文をそのまま引用するだけで正面に出せる。**
0007 の「断定ではなく引用のときは出典を添え、要約しない」がそのまま適用できる形だった。

## 決めたこと

- **災害リスクを判定カードの正面に出す。** 根拠パネルの奥に置かない
- 文は**国土地理院の記述をそのまま**。こちらで要約しない。**見出しには危険の中身を書かない**
  （要約すると原典より強くも弱くもなる）
- 後に画面の高さを詰めるときも、**畳むが、消さない。** 正面へ引き上げた判断そのものは生きている
- 「防災クラスタを新しい狙いに据える」という読み替えは**しない**。誰に向けるかは共有率を観測してから決める（0004）

## そうしなかったこと

- **古い判断を黙って書き換える** … 訂正は古い判断を消すためではなく、**なぜ当てはまらなくなったかを残すため**に書く。
  判断は当時の前提の上で正しく、変わったのは前提のほう
- **災害リスクの文を自分で書き直して短くする** … 引用でなくなる
- **リスクを2層目へ戻す** … 検討したが、正面に上げた判断ごと見直すことになるので次のラウンドへ送った

## これを守っているもの

- `public/index.html` — 災害リスクを根拠パネルの奥から正面へ引き上げる箇所と、
  「⚠ 畳むが、消さない」のコメント
- `public/data/landform.json` の `risk`（地理院の記述そのまま）
