# Discovery は、案を出すより先に案を捨てる

- 状態: 採用
- 日付: 2026-08-24

## 判断

「次に何を改善する価値がありそうか」を探す Skill を置く
（`.claude/skills/product-discovery/SKILL.md`）。

⚠ **ただし、⚠ 責務の中心は「案を出すこと」ではない。**⚠ **「案を捨てること」。**

⚠ **捨てる判断をしたことが読めない Discovery は、⚠ Discovery ではない。**

⚠ **これは「`Rejected` を空にするな」ではない**（2026-08-24。Owner 判断）。
⚠ **件数を求めると、⚠ 落とすつもりのない案を並べて落とすようになる**
（⚠ **候補の水増しと同じ病**）。⚠ **求めるのは件数ではなく、⚠ 判断の跡。**

```text
## Rejected
- なし
  理由: この Scope では、⚠ 比較できる別の仮説を Evidence から作れなかった
```

⚠ **これは正しい Discovery の結果。**⚠ **`なし` とだけ書いて理由が無いものが、⚠ 駄目。**

## ⚠ なぜ「捨てる」を責務にするか

⚠ **AI は、放っておくともっともらしい機能を大量に出す。**
⚠ **出す側は速く、⚠ 捨てる側は遅い。**⚠ **だから、⚠ 捨てるほうを仕事にする。**

この repo は、既にその向きで揃っている。

- `CLAUDE.md` §3: ⚠ **新しい仕組みを増やすより、⚠ 同じ意味の処理を一つにまとめる**
- `.claude/rules/domain.md`: ⚠ **この問いに答えないものを、⚠ 便利そうという理由で足さない**
- [0026](0026-押しても何も起きない導線を置かない.md): ⚠ **押しても何も起きない導線を置かない**

⚠ **Discovery だけが「増やす側」に立つと、⚠ そこが穴になる。**

## ⚠ なぜ `ui-ux-review` / `issue-ready` と分けるか

⚠ **答える問いが違う。**⚠ **同じ Skill に入れると、⚠ どれも中途半端になる。**

| | 答える問い | 前提 |
|---|---|---|
| `product-discovery` | ⚠ **何を改善する価値がありそうか** | ⚠ **方向がまだ決まっていない** |
| [`ui-ux-review`](../../.claude/skills/ui-ux-review/SKILL.md) | 画面が成立しているか | ⚠ **方向は決まっている** |
| [`issue-ready`](../../.claude/skills/issue-ready/SKILL.md) | AI に渡せる形か | ⚠ **やることが決まっている** |

⚠ **判断基準を写さない。**⚠ **5 秒ルール・4 幅・44×44・重なりは `ui-ux-review` が正本。**
⚠ **Discovery は、⚠ その判定を Evidence として使うだけ**（掟: 同じ問いに答える実装を 2 つ持たない）。

## ⚠ なぜ優先順位を自動で決めないか

⚠ **優先順位は価値判断で、⚠ 実測では決まらない**（`CLAUDE.md` §7-1 の右の列）。

⚠ **点数を付ければ決まったように見えるが、⚠ その点数は測っていない**
（[0005](0005-確率を出さず実測値そのものを出す.md): ⚠ **確信度を数値化しない**）。

⚠ **落とすのは、⚠ Evidence で落とせるものだけ。**
⚠ **`AI では判断できない` は `REJECT` ではない。**⚠ **`HUMAN-DECISION`。**
⚠ **何でも人へ投げるのも、⚠ 人の時間を奪うので同じくらい悪い。**

## ⚠ AI Task の計測を、利用者の話に読み替えない

`main` には AI Task の計測（[0035](0035-開発の計測は配信の計測と分けてGitの外に置く.md)）と
その集計（[0036](0036-Evalは観測を比べるだけで良し悪しを決めない.md)）がある。

⚠ **測っているのは、⚠ こちらの開発作業。**⚠ **利用者の求めていることではない。**

```text
Task の所要時間 ／ Turn 数 ／ Session 数
        ↓
⚠ 「この機能は利用者に重要」 ⚠ 「この UX は悪い」 ⚠ 「これを優先すべき」
        ↓
⚠ どれも言えない
```

⚠ **使ってよいのは、⚠ AI Workflow 側を見るときだけ**（⚠ しかも `Inferred`）。
⚠ **`result` は常に `unknown`**（0036）。⚠ **Discovery 側で成功・失敗へ読み替えない。**

⚠ **利用者側の計測（`/t` の `tick` / `health`）は別もの**（[0028](0028-配信用データと計測データを分離する.md)）。
⚠ **どちらの話をしているかを、⚠ 毎回名乗る。**

## ⚠ Skill が Issue を作らないことを、機械で見張る

⚠ **文書に「作らない」と書くだけにしない。**

`test/check/guard.mjs` は `.claude/` の中を走査して、
⚠ **AI が人の判断を飛ばせる書き方**を落としている。
⚠ **`gh issue create` / `gh issue edit` を、⚠ その一覧へ足した**（2026-08-24）。

⚠ **実測（2026-08-24・`main` = `ff1fcee`）: 足す前の該当は 0 件。**
⚠ **既存の Skill は 1 つも使っていない。**⚠ **だから、⚠ 足しても何も壊れない。**

⚠ **Issue を起こすのは人。**⚠ **Discovery は Draft を書くところまで。**

## 変更時の確認事項
