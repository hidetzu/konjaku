# Service Worker の版は手で書かず、キャッシュ対象の中身から振り直す

- 状態: 採用
- 日付: 2026-08-12

## 何が問題だったか

`sw.js` の `VERSION` は**キャッシュのキーそのもの**である。
手で番号を振っていたころ、中身だけ変えて上げ忘れると、**一度来た人に古い画面が出続けた。**

しかも、

- **ローカルでは初回訪問なので絶対に再現しない**
- **CI も全部通る**

いちばん診断しづらい壊れ方をする。流入を測り始める直前に一度踏みかけた（看板を変えたのに `v4` のままだった）。

## 何を測ったか

- 踏みかけた実例: 看板を「この土地は、昔なんだったのか？」に変えたのに `VERSION` が `v4` のまま
- SHELL に入れるものの重み: **MapLibre 1,032KB ＋ CSS 68KB** を SHELL に入れていたため、
  初回訪問が **250KB → 1,646KB** になっていた。判定しか見ない人にも丸ごと乗る。
  Zenn 流入はほぼ全員が初回なので、1万PV で約 16GB の差
- 索引を SHELL に入れると、**取り込みのたびに全利用者のキャッシュが丸ごと捨てられる**
  （全国に広げれば索引だけで 1MB 超）
- 3D の実装（`peel3d.js`）を SHELL に入れると、**3D を1行直すたびに同じことが起きる**
- Service Worker は**告知当日には効かない**（2回目の訪問から）

## 決めたこと

- **`VERSION` は `SHELL` の中身から決まるハッシュ。** `npm run stamp` が振り直し、古ければ CI が落ちる
- SHELL に入れるのは、**判定しか見ない人にも必要なものだけ**。
  地図エンジンと 3D の実装と索引は入れない（触った人だけが読む）
- タイルの棚（`konjaku-tiles-v1`）は版が上がっても消さない。溜めた意味が無くなる
- 地理院タイルは端末の中に置くだけ（再配信ではない）。**最大250枚**、
  古い年代は30日・`seamlessphoto` は1日で切る
- リリースタグ・`package.json` の `version`・CHANGELOG は**いま整理しない**。
  SW の版だけが例外で、これは「約束」ではなく**「事故」の側**だから

## そうしなかったこと

- **手で番号を上げる運用にして、チェックリストで守る** … ローカルで再現せず CI も通るので、人では守れない
- **地理院タイルを素通しする** … 実測して考えを変えた。地理院タイルは `Cache-Control` も `Expires` も返さない
  （返るのは ETag と Last-Modified だけ）ので、ブラウザは経験則で判断するしかなく取り直しが起きる。
  素通しは「溜め込まない」ではなく「**同じ絵を何度も取りに行く**」だった
- **セマンティックバージョニングを導入する** … 分母が来てから

## これを守っているもの

- `public/sw.js` の `VERSION` / `SHELL` / `TILES` / `TILE_MAX`
- `scripts/sw-hash.mjs`（なぜハッシュにしたかの全文はここの頭にある）、`scripts/stamp-sw.mjs`
- `npm run check` の `konjaku-xxxxxxxx（SHELL の中身と一致）` /
  `sw.js の SHELL に判定の依存が揃っている（11 件）` / `sw.js の SHELL は全件が配信物にある` /
  `SHELL に 3D 側のものは入っていない`
