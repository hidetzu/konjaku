# 枠は 2 段。情報を持つものだけに下限を求める

- 状態: 採用
- 日付: 2026-08-28

## 判断

⚠ **枠を 2 つに分ける。**⚠ **情報を持つほうだけに 3.0 を求め、⚠ 検査が落とす。**

```text
--line-strong  情報を持つ枠   押せるもの・入力・箱の輪郭   ⚠ 3.0 以上（⚠ 落とす）
--line         区切り線       面と面の境目・待機中の骨組み  ⚠ 下限は求めない（⚠ 数字だけ出す）
```

⚠ **実測（2026-08-28）**: ⚠ `--line-strong` は 4 つの色みで 3.06 / 3.14 / 3.06 / 3.12。
⚠ `--line` は 1.28 / 1.38 / 1.48 / 1.63（⚠ **変えていない**）。

## なぜ

⚠ **3.0 は「情報を持つ部品の境界」への要求。**
⚠ **枠は 58 か所で使われていたが、⚠ そのすべてが情報を持つわけではない**
（⚠ 実測: ⚠ 情報を持つ 47 ／ 区切り 10。⚠ 残り 1 は era-control の 1 件）。

⚠ **59 か所すべてに一律で当てると、⚠ 根拠のない主張を検査に固定する**
（`CLAUDE.md` §9: ⚠ 静的検査そのものが間違った方向へ後押しすることがある）。

⚠ **上げないままにもできない。**⚠ **警告が「届いていない」としか言っておらず、
⚠ 未対応に読めた。**⚠ **決めた上でそうしている、と読める形にする必要があった。**

## ⚠ どう決めたか

⚠ **絵で決めた**（ADR 0042）。⚠ **いま（1.28 / 1.48）・中間（2.0）・3.0 の 3 案を、
⚠ 同じ切り取り・明るい暗い両方で撮って Owner に渡した。**
⚠ **Owner 判断（2026-08-28）: ⚠ 「B 情報を持つ枠だけ」。**

⚠ **3.0 を全部に当てた絵では、⚠ 枠が答えの字と競合していた**（⚠ Issue の Stop Conditions
「枠が主役より目立つようになった」に当たる状態）。
