# 実行時の外部APIは「止まりうる依存」として扱い、事前に固められるものは固める

- 状態: 採用
- 日付: 2026-08-11（旧 §3.17）／取り込みへの移行は 2026-08-14

## 何が問題だったか

「座標は地図クリックで得られるので住所検索が要らない」と書いていたが、楽観的すぎた。
実際には住所検索が入口であり、しかもその API は**公開APIではなかった。**

国土地理院の回答（原文）:

> 主に地理院地図からの利用を想定しております
> 必ずしも常にまた長期的に提供できるとは限りません
> 仕様や利用方法は、予告なく変更する場合があります

地形分類も `experimental_landformclassification` という**提供実験**で、同じ性質を持つ。
Wikidata・Overpass も実行時に叩けば同じ。**止まりうるものの上に、主題そのものが乗っていた。**

## 何を測ったか

- `https://msearch.gsi.go.jp/` は **403**（APIホストなので閲覧不可）
- 参照 issue: `gsi-cyberjapan/gsimaps#29`
- Overpass 公開インスタンス: 実測で **406 / 429 / 504 / タイムアウト**。
  `overpass-api.de` 504（10.4秒）／`overpass.kumi.systems` 応答なし（40秒）
- 取り込みに移した効果: 取り込み済みの土地では Overpass も Wikidata も**1リクエストも出ない**（広島で実測 Overpass 0件）
- 候補地を測る道具そのものが、同じ罠を踏んだ ―― 25地点を続けて叩いたら
  **西新宿と汐留が `net::ERR_ABORTED`** で返り、0件と記録していたら
  **西新宿（157件）と汐留（314件）を「何も無い街」として候補から外していた**

## 決めたこと

- **止まる前提で書く。** 落ちたときに断定せず、再試行を出す（0001）
- **落ちたときに黙って別の答えを出さない。** 地形分類が落ちたら地形分類の欄が読めないだけで、
  明治期の答えをそこに滑り込ませない
- **事前に固められるものは固める。** 事物（Wikidata）と建物（Overpass）は手元で1回取り、静的タイルとして配る。
  索引に載っている土地では実行時に外へ出ない
- 取り込みは**途中から再開できる**形にする。1件断られただけで全部測り直すのは相手にも自分にも損
- 取れなかったものは `-1` などの**別の値**で持ち、0 と混ぜない。
  「済み」の判定に `err` の付いた行を入れない（入れると「取れなかった」が「0件」として固定される）
- 実行時に残る外部は、画面に出典として全部書く

## そうしなかったこと

- **Nominatim 公開インスタンス** … 商用・大量利用は禁止
- **CSIS シンプルジオコーディング** … 地理院自身が代替として挙げるが「実験」の位置づけで参加規約あり（規約未読）。保留
- **Geolonia NJA ＋ アドレス・ベース・レジストリを自前に取り込む** … 筋としてはこれが本命だが、未着手
- **明治期データの有無を検索の並べ替えに使う** … 検索経路に新しい実行時外部依存が増える。逆行する
- **Overpass を全部やめて事前計算だけにする** … 索引に無い土地では実行時に落ちるが、
  そのとき**水域と空中写真だけで画面が成立する**ようにしてある

## これを守っているもの

- `public/verify.js` — 地形分類を「住所検索と同じで、止まりうる依存として扱う」
- `public/events.js` — Wikidata は実行時に問い合わせるので止まりうる
- `scripts/ingest-wikidata.mjs` / `scripts/ingest-buildings.mjs` — 取り込みと再開
- `npm run render` の `取り込み済みの土地では、Wikidata を叩かない` / `建物が取り込み済みなら、Overpass に出ない` /
  `Wikidata が落ちても「無い」と言わない` / `建物が取れないとき、待たせ続けない`
- `npm run render` の `通信した先が、全部フッターに書いてある`
