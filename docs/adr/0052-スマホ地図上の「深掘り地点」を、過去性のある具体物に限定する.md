# 0052. スマホ地図上の「深掘り地点」を、過去性のある具体物に限定する

- 状態: 採用（⚠ **決めたのは Owner。**⚠ 2026-08-29。⚠ 原文は `tmp/tmp2.md`）
- 日付: 2026-08-29

⚠ **`docs/adr/0051` が空欄で残していた「深掘りできる具体物とは何か」の答え。**

## ⚠ 決め方を変えた

```text
⚠ **データソースから決めるのではなく、
⚠ 「ピンを押したら何が分かるのか」から決める。**
```

⚠ **これが効く理由は、⚠ 実際に踏んだ食い違いが説明できるから。**

⚠ **2026-08-29 の実測で、⚠ 大阪梅田は「1km で 0 件」にも「上限 200 件」にもなった。**
⚠ **半径の問題ではなく、⚠ **ピンの意味が未定義だった**ことを示していた**（Owner）。

## 決めたこと

⚠ **ピンは 2 種類だけ。**

| ピン | 答える問い | 例 |
|---|---|---|
| ⚠ **昔ここにあったもの** | 「ここは昔何だった？」 | 旧橋・廃駅・旧工場・城跡・旧河道・建物跡 |
| ⚠ **ここで起きたこと** | 「ここで昔何があった？」 | 災害・事故・歴史的出来事・自然災害伝承碑 |

⚠ **この土地そのものが昔どうだったかは、⚠ ピンにしない。**⚠ **面の色に任せる**（`docs/adr/0051`）。

```text
面    「この辺りは昔、水部だった」
  ＋
ピン  「300m 先に旧○○橋があった」
      「450m 先で○○災害が起きた」
```

## ⚠ ピンになる条件（⚠ 5 つ）

```text
1  緯度経度がある
2  何の場所か特定できる
3  ⚠ **過去について言えることがある**
4  時代・年代の手掛かりがある
5  出典を示せる
```

⚠ **3 がいちばん重い。**⚠ **これを満たすものを「深掘りできる具体物」と定義する。**

⚠ **条件は「名前があるか」ではない**（`docs/adr/0051` で測った ── ⚠ β のピンも、
⚠ 分類を広げて聞き直した寺社 200 件も、⚠ 全部に名前が付いていた）。
⚠ **「その場所について、⚠ 昔との変化・出来事を 1〜2 文で説明できるか」。**

```text
○  旧○○駅 ── 1930 年に開業し、1972 年に廃止されました
○  ○○橋跡 ── この場所には昭和初期まで木造橋が架かっていました
△  ○○神社 ── 神社です
```

⚠ **△ は歴史的ではあるが、⚠ 今昔としての「へえ」が弱い。**

## ⚠ 出典は、⚠ 役割で分ける

| 出典 | 役割 |
|---|---|
| ⚠ **OSM の `historic` / `ruins`** | ⚠ **「昔ここにあったもの」の主力。**⚠ ただし `historic=*` だから出すのではなく、⚠ **説明できるものを選ぶ** |
| ⚠ **地理院 自然災害伝承碑** | ⚠ **「ここで起きたこと」。**⚠ **1 カテゴリとして扱う**（⚠ これだけになると「災害マップ」に見える） |
| ⚠ **Wikidata** | ⚠ **大量のピンを作る用途に使わない。**⚠ **見つけた地点を深掘り・補強する側へ回す** |

```text
OSM  →  旧○○駅を見つける  →  Wikidata  →  開業年 / 廃止年 / 別名 / 関連
```

⚠ **これなら Wikidata の「200 件問題」に巻き込まれない。**

## ⚠ 測った（⚠ 実測 2026-08-29・13 か所）

```bash
node scripts/survey-pins.mjs 0 7
node scripts/survey-pins.mjs 7 13
```

⚠ **数字は書き写さない。**⚠ **走らせて出す**（`CLAUDE.md` §6）。
⚠ **ここに書くのは、⚠ 判断が変わったところだけ。**

⚠ **13 か所の内訳**: 都心 2（渋谷・梅田）／ 埋立 1（浦安）／ 郊外 2（所沢・春日部）／
地方都市 4（高知・松江・弘前・佐賀）／ 城下町 1（松本）／ 宿場 1（関宿）／
農村 1（美瑛）／ 漁村 1（鞆の浦）。

### ⚠ ① 条件 4（年）は、⚠ 単独では使えない

```text
⚠ **1000m で条件 4 を満たすものが 0 件だったのは、⚠ 13 か所中 10 か所。**
⚠ **満たした 3 か所でも、⚠ 最大 2 件。**
```

⚠ **年を必須にすると、⚠ ほぼ全国でピンが出ない。**
⚠ **`OSM で見つけて Wikidata で補強する` は、⚠ 好みではなく **必須**。**

### ⚠ ② 地方のほうが濃い（⚠ 前提が逆だった）

⚠ **条件 3 を満たす件数（1000m）で並べると、⚠ **都心より地方都市のほうが多い**。**
⚠ **城跡・史跡・旧宅が残っているため。**

⚠ **`tmp/tmp.md` の「都市部 300m ／ 普通 500m」は、⚠ **逆かもしれない**。**
⚠ **都心のほうが薄いので、⚠ 都心こそ広く取る必要がある。**

### ⚠ ③ 300m では、⚠ 空振りが多い

```text
⚠ **1 件以上あったのは 300m で 7 か所、⚠ 500m で 8 か所、⚠ 1000m で 11 か所**（⚠ 分母 13）。
```

⚠ **「近い順に 3 件」の上限が効くのは 1000m にしたとき。**
⚠ **300m だと、⚠ 上限より下限のほうが問題になる。**

### ⚠ ④ 1000m でも 0 件の土地がある

⚠ **浦安と春日部は、⚠ 1000m でも 0 件。**⚠ **どちらも埋立・新興住宅地。**
⚠ **伝承碑も 1km では 0**（⚠ 春日部は 2km で 2 件）。

⚠ **「ピンが 0 件のとき、⚠ 面（色）だけで成立させる」は、⚠ 避けて通れない。**
⚠ **`docs/adr/0051` で「ピンは無くても画面は成立する」と決めたのは、⚠ この形で効く。**

### ⚠ 伝承碑は、⚠ 出たときは強いが、⚠ 常設の入口にはならない

⚠ **中身は条件 1〜5 を出典側が最初から満たしている**（⚠ `LoreName` / `LoreYear` /
`DisasterName` / `DisasterInfo`）。⚠ **絞り込みが要らない。**

⚠ **ただし、⚠ 13 か所すべてで半径 1km 以内に 0 件だった**
（⚠ **これは本当に 0。**⚠ タイルは取れている）。⚠ **2km・5km まで広げて、ようやく数件。**

### ⚠ 踏んだこと ── ⚠ **404 を「0 件」と数えていた**

⚠ **自然災害伝承碑は `maxNativeZoom: 7`。**⚠ **z13〜16 は 404 を返す。**
⚠ **最初の測定では `if (!r.ok) continue;` にしていたので、⚠ 全部 0 件に見えた。**

⚠ **取れなかったことと、⚠ 無いことを分ける**（掟 §1）。⚠ **走者は「聞けず」と書くようにした。**

### ⚠ 測れていないもの

```text
⚠ Wikidata で補強したあとの件数（⚠ 条件 4 がどこまで埋まるか）
⚠ 説明文（条件 3 の「1〜2 文」）を、⚠ 実際に作れるか
⚠ 同じ土地の中での散らばり（⚠ 中心から測っただけ。⚠ 歩く経路では違う）
```

## ⚠ 測ったあとに決めたこと（⚠ 2026-08-29。Owner）

```text
⚠ **半径**    現在地から 1km 以内を候補とする
⚠ **上限**    距離の近いものから 最大 3 件 を表示する
⚠ **年代**    ⚠ **表示条件としない**
```

⚠ **年代を条件から外したのは、⚠ 上の実測による**
（⚠ 1000m で条件 4 を満たすものが 0 件だったのは 13 か所中 10 か所）。
⚠ **年は「あれば添える」もので、⚠ 「無ければ出さない」ものではない。**

### ⚠ ピンは、⚠ 画面成立の必須要素にしない

```text
⚠ **1km 以内に候補が存在しない地域が、⚠ 実測で確認された**（⚠ 浦安・春日部）。
⚠ **土地の過去を示す面情報のみでも、⚠ 基本体験が成立する設計とする。**
```

⚠ **`docs/adr/0051` の「ピンは無くても画面は成立する」を、⚠ 実測が裏づけた形。**
⚠ **「ピンが無い＝壊れている」に見えてはいけない**（⚠ 掟 §4-1: ⚠ できないことから書き始めない）。

### ⚠ 密度の低い高品質データの扱い

```text
⚠ **自然災害伝承碑など、⚠ 密度は低いが質が高いものは、
⚠ 存在する場合に「追加の深掘り地点」として扱う。**
```

⚠ **常設の入口にはしない**（⚠ 13 か所すべてで 1km 以内 0 件だった）。
⚠ **これだけを主役にすると「災害マップ」に見える**（⚠ `tmp/tmp2.md`）。

⚠ ⚠ **ピンが 0 件のとき、⚠ 面だけで何を出すか**（⚠ 決めたのは「成立させる」ところまで）
