# 今昔 — 仕様

いま何ができて、何をどこまで言えるか。判断の経緯は `docs/adr/` にある。

---

## 1. 何をするサービスか

場所を指すと、**その土地がどうやってできたか**を国土地理院のデータを実際に読んで判定し、
読んだタイルと画素を根拠として画面に出す。そこから、その場所について調べられることが並ぶ。
Google マップが「いまそこに何があるか」に答えるのに対し、これは「そこがどういう土地なのか」に答える。
**サーバーサイドの処理はゼロ。** 判定はブラウザが実行時に画素を読んで行う。

## 2. 画面と道具

| 道具 | 何に答えるか |
|---|---|
| **昔を見る**（判定） | この場所は何からできた土地か。地形分類の成因と、明治期の低湿地区分。判定文は「この場所は 旧水部 で、いまは 盛土地･埋立地 です」の形 |
| **時間を動かす**（帯） | **その地点に残っている**空中写真を並べる（最大 8 コマ＝7年代＋現在）。押すとその年代が大きくなる。**中間は語らず、写真がそのまま語る**。左端の明治期は空中写真ではないので、大きい見出しで**そう名乗る**。明治期の土地を重ねる操作は**写真の上**にあり（2026-08-16 実測: 320×640 / 375×667 / 1280×800 のいずれも初期画面に入る）、**取れなかったときだけ**そう言葉で出す（正常なときは何も言わない。入っているかはチェックの形が示す）。明治期のコマでは水域が既定で重なり、下地の淡色地図が透ける |
| **この年代で変わったもの** | その写真の範囲に、その時点までにできていたもの／無くなったもの。年と出典URLが 100% 付いている |
| **この場所を深掘り**（`/peel`） | ⚠ **トップからの導線「この場所を深掘り」は、どこでも出る。押せる**（2026-08-18）。取り込んであるのは z14 タイル 87 枚・7 かたまり（長崎・広島・大阪・長野・東京・仙台・札幌）で、そこから外れる場所は**押す前に**「建物ごとの判定は、対応した場所から順に増やしています」と断る。⚠ **できないことから書き始めない**（利用者役 3/3 が「用意できていません」で始まる案を最下位にした）。⚠ **⚠ の記号は使わない**（災害リスクの印と紛らわしい）。⚠ **導線を消さない。**消すと「まだ用意していない」が「この場所には機能そのものが無い」に見える（利用者役 3/3 が「機能があること自体に気づけない」）。⚠ 判定は `public/ground.js` の**1か所**で、トップと `/peel` が同じ答えを使う。⚠ 索引そのものを**取得できなかったときは何も断らない**（取得できなかった ≠ 用意していない）。⚠ `/peel` は建物の状態を 4 つに分ける（対応済み／**未対応**／用意はあるが読めない／索引を読めない）。**未対応を「取得できませんでした」と言わない**。⚠ **進行形（「取得中」「届いていない」）を状態の説明に使わない**（利用者役 3/3 が自分の通信の話と読んだ）。⚠ **「通信の問題ではありません」と言い切る**。⚠ **出ていないものを「表示中」と言わない**（2026-08-18）。地表のタイルが 1.2 秒たっても届かないときは「表示中 現在 / 最新の空中写真」ではなく「**選択中 現在 / いまの街の写真は、まだ出ていません**」。⚠ **理由は断定しない**（落ちたのか、まだ来ていないのかを、この時点では知らない）。⚠ **通信のせいにもしない**。⚠ 猶予 1.2 秒は実測から決めた（通常回線 69ms〜403ms ／ 3G 相当 3.4〜9.5 秒。すぐ切り替えると通常回線で毎段光る）。⚠ 台帳（`#prov`）まで同じことを言う。⚠ 台帳の**文面と語彙**（実測＝読んだ／未取得＝読めなかった／欠落＝本当に無い／未対応＝まだ用意していない／推定）は `public/prov.js` の**1か所**で、DOM も地図も見ないので検査が全組み合わせを回せる（2026-08-18）。いまの街を立体で見て、建物 1 件ずつの足元を明治期の低湿地データで判定する。建物を押すと足元が出る。**答えと分母（「99.6%／533 / 533件の足元を判定」）は、情報パネルを開かなくても画面の上に出る**。年代の段は**帯と同じ判定**（`Konjaku.photos`）で組むので、地点によって段の数が変わる（豊洲 9 段 / 広島 7 段 / 長崎 出島 4 段。2026-08-16 実測）。⚠ **年代を選ぶ道具は、PC とスマホで別**（2026-08-18）。PC は横棒（1 段 77px）、**スマホは横ドラムロール**（指で回して真ん中で選ぶ／全段に名前が出る／全体の位置を点で示す）。横棒は狭い幅で 1 段 27.6px（320）＝指の 63% しか無く、名前も 9 段中 5 段しか出せなかった。⚠ **置き方は PC / スマホそれぞれのブロックが持ち、共有の既定には書かない**（片方を触ってもう片方を壊した実測がある）。⚠ **この画面に場所を探す口は無い**（2026-08-18）。場所を決めるのはトップの責務で、場所を変える導線は「← もどる」→ トップの ✕ の一本だけ。⚠ **サイト全体の情報（作者・プライバシーの詳しい説明・データについて）はこの画面に置かない**（2026-08-18）。全文はトップのフッターが正本。⚠ ただし**プライバシーはゼロにしない**。この画面も判定すると URL に `?q=&ll=` を載せるので、「**載る → 届く → 残らない**」の3段を1文に圧縮して残す。⚠ **スマホでは、根拠（情報パネル）は全画面で読む**（2026-08-18）。地図を中途半端に覆わない — 覆っていたときの実測は、地図に触れる帯が **0px**・＋− の 89% が下敷き・画面の中心（＝調べている地点）を台帳が受け取っていた。⚠ 全画面でも「← もどる」は下敷きにしない（戻る手段は常に見えている場所に）。⚠ PC は左の縦パネルのまま。**変えるのは根拠の見せ方だけ** |
| **土地を知る**（渡す） | 飲食・買い物・病院はGoogle マップへ、ハザードは重ねるハザードマップへ、地図は地理院地図へ。**自前では持たない** |
| **根拠を見る** | 判定ごとに、参照したタイルURL・読んだ画素の rgba・図式コード・取得方法（直読み/計算/推定）・既知の限界を出す |
| **共有する** | 判定を画像カードにして共有する。カードにも「粗いときは粗い」と書く。**選んだ年代（トップ・`/peel`）と、押した建物（`/peel`）は URL に載る**ので、共有先も同じ状態から始まる。年代は**安定したレイヤID**（`era=ort_USA10` など）で載せる（段は地点ごとに間引かれるため、位置では別の年代を指す）。建物は**重心を丸めた鍵**（`b=経度,緯度`）で載せる（配るタイルも Overpass 経路も OSM の id を落としているため）。⚠ `q` と `ll` だけの古い URL もこれまでどおり開ける。⚠ 指定された年代・建物がその土地に無いときは、黙って別の状態にせず**復元できなかったことを画面に出す** |

看板は `/` が「この土地は、昔なんだったのか？ — 今昔」、`/peel` が「この場所を深掘り — いまの街と、明治期の地面」。⚠ 2026-08-18 に「立体で見る」から変えた。トップの導線と同じ名前にそろえる。

## 3. 主張と、その裏づけ

この文書の核心。**ここに無いことは、画面でも言わない。**

| 何を言っているか | 何を根拠にしているか | どこまで言えるか（実測） |
|---|---|---|
| **この場所は ○○ です**（成り立ち） | 地形分類ベクトルタイル（地理院・提供実験）の図式コードを直読み。36区分。成因・災害リスクの文は**国土地理院の記述をそのまま**使い、こちらで書かない | 全国24地点で **24/24（100%）**。詳細版（z16）が無い土地は広域版（z13）に落ち、画面に「（広い区分）」と書く |
| **明治期には ○○ でした** | 明治期の低湿地タイルの画素 rgba を直読み。凡例 `lw_legend.pdf` の**14区分**（うち水域は 2 つ＝干潟・砂浜 / 河川・湖沼・海面。⚠ 重ねる操作は 14 区分すべてを塗るので「水域を重ねる」とは呼ばない。実測 2026-08-17: 浦安は **97% が水域以外**）。参照タイルURLと rgba を画面に出す | 全国24地点で **7/24（29%）**。整備は全国主要都市周辺のみ。近傍 15×15 の一致率が低い土地では言い切らない（大阪 此花 **71.1%**）。凡例に「かなりの位置誤差を含む」とあるため、**街区単位まで** |
| **いまの標高は N m** | `dem5a`（5mメッシュ）を直読み。数値そのもの | 読めた地点だけ。読めなければ何も言わない |
| **この範囲に、その時点までにできていたもの** | Wikidata（CC0）から取り込んだ **2,367件**。年 100%（year 2,349 / decade 11 / century 7）、出典URL **100%**、無くなった年 161件（6.8%） | 「**開業年 ≤ 撮影年なら、撮影時に存在していた**」という含意だけ。**「写っている」とは言わない**。半径1kmの24地点で当たり **23/24（96%）**・件数の中央値 14件。索引に無い区画では何も言わない |
| **残っている空中写真は N 年代** | タイルの実在＋「写っているか」の空白判定（明>250 かつ σ<1 は空白） | 7年代（1936–42 / 1945–50 / 1961–69 / 1974–78 / 1979–83 / 1984–86 / 1987–90）＋現在 |
| **建物の N% が、明治期には水の上** | 建物 1 件ずつ、足元の画素を読む | 豊洲 **99.6%**（足元を判定できた **533 / 533件**）。ただし**場所で極端に振れる**（2026-08-16 実測: お台場 97.1%（103/103）／渋谷 1.5%（4,786/5,017）／広島 1.4%（3,261/3,555）／上野 1.3%（2,728/5,673）／西新宿 1.3%（3,405/4,258））。⚠ **分母は「足元を判定できた件数」**で、建物の全件ではない（上野は 5,673 件のうち 2,728 件しか判定できていない）。範囲は bbox **2.52 km²** で、大きい写真の枠 0.99 km² とは別のもの |
| **建物の高さ** | OSM の `height` / `building:levels`。無ければ種別ごとの既定値 | 豊洲 533件で実測 **42件（7.9%）**。配っている 403,397件では **319,381件（79.17%）が既定値**。画面に常時「推定」と出す |
| **建物の建設年** | OSM の `start_date` | 403,397件中 **1,216件（0.30%）**。豊洲 8/533（1.5%）、長崎 出島 **0/3,914（0.00%）**。→ **建物が消える年代は演出**であり、画面にそう書く |

**言わないと決めているもの**（測って、出せなかった）:

- 「いつ陸になったか／いつ埋め立てられたか」… 空中写真の輝度・分散・彩度では**水陸すら分離しない**（皇居の森 明24.1 が東京湾 明85.7 より暗い）
- 「この土地が大きく変わったのは1960〜70年代です」… 連続する2年代の正規化相互相関では、**変わった土地と対照が重なる**（対照の最大 0.94 が、変わった土地の大半の区間を上回る）
- 確率・確信度… 根拠の無い数値は「検証器の顔をした生成」になる

## 4. データの流れ

```
収集（手元で1回）              配る                    ブラウザ（実行時）
  Wikidata SPARQL  ┐                                    国土地理院タイル
  Overpass (OSM)   ┴→ SQLite ──→ public/data/ ─→ 静的配信 ─→ 画素を直読みして判定
                    coverage      ev/ z12×20束           地形分類・低湿地・DEM・空中写真
                    に「見た範囲」  bl/ z14×64枚
                    を記録         (403,397件 / 生17.0MB
                                    / gz 4,838KB
                                    / 最大1枚 gz 199KB)
```

- **収集と配信を分ける。** 実行時に外へ取りに行くのは、索引に無い土地だけ（Wikidata / Overpass）
- **索引が持つのは「このタイルを見た」という事実**。0件でもタイルを書く
- Worker（`worker.js`）が動くのは `/t` を叩いたときだけ。静的アセットは Worker を起こさない
- Service Worker は自前アセットと、利用者が自分で見た地理院タイル（最大250枚）だけを持つ。版は `SHELL` の中身のハッシュで、手で書かない

## 5. 掟

1. **取れなかったことを「無い」と言わない。** 取得結果は `ok` / `absent`（**404 だけ**＝本当に無い）/ `unreachable`（通信断・8秒のタイムアウト・**403 などの拒否**・5xx）の3状態。`unreachable` のときは断定せず、根拠UIも出さず、再試行を出す。
   ⚠ **403 を `absent` に入れない。** 拒まれたのは「見せてもらえなかった」であって「無い」ではない。
   実測（2026-08-16 / 5地点 × 6経路 = 30本）では、不在の応答は全部 404 で 403 は 0 本だった
2. **索引は「見た範囲」であって「1件でも入った範囲」ではない。** 見ていない区画について何も言わない
3. **出すのは実測値そのものと、その取り方と、既知の限界だけ。** 確率は出さない。断定ではなく引用のときは出典を必ず添え、要約しない
4. **数字は必ず主張範囲の分母で書く。** 別の範囲の数字を持ち込むと、その数字自体が嘘になる
5. **利用状況の計測には、地名も座標も送らない。** Cookie も識別子も使わない。Referer も止めてある。
   ⚠ IP は保存せず、利用者の識別にも使わない（基盤（Cloudflare）が接続元 IP を扱うことは避けられない）
   ⚠ **主語は「計測」。** 調べた場所は **URL に載る**（戻る・共有するため）。その URL を開けば、
   アドレスの一部として**配信元（Cloudflare）には届く**。以前この掟を主語なしで書いていたため、
   画面に「こちらのサーバーには送りません」と**事実でないこと**が出ていた（2026-08-15 に実測して修正）
6. **同じ問いに答える実装を2つ持たない。** やむを得ず持つときは、機械で突き合わせる
7. **押しても何も起きない導線を置かない**

これらは人の目に頼らず、`npm run check`（静的 ****）と `npm run render`（実描画 ****）で見る
（2026-08-18 に手元で実測。`✓` の数と、実描画のケース数）。
`render` は通信を落とした状態と、**403（拒否）を返された状態**で「整備対象外」「データが無い」と
断定しないことまで確かめる。
⚠ 実描画は 2 群に分かれている。`--group=core`（**109件**・外へ検索に出ない）と
`--group=search`（**9件**・地理院の住所検索が返らないと成立しない）。
CI は両方を回す。**core が落ちたら外部のせいにできない**＝こちらの不具合。
search 群だけ 1 回やり直す（やり直した回数は必ず出力する）。
実測（2026-08-17）: 住所検索の応答は速いとき 0.4 秒・遅いとき **8.2 秒**。
アプリは 8 秒で中断する（上の掟1）ので、遅い回は**アプリが正しく中断したのに検査だけが落ちる**。
検索の並びは `npm run check-search`（**42語**）で見る。

## 6. 数えているもの（`/t`）

固定文字列だけを受け取り、列挙にないものは黙って捨てる。D1 に日ごとの件数を1行書く。

| 種類 | 中身 |
|---|---|
| イベント | `judged.ok` / `judged.coarse` / `judged.none` / `judged.fail` / `shared` / `saved` / `era.moved`（1つの場所につき1回）/ `open.peel` / `open.speak` |
| 依存の生死 | `health:<all\|landform\|meiji\|elevation\|photos\|search\|events>:<ok\|fail>` |
| 流入の出所 | `from:<zenn\|x\|note\|qiita\|github\|hatena>` |

- **唯一の指標は共有率**（`shared` / `judged.*`）。判定が 100 件たまるまでは読まない
- Origin が自分のオリジンでないものは落とす（204 を返し、理由は教えない）
- 本文は **48 バイトまで**。`Content-Length` を見て、**読む前に**落とす（無いものも落とす）。
  受け付ける本文は **29 種**で、最長は `health:elevation:fail` の **21 文字**（2026-08-15 実測）
- 1人あたりの `/t` は実測で **最大3回**（判定だけ 2／年代まで動かして 3／`/peel` は 1）。
  無料枠（Worker 10万req/日・D1 書き込み10万行/日）から、**1日 33,333 人まで無料**

## 7. 外部への依存と、落ちたときどうなるか

| 依存 | 何に使うか | 落ちたときどうなるか |
|---|---|---|
| 国土地理院タイル（`cyberjapandata`） | 空中写真・明治期の低湿地・DEM | 判定できたものだけ出す。読めなかった項目は「読み込めていません」と再試行。**「無い」とは書かない** |
| 地理院地図 ベクトルタイル提供実験（地形分類） | 主題そのものの判定 | 同上。黙って別の答えに差し替えない |
| 地理院 住所検索（`msearch`） | 場所を探す | 「見つかりませんでした」と書かず、取れなかったことを言う。⚠ **公開APIではない**（主に地理院地図からの利用を想定した機能）ため、仕様変更・停止がありうる |
| Wikidata SPARQL | 索引に無い土地の事物 | 「この範囲に何があるかは分かっていません」と言い、再試行を出す |
| Overpass（公開インスタンス） | 索引に無い土地の建物 | 実測で 406 / 429 / 504 / タイムアウトが常態。取れなかったと表示し、**水域と空中写真だけで画面が成立する** |
| 自前 `/t`（Worker + D1） | 計測 | 数えられなかっただけ。画面の動きは何も変わらない |

⚠ **段に出すのは、その地点に残っている年代だけ。** 固定 8 段を出していたときは、
その土地に存在しない年代のタイルを地図が引いていた。全年代へ動かしたときの実測
（2026-08-16 / 1280×800 / Service Worker 無効 / 各段を順に選択）:
