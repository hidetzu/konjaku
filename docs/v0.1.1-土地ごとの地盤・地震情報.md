## 3. J-SHIS API の利用

J-SHIS には公式の Web API があり、緯度経度を指定して表層地盤や地震ハザード情報を取得できる。

Webページ等から地震ハザード情報・表層地盤データを表示する用途も想定されている。

そのため、v0.1.1 の第一候補は **実行時にJ-SHIS APIを利用する方式**とする。

```text
/deep
  ↓
必要になった場合のみ
  ↓
J-SHIS API
  ↓
地点に必要な情報だけ表示
```

### 基本方針

- トップ画面からは呼ばない
- `/deep` でのみ取得する
- J-SHIS のレスポンスそのものを配布しない
- `public/data/` に全国分を取り込まない
- API失敗時でも `/deep` の他の情報は正常に表示する
- APIのレート制限・障害を考慮する

これにより、今昔全体を Runtime API 依存へ変更するのではなく、

**「deep の追加資料だけ外部依存」**

という境界にできる。

---

## 4. 利用規約について

J-SHIS の利用規約では、地震動予測地図データをそのまま複製して第三者へ頒布することは禁止されている。

一方で、編集・加工した成果物については利用可能とされている。

どこまでが「加工」に該当するのかは今昔側で判断せず、必要なら防災科研へ確認する。

特に確認しておきたいのは以下。

- J-SHIS Web API をWebサービスから呼ぶこと
- 取得した数値の一部を地点情報として表示すること
- APIレスポンスそのものは再配布しないこと
- Worker等を経由すること
- 一時的なキャッシュを行うこと
- 将来的にサービス形態が変わった場合の扱い

問い合わせる場合は、具体的な利用方法を示して確認する。

例：

> J-SHIS Web APIをWebサービスから呼び出し、取得した微地形区分・地盤増幅率・今後30年間の震度超過確率の一部を、出典を明記して地点ごとの情報として表示したいと考えています。APIレスポンスそのものの再配布は行いません。必要に応じてサーバー側で一時的なキャッシュを行う可能性があります。この利用方法が利用規約上問題ないか確認したいです。

## 5. `/deep` での表示方針

情報同士を因果関係でつながず、事実として並べる。

### 表示例

```text
この土地の地盤と地震

微地形
埋立地

地盤増幅率
2.26

今後30年間に

震度5弱以上    100%
震度5強以上     98.6%
震度6弱以上     70.6%
震度6強以上     20.3%

出典
防災科学技術研究所 J-SHIS
```

今昔が既に持っている情報とは、例えば以下の順番で並ぶ。

```text
この土地は昔なんだった？
        ↓
土地の成り立ち
        ↓
地形・標高
        ↓
地盤・地震
        ↓
周辺に残る災害の記録
        ↓
昔の写真・資料
```

これは画面上の情報構造であり、

**「土地の成り立ちが原因で地震リスクがこうなった」**

という因果を示す矢印ではない。

## 6. 表示してよいこと

公的データから直接取得できる以下は表示候補とする。

- 微地形区分

- 地盤増幅率
- 今後30年間の各震度以上の超過確率

- 出典
- 近隣の自然災害伝承碑

## 7. 表示しないこと

以下は今昔側で断定しない。

- 「埋立地だから危険」
- 「昔水だったから揺れやすい」
- 「この地域は地震が多い」
- 「過去○年間でこの地点は○回揺れた」
- 「震度6弱以上1.2%なので安全」
- 避難や居住についての推奨
- 防災判断そのもの

特に確率が低い地点についても、「安全」と読ませない。

J-SHIS の数値はあくまで地震ハザードに関する公的データであり、個別の防災判断を代替するものではない。
