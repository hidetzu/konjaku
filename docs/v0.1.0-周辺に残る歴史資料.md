# 今昔 v0.1.0 — 周辺の歴史情報として自然災害伝承碑を扱う設計

## 目的

今昔の主役はあくまで、

> この土地は、昔なんだったのか？

への回答とする。

そのうえで、現在地の周辺に残る「歴史の痕跡」を補助情報として提示し、
スマホでは軽く気づかせ、PC / Deep では背景まで深く読めるようにする。

v0.1.0 では、その最初のデータとして **国土地理院「自然災害伝承碑」** を扱う。

---

## 基本方針

自然災害伝承碑は「この場所で災害が起きた」という直接証拠として扱わない。

碑があることで言えるのは、

> この場所の近くに、その災害を伝える碑が残っている

ということ。

### 表示してよい

> 650m先に、1967年の洪水を伝える碑があります。

### 表示しない

> 1967年、この場所は洪水に遭いました。

碑の位置と被災地点は一致するとは限らないため、
今昔の「言えることだけを言う」原則を守る。

---

# スマホ版

## 役割

散歩中に立ち止まって詳しく読む画面にはしない。

「この土地は昔なんだったのか？」への回答を読んだあとに、
周辺にも少し気になる歴史があることだけ伝える。

## 表示例

```text
この土地は、昔なんだったのか？
────────────────
（この場所への回答）

ちなみに、この近くには

🌊 650m先
1967年の洪水を伝える碑があります。

                         深く見る →
```

## スマホで出す情報

原則として以下だけ。

- 災害種別
- 災害年または年代
- 碑までの距離
- 1行程度の説明
- Deep への導線

詳細な伝承文、出典説明、複数候補の一覧などは出さない。

## 表示件数

周辺に候補が複数あっても、原則 **1件だけ** 出す。

スマホ版を「周辺スポット検索」にしない。

候補例:

```text
120m 神社
300m 城跡
650m 災害伝承碑
800m 廃駅
```

これらを全部並べるのではなく、
その場所との関連性や歴史的な面白さが高いものを1件選ぶ。

---

# PC / Deep 版

## 役割

スマホで気づいた情報について、

- 何があったのか
- いつのことか
- 何を根拠に言っているのか
- その痕跡が今どこに残っているのか

を深く読めるようにする。

## 表示イメージ

```text
この近くに残る災害の記録

羽越豪雨
1967年8月
洪水

現在地から 650m
「○○水害記念碑」

────────────────

何があった？

1967年8月、この地域では羽越豪雨による
洪水被害が発生しました。

（伝承内容を元にした説明）

────────────────

なぜ分かる？

この場所から650m先に、
この災害を伝える「○○水害記念碑」が
現在も残っています。

建立：1970年

[地図で碑の位置を見る]

────────────────

出典

国土地理院「自然災害伝承碑」
```

## Deep の情報構造

```text
この場所について
│
├─ この土地は昔なんだった？
├─ 地形と成り立ち
├─ 時代ごとの変化
└─ この近くに残る記録
      ├─ 🌊 災害
      ├─ 🏯 城・城跡
      ├─ ⛩ 神社
      ├─ 🚉 廃駅
      └─ その他の歴史的痕跡
```

「この場所の答え」を無理に長文化するのではなく、
周辺に残っている証拠・記録を別レイヤーとして広げる。

# データソース

v0.1.0 では以下を使用する。

## 国土地理院「自然災害伝承碑」

取得候補:

- 碑名
- 所在地
- 緯度・経度
- 災害名
- 災害種別
- 建立年
- 伝承内容
- 出典情報

データは事前取得し、今昔側で正規化する。

Runtime から毎回外部APIへ問い合わせるのではなく、
既存方針と同様に、

```text
Source
  ↓
事前取得
  ↓
SQLite / 正規化
  ↓
静的JSON
  ↓
ブラウザで現在地周辺を検索
```

を基本とする。

# データモデル案

```json
{
  "id": "gsi:xxxxx",
  "type": "disaster_monument",

  "name": "○○水害記念碑",

  "disaster": {
    "name": "羽越豪雨",
    "type": "洪水",
    "dateText": "1967年8月"
  },

  "monument": {
    "establishedYear": 1970,
    "lat": 37.0,
    "lon": 139.0
  },

  "description": "...",

  "source": {
    "name": "国土地理院 自然災害伝承碑"
  }
}
```

## 年代は分離する

特に以下を混同しない。

```text
disaster.date
```

= 災害が発生した年代

```text
monument.establishedYear
```

= 碑が建立された年代

「建立 1970年」を「1970年に洪水があった」のように扱わない。

# Nearby Historical Context

自然災害伝承碑だけの専用機能にはせず、
将来的には「周辺に残る歴史情報」の共通モデルにする。

```text
Nearby Historical Context
│
├─ disaster_monument
├─ castle
├─ shrine
├─ abandoned_station
└─ historical_facility
```

候補データ源:

| 種類 | 主なデータ源 |
|---|---|
| 自然災害伝承碑 | 国土地理院 |
| 城・城跡 | OSM / Wikidata |
| 神社 | OSM / Wikidata |
| 廃駅 | OSM / Wikidata / その他公開データ |
| その他 | 公的オープンデータ等 |

v0.1.0 では、まず自然災害伝承碑だけでこの型を作る。

# 周辺情報の選択

初期実装では、現在地から一定距離以内を対象とする。

例:

```text
半径 1km
```

候補の評価軸:

1. 距離
2. 年代が取得できるか
3. 説明できる情報量
4. 災害種別
5. 同種情報の重複
6. 「ちなみに」として興味を持てるか

単純な最近傍だけに固定する必要はないが、
v0.1.0 では複雑なランキングを作り込まない。

# 表現上のルール

## 原則

**取れなかったことを「無い」と言わない。**

**碑があることと、その地点が被災したことを混同しない。**

**推定を事実のように表示しない。**

## 推奨表現

> この近くには、○○災害を伝える碑があります。

> 現在地から約650m先にあります。

> この碑には、○○年の洪水被害について伝えられています。

## 避ける表現

> この場所は○○年に洪水になりました。

> この地域全体が○m浸水しました。

別途、浸水推定図など地点を裏付けるデータが存在する場合のみ、
そのデータの意味を明示して扱う。

# v0.1.0 の実装範囲

まず以下までを完成させる。

1. 自然災害伝承碑データの取得
2. 今昔用データへの正規化

5. Deep画面で詳細表示
6. 出典を明示
7. 「碑の位置 ≠ 被災地点」を守る表示ルールをテストする

以下は v0.1.0 では必須にしない。

- 城・神社の統合
- 高度なランキング
- 全周辺情報一覧
- 過去の浸水範囲との統合
- 気象庁降水量との統合
- 災害タイムラインの作り込み

# 一言でまとめると

> **スマホでは「この近くにも歴史が残っている」と気づかせ、Deepでは「何が起き、何が根拠として残っているのか」を読む。**

自然災害伝承碑を、その最初の Nearby Historical Context として実装する。
