# Visual Decision

⚠ **これは「判断してください」を「見て決められる状態」に変える Skill。**
⚠ **Owner を外すためではない。**⚠ **Owner の判断コストを下げるため。**

⚠ **画面の見方は [`ui-ux-review`](../ui-ux-review/SKILL.md) が正本。**⚠ ここには書かない。
⚠ **検査の回し方は [`verify`](../verify/SKILL.md)。**⚠ **これは検査ではない。**⚠ **落ちない。**

---

## 0. ⚠ なぜ要るか（⚠ 実測 2026-08-28）

```
Owner 判断に触れている Issue        70 件 / 全 95 件
  うち 見え方を決めるもの           45 件
    判断材料が px などの数字だけ    34 件（76%）
    案が 2 つ以上                    8 件（18%）
    文章だけ                         2 件（4%）
    ⚠ 画像があった                   1 件（2%）
```

⚠ **見え方を決める 45 件のうち、⚠ 絵があったのは 1 件だった。**

⚠ **同じ症状が分かれた例**: ⚠ 「重ねる」が初期画面から出る
（hidetzu/konjaku#176 → hidetzu/konjaku#278 → hidetzu/konjaku#279 → hidetzu/konjaku#280 → hidetzu/konjaku#281）。
⚠ **hidetzu/konjaku#176 を閉じた翌日に、⚠ 別の条件（横向き）で hidetzu/konjaku#281 が出た。**
⚠ **hidetzu/konjaku#176 は 1 条件の px で判断していた。**⚠ **他の条件は視野に入っていなかった。**

⚠ **これは事実。**⚠ **「絵があれば防げた」は推測**（⚠ そう書かない）。

---

## 1. ⚠ これは見て決める問題か

⚠ **先に分ける。**⚠ **文章で足りるものに絵を作らない**（⚠ 時間と Owner の目を使う）。

| 見て決める | 文章で決める |
|---|---|
| ⚠ **色・コントラスト・色み** | 仕様（何が言えるか） |
| ⚠ **余白・文字サイズ・行の高さ** | データの意味・分類 |
| ⚠ **画面に収まるか・はみ出すか** | 取得先を増やすか |
| ⚠ **並び順・畳むか開くか** | 検査の置き方 |
| ⚠ **要素を残すか消すか** | ファイルの分け方 |
| ⚠ **案が 2 つ以上あって、実測では決まらないとき** | 数えれば決まること |

- MUST: ⚠ **語だけで決めない。**⚠ **何を決めるのかで決める**（⚠ 「色」と書いてあっても、
  ⚠ 「色を 1 か所に集めるか」は作りの話）。
- MUST NOT: ⚠ **見て決める問題を、⚠ px だけで聞かない。**

---

## 2. 出すもの（⚠ v1 はこれで足りる）

```
いま        ⚠ 変える前
案          ⚠ 変えたあと（⚠ 1 つ）／ 案 A・案 B・案 C（⚠ 選ぶとき）
短い説明    ⚠ 何が変わったか。⚠ 1〜2 行
推す案と理由 ⚠ こちらの見立て。⚠ 「決めてください」で終わらせない
```

- MUST: ⚠ **同じ切り取り・同じ条件で撮る**（⚠ 幅・色み・場所・文字サイズ）。
- MUST: ⚠ **条件を書く**（⚠ どの幅で、⚠ どの色みで、⚠ どこを開いて撮ったか）。
- MUST: ⚠ **色みは両方撮る**（⚠ 片方だけ見て決めると、⚠ もう片方で割れる。
  ⚠ hidetzu/konjaku#282 で実際に起きた）。
- SHOULD: ⚠ **推す案には、⚠ 何を失うかも書く**（⚠ 良いことだけ並べない）。

---

## 3. 撮り方

```bash
node scripts/visual-decision.mjs --url="/?ll=…&q=…" --sel="#ovRow" --label=いま
node scripts/visual-decision.mjs --url="/?ll=…&q=…" --sel="#ovRow" --label=案A
node scripts/visual-decision.mjs --compose --title="…" --cond="…" --note="…"
```

| 口 | 何をするか |
|---|---|
| `--sel` | ⚠ **撮る相手。**⚠ **`fullPage` で撮ると版面が組み直され、⚠ 座標がずれる**（⚠ 実際に踏んだ） |
| `--fold` | ⚠ **初期画面ぜんぶを撮り、⚠ 相手がその中に在るかを言う**（⚠ 「画面外へ出た」はこれでないと見えない） |
| `--size=667x375` | ⚠ 一覧に無い幅（⚠ 横向きなど） |
| `--widths=all` | ⚠ `ui-ux-review` §0 の 4 幅 |
| `--theme` | ⚠ 既定は明るい・暗いの両方 |
| `--wait` | ⚠ **器ではなく、⚠ 結果の字が出るまで待つ**（`CLAUDE.md` §9） |

⚠ **出力は `tmp/`**（⚠ 追跡しない）。⚠ **`compare.html` は Artifact にそのまま載る形**で出る。

---

## 4. 渡し方

```
画像そのもの   ⚠ SendUserFile（⚠ 会話に出る。⚠ いちばん速い）
並べた 1 枚    ⚠ compare.html を Artifact にする（⚠ 共有したいとき）
```

- MUST NOT: ⚠ **公開リポジトリの Issue / PR 本文に、⚠ 作業環境の絶対パスや
  セッションの URL を書かない**（`CLAUDE.md` §8-1）。
- SHOULD: ⚠ **Issue / PR には数字と字を書き、⚠ 絵は会話で渡す**（⚠ 画像は repo に足さない）。

---

## 5. 聞き方

⚠ **`AskUserQuestion` を使う。**⚠ **本文に混ぜない**（`CLAUDE.md` §7-1）。

```
⚠ 問題      何が起きているか。⚠ 1 行
⚠ いま      画像
⚠ 案        画像（⚠ 1 つ、または A / B / C）
⚠ 推す案    どれか。⚠ なぜか。⚠ 何を失うか
⚠ 選択肢    A ／ B ／ 現状維持  程度で答えられる形
```

- MUST: ⚠ **推す案を必ず書く。**⚠ **「どちらがよいですか」だけで投げない。**
- MUST: ⚠ **迷ったら利用者役にも聞く**（[`ui-ux-review`](../ui-ux-review/SKILL.md) §6）。
  ⚠ **実在の利用者ではないと明記する。**
- MUST: ⚠ **静止画で聞くときは、⚠ 押せるものは押せると伝える**
  （⚠ hidetzu/konjaku#142 で、⚠ 押せることが伝わらず「読む理由がない」と読まれた）。

---

## 6. ⚠ 決めたあと

- MUST: ⚠ **判断とその理由を、⚠ PR 本文かコメントに残す**（⚠ 「Owner が絵で確かめた」まで書く）。
- MUST: ⚠ **同じ条件で撮り直して、⚠ 直ったことを見せる。**
- MUST NOT: ⚠ **絵を根拠に「検査した」と言わない。**⚠ **絵は判断材料。**⚠ **主張を守るのは検査。**

---

## 7. やらないこと（⚠ v1）

```
画像の自動比較（diff）        ⚠ 人が見る。⚠ 差分の自動判定はしない
すべての Issue へ強制         ⚠ 見て決める問題だけ
Owner 判断の自動化            ⚠ 決めるのは Owner
画像を repo に置く            ⚠ tmp/ に置いて会話で渡す
```
