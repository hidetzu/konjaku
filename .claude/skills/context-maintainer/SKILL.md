# 記録のずれを見つけ、整理案を出す

1. 最近クローズされたIssue / Merge済PRを確認
2. SPECと現在実装の乖離を確認
3. ADRのSuperseded関係を確認
4. CLAUDE.mdの
   - 重複
   - 矛盾
   - 既に不要な指示
   - Skillへ移せる詳細
     を抽出
5. 修正案を作る
6. 人間に「削除・統合してよいか」を提示

---

## ⚠ やらないこと

- ⚠ **自分で消さない・統合しない。**⚠ **6 で止まる**
- ⚠ **記録の実測値を、そのまま引き写さない。**⚠ **書かれた日の値**であって、いまの値ではない
- ⚠ **「たぶん終わっている」を「終わった」に書き換えない**

## ⚠ 測ってから言う

```bash
git log --oneline -1
gh pr list --state merged --limit 30
gh issue list --state open
npm run check 2>&1 | tail -2
```

⚠ **印象で「多い」と言わない。**数える。

## 返す形

```
いまの main:   <commit> <題>
検査:          静的 N 件 ／ 実描画 N 件

ずれていたもの:
  <記録が言っていたこと → いまの実測>

⚠ 消す・統合する案:
  <何を、なぜ。⚠ 消したら戻らないものは、そう書く>

⚠ 人の判断が要るもの:
  <一覧>
```
