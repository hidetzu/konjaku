# 記録のずれを見つけ、整理案を出す

1. 最近クローズされたIssue / Merge済PRを確認
2. SPECと現在実装の乖離を確認
3. ADRのSuperseded関係を確認
4. CLAUDE.mdの
   - 重複
   - 矛盾
   - 既に不要な指示
   - Skillへ移せる詳細
     を抽出
5. ⚠ **決まったことが、消える場所にしか無いか**を確認（下の節）
6. 修正案を作る
7. 人間に「削除・統合してよいか」を提示

---

## ⚠ やらないこと

- ⚠ **自分で消さない・統合しない。**⚠ **7 で止まる**
- ⚠ **記録の実測値を、そのまま引き写さない。**⚠ **書かれた日の値**であって、いまの値ではない
- ⚠ **「たぶん終わっている」を「終わった」に書き換えない**

## ⚠ 決まったことが、消える場所にしか無いことがある

⚠ **`tmp/` は追跡されていない**（`.gitignore`）。⚠ **Owner の判断がそこにしか無いと、消える。**
⚠ **記録が古いことより、記録がそもそも残らないことのほうが気づきにくい。**
ずれを見つける Skill が、⚠ **「まだ書かれていない」も見る。**

実例（2026-08-21）: `/peel` の情報の置き方について Owner が 7 つ決めた
（HUD に残すもの／「データ・根拠」は新設しない／分母は必ず維持する ほか）。
⚠ **出どころは追跡されていないメモ 1 つだけ**だった。
いまは hidetzu/konjaku#151・hidetzu/konjaku#152・hidetzu/konjaku#153 の
`Owner Decisions` に写してある。

| 拾うもの | ⚠ どう拾うか |
|---|---|
| ⚠ **消える場所にしかない決定** | `git check-ignore -v tmp/*.md` で、追跡されていないことを確かめてから中を読む |
| Issue にしかない決定 | `gh issue list --state all --search "Owner Decisions"` |
| ⚠ **実装が終わったのに、経緯が残っていないもの** | 閉じた Issue の `Owner Decisions` と `docs/adr/` を突き合わせる |

⚠ **ADR を勝手に書かない。**「⚠ これは ADR に落ちていない」と**人に出すところまで**。
⚠ **決まっただけのものを ADR にしない。**実装が終わるまでは Issue が持つ
（⚠ ADR は**判断の経緯**であって、予定表ではない）。
⚠ **番号は名前つきで書く**（`<owner>/<repo>#<番号>`）。⚠ 裸の番号は、移行後に別のものを指す。

```bash
gh issue list --state open

```
