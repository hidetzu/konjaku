# Verify

⚠ **この Skill は検査を作らない。**⚠ **すでにある検査の回し方を決めるだけ。**

検査そのものは `test/check.mjs` ／ `test/render.mjs` ／ `test/search-check.mjs` に
あり、⚠ **そちらが正**。ここに検査の中身を書き写さない（掟: 同じ問いに答える実装を2つ持たない）。

```
Worker
  ↓
Verify   ← ここ
  ├─ FAIL          → Worker へ戻す
  ├─ NOT-VERIFIED  → 何が見られていないかを言う。⚠ 緑と呼ばない
  └─ PASS          → Review へ
```

---

## 1. いまある入口（⚠ ここが全部）

⚠ **実測（2026-08-19・手元）。**⚠ **数字はそれぞれ測った日のもの。**⚠ いまの値ではない。

| 入口 | 何を見るか | 外へ出るか | 実測 |
|---|---|---|---|
| `npm run check` | 静的。ファイルを読んで分かること | ⚠ **出ない** | **3 秒** |
| `npm run render` | 実描画。ブラウザで開いて、押して、測る | 地理院のタイル | 数分 |
| `npm run check-search` | 検索の並び 42 語 | ⚠ **地理院を 42 回** | 数分（1.5 秒あけて 1 語ずつ） |

**部分だけ回す口**（⚠ どれも既にある。足していない）

| 口 | 何が起きるか | 実測 |
|---|---|---|
| `npm run render -- --only=<部分一致>` | 名前が一致するケースだけ | **9 秒**（3 件のとき） |
| `npm run render -- --suite=peel` | ⚠ **`/peel` のケースだけ**（2026-08-22 に割った） | — |
| `npm run render -- --suite=top` | ⚠ **トップのケースだけ** | — |
| `npm run render -- --group=core` | 外へ検索に出ない群だけ | — |
| `npm run render -- --group=search` | 住所検索に寄りかかる群だけ | — |
| `npm run render -- --count` | ⚠ **走らせずに件数だけ**（`--suite=` / `--group=` と混ぜられる） | — |
| `node test/check.mjs --links-new=<ref>` | そのブランチで足した URL だけ叩く | — |
| `node test/check.mjs --links` | 外部リンク全部 | — |
| `node test/search-check.mjs --offline` | ⚠ **キャッシュで回す**（`.artifacts/search-cache`・42 語ぶん） | — |
| `node test/render-scope.mjs origin/main...HEAD` | ⚠ **CI が何を回すかを、手元で同じ判定で見る** | — |

⚠ **`npm run render --group=core` と書くと npm が引数を飲み、黙って全群が走る。**
⚠ **`--` を挟む。**⚠ 走った suite と群は出力の 1 行目が名乗るので、そこを読む。
⚠ **落ちないので気づかない**（数字が多いだけ）。

### ⚠ 手元で回すときは、⚠ 自分が立てたサーバを測っているか

⚠ **別のワークツリーが同じポートを掴んでいると、⚠ 相手の画面を黙って測る**
（2026-08-22 に 2 回踏んだ。⚠ **自分の変更のせいだと 4 件を誤診した**）。

```
KONJAKU_RENDER_PORT=8216 npm run render
```

⚠ **既定は 8099。**⚠ **走者は測る前に、配られている `sw.js` の VERSION と手元の中身を
突き合わせる**ので、⚠ **食い違えばそこで止まる**（黙って測り続けない）。

### ⚠ 件数は、走者が名乗る（⚠ **どこにも書かない**）

⚠ **`docs/SPEC.md` に件数を書かない**（2026-08-22。`CLAUDE.md` §9）。
⚠ **書き戻すと静的検査が落とす。**⚠ **突き合わせる相手はもう無い。**

```
静的検査は N 件を数えた
N 件すべて描画できた
0 語（N 語すべて判定できた）
```

⚠ **報告には、⚠ そのとき名乗った数をそのまま写す**（§7 の `Ran:`）。
⚠ **ここに実際の数を書かない。**⚠ **書いた瞬間から古くなる**（⚠ **それが元の穴だった**）。

⚠ **`npm run check` だけでは足りない。**
⚠ **実際に不具合を捕まえているのは実描画のほうが多い。**
静的検査は DOM 構造の間違いを見つけられない
（⚠ 「判定の結果を畳んだ `<details>` に入れた」を見つけたのは**実描画 9 件の失敗**だった）。

## 2. Inner Loop（直している間）

⚠ **速い順に回す。落ちたら、そこで戻る。**

```
1. npm run check                        3 秒・外へ出ない
2. npm run render -- --only=<触った所>   9 秒（3 件のとき）
```

⚠ **ここで緑でも「通った」と言わない。**⚠ 回していないケースがある。
`--only` のときは `render.mjs` 自身が「⚠ 全 N 件のうち --only で選んだぶんだけ」と名乗る。

⚠ **`--offline` を Inner Loop で使ってよい。**ただし ⚠ **キャッシュは撮った日の応答**で、
相手が変われば古くなる。⚠ **これで検索の並びを「確認済み」と言わない。**

⚠ **部品を触ったなら、⚠ 部品だけで開くケースがいちばん速い。**

```
npm run render -- --only=コンポーネント単体
```

⚠ **実測（2026-08-22・`main` = `ffe53ca`）**: 1 件 **95ms** ／ 引いた URL **5 本** ／ 地図 **0 本**
（⚠ 地図を立ち上げるケースは 1 件 10〜30 秒）。
⚠ **速いだけではない。**⚠ **実物のページでは動いてしまう暗黙の依存は、⚠ これでしか出ない**
（[`components.md`](../../rules/components.md)）。

## 3. Final Gate（PR を出す前）

⚠ **3 つとも回す。**`npm run check` だけでは足りない。

```
npm run check
npm run render
npm run check-search
```

⚠ **実際に不具合を捕まえているのは実描画のほうが多い。**
静的検査は DOM 構造の間違いを見つけられない。

⚠ **件数は各走者が自分で名乗る。**⚠ **直す場所は無い**（§1）。
⚠ **名乗った数を、⚠ そのまま報告へ写す。**⚠ 「通った」と書かない。

## 4. ⚠ 落ちたときに、まず切り分ける

⚠ **自分の変更を疑う前に、落ちた場所を見る。**

| 落ち方 | ⚠ こちらの不具合か |
|---|---|
| `npm run check` が落ちた | ⚠ **こちらの不具合。**外へ出ていない |
| `--group=core` が落ちた | ⚠ **こちらの不具合。**外部のせいにできない |
| `--group=search` が落ちた | ⚠ **外部かもしれない。**住所検索は速いとき 0.4 秒・遅いとき 8.2 秒。⚠ アプリは 8 秒で中断するので、**アプリが正しく中断したのに検査だけが落ちる**回がある |
| 「応答を取得できませんでした」「判定を保留します」 | ⚠ **並びが悪いのではなく取得失敗。**外部 |
| CI がブラウザの用意（`playwright install`）で固まった | ⚠ **こちらの変更とは無関係。**テストは 1 秒も走っていない。上限つきで 1 回取り直す作りが入っている |
| 外部リンク（全部）が落ちた | ⚠ 相手先の一時的な不調。`main` と週次だけで、⚠ **止めない作りになっている** |

⚠ **自分の検査が間違っている場合もある。**そのときは検査を直し、
⚠ **なぜ間違っていたかをコメントに残す**（実例: 検査が自分の説明コメントを拾った・3 回）。

---

### ⚠ offline にすれば fork でも検証できるが

⚠ **タイル画像を fixture にすると「画素を実際に読んで判定する」という主張が崩れる。**
⚠ **そこは慎重に決める。**

## 5. ⚠ 検査を足したときにやること

⚠ **直した不具合は、検査として残す。**同じことがもう一度起きたら止まる形にする。


⚠ **足しただけでは終わらない。**

```
1. わざと壊して、本当に落ちることを確かめる
2. ⚠ 落ちた理由の文言が、狙った主張になっているかまで読む
3. 新しいファイルを足したなら、⚠ git add してから回す
```

⚠ **`git ls-files` を見る検査は、追跡されていないファイルを一生見ない。**
`git add` の前に回して「通った」と思う事故がある。

⚠ **「消した」検査だけを置かない。**対にする。
例: 「動きを消した」だけだと、⚠ **全部消してしまっても緑**になる。
消していない側（既定）を見る検査を対で置く。

## 6. ⚠ CI が緑でも、見られていないものがある

⚠ **fork からの PR では、外へ出る検査が走らない。**
見知らぬ人の PR から地理院へ通信を飛ばさないため。

| 検査 | 自分のブランチ | ⚠ fork からの PR |
|---|---|---|
| 静的検査 | 走る | 走る |
| 外部リンク（足した分） | 走る | ⚠ **走らない** |
| 検索の並び | 走る | ⚠ **走らない** |
| 実描画 | 走る | ⚠ **走らない** |

⚠ **fork の PR が緑でも、実描画で検証されていない。**取り込んでから `main` で見る。

### ⚠ 変更によっては、実描画が走らない／一部しか走らない

⚠ **画面に届かない変更で、⚠ 数分の待ちとブラウザの用意の揺れ**
（取り直し 3 回でも 6.4% 落ちる）⚠ **を引き受けない。**

⚠ **判定は [`test/render-scope.mjs`](../../../test/render-scope.mjs) が 1 か所で持つ。**
⚠ **ここに書き写さない**（⚠ **2 か所に書くと片方だけ古くなる**。⚠ **実際にここが古くなった**）。
⚠ **手元で、⚠ CI と同じ判定を見られる。**

```
node test/render-scope.mjs origin/main...HEAD
```

⚠ **出るのは「回すもの」だけ**（`peel core` / `top core` / `top search`）。
⚠ **何も出なければ、⚠ 実描画は回らない。**

⚠ **いちばん大事な規則は、⚠ `render-scope.mjs` の冒頭にある**:
⚠ **分からなければ全部に倒す。**⚠ **絞り込みで検査漏れを作らない。**

⚠ **`main` へ入るときは、⚠ PR で絞ったぶんを取り戻して全部回る。**

⚠ **実測（2026-08-21・`.claude/` の 1 ファイルだけを変えた PR）**: 実描画ジョブは **7 秒**で
緑になり、⚠ **テストは 1 件も走っていない**（ブラウザも入れていない。判定より後の段は
7 つとも `skipped`）。ログにはこう出る。

```
変更 1 ファイル:
  .claude/skills/verify/SKILL.md
⚠ この実行では実描画を回していない（画面にも実行環境にも届かない変更だけ）
```

⚠ **実測（2026-08-22・CI・全部回った PR）**: 実描画 **8分50秒** ／ 静的の並び **1分32秒**。

⚠ **判断は「実描画」ジョブの中でしている**（`paths-ignore` ではない）。
⚠ あれは Workflow ごと走らせないので、必須チェックにしていると**報告が来ないまま待ちになる**。
⚠ **緑で返るが、⚠ ログに「回していない」「N 件だけ回す」と出る。**そこを読む。

### ⚠ 外部リンクは 2 段になっている

| いつ | 何を叩くか | 落ちるか |
|---|---|---|
| PR | ⚠ **このブランチで新しく足した URL だけ**（実測 平均 **0.00 本／PR**） | ⚠ **落ちる。**足したばかりの URL に到達できないのは、ほぼ打ち間違い |
| `main` へのマージ後・週次 | 全部（8 本） | ⚠ **落ちない**（相手先の一時的な不調で止めない） |

⚠ **既存のリンクが腐ったことは、マージするまで分からない。**
PR で見ているのは「自分が足した分」だけ。

⚠ **CI が緑でも「仕様が正しい」ではない。**

## 7. 返す形

```
Verdict: PASS / FAIL / NOT-VERIFIED

Ran:
  <入口>  <結果>  <件数>        ⚠ 回していないものは書かない

Failed:
  - <落ちた文言そのまま>
  - <こちらの不具合か、外部か>

Not verified:
  - <走らなかった検査と、その理由>

Regression guard:
  EXISTING / ADDED-AND-PROVEN / NONE    ⚠ 同じことが起きたら、次は止まるか

Mutation check:
  <修正を外した状態で、⚠ 狙った理由により FAIL したか。⚠ 落ちた文言をそのまま>

Next:
  - <Worker へ戻すのか、Review へ進むのか>
```

### ⚠ Regression guard は 3 つのどれか

| 値 | いつ |
|---|---|
| **EXISTING** | ⚠ **すでにある検査が、この不具合を捕まえる。**⚠ **捕まえることを確かめた**ときだけ |
| **ADDED-AND-PROVEN** | 検査を足し、⚠ **わざと壊して、狙った理由で落ちるところまで見た**（§5） |
| **NONE** | ⚠ **どちらでもない。**⚠ **理由を書く**（画面を変えていない／検査で表せない、など） |

⚠ **`ADDED` は無い。**⚠ 足しただけは `ADDED-AND-PROVEN` ではない（§5 の 1〜2 を通っていない）。
⚠ **`EXISTING` は「たぶん捕まえる」ではない。**⚠ **外して落ちるのを見て**いなければ `NONE`。
⚠ **不具合を直したのに `NONE` なら、`PASS` にしない。**`NOT-VERIFIED` にして、
⚠ **なぜ検査として残せないか**を書く（掟: 直した不具合は、検査として残す）。

### ⚠ Mutation check は「落ちた」では足りない

⚠ **落ちた理由が、狙った主張になっているか**まで読む。
別の理由（読み込み順・書き方の崩れ・時間切れ）で落ちていたら、
⚠ **その検査は、まだ主張を見ていない。**
⚠ **落ちた文言をそのまま控える。**要約すると、次に読む人が同じ確認をやり直せない。

| 判定 | いつ |
|---|---|
| **PASS** | ⚠ **Final Gate の 3 つを回して、3 つとも通った。**⚠ 不具合を直したなら、⚠ **Regression guard が `NONE` でない** |
| **FAIL** | 1 つでも落ちた。⚠ **外部が原因でも FAIL。**ただし「外部」と書いて再実行を勧める |
| **NOT-VERIFIED** | ⚠ **回していない検査がある。**`--only` だけ／fork の PR／外部が落ちていて回せない |

⚠ **回していない検査があるのに PASS と書かない。**
⚠ **Regression guard と Mutation check を空にしない。**⚠ 該当しないなら「該当しない」と書く。
⚠ **「通った」ではなく「何が何件」で書く**（掟: 検証していないことを「確認済み」と報告しない）。
