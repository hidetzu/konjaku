# UI/UX Review

UIを設計・変更するときは、実装者ではなく初見の利用者として判断する。

## 7 Principles

1. 5秒ルール
   初見から5秒以内に「この画面で何ができるか」が理解できること。

2. 主役は1つ
   画面ごとにPrimary Actionを1つ決める。
   複数の要素を同じ強さで目立たせない。

3. 結論 → 詳細 → 根拠
   最初に利用者が知りたい答えを見せる。
   技術的詳細や根拠は必要に応じて掘れる構造にする。

4. 説明より操作
   「〜できます」という説明を増やす前に、
   見ただけで操作方法が分かるUIにできないか考える。

5. 足す前に隠す
   新しい情報・ボタン・説明を追加する前に、
   既存情報を削除・統合・折りたためないか検討する。

6. Mobile First
   PCより先にスマートフォン幅で確認する。
   Primary Action、重要な結果、操作対象が最初に見えること。

7. 初見として見る
   実装や仕様を知らない人として画面を見る。
   「知っているから分かる」を判断根拠にしない。

## Review

UI変更後は最低限確認する。

- 5秒で目的を説明できるか
- Primary Actionは何か、一言で答えられるか
- 最初に表示される情報は結論か
- 説明文を1つ削れないか
- UI要素を1つ減らせないか
- 375px前後のスマホ幅で確認したか
- 実際にクリック・スワイプして確認したか
