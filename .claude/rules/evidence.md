## いちばん上の原則

> **面白さより先に、情報が正しいこと。**

その上で、利用者の知的好奇心・探求心をくすぐる。順序を入れ替えない。

この3つは、コードでも画面でも崩さない。

```
観測されていない  ≠  存在しなかった
取得できなかった  ≠  存在しなかった
データにない      ≠  現実にない
```

だから、

- **確認できないことを「検査済み」と呼ばない**
- **取得できなかったことを「無い」と言わない**
- **推定を実測のように見せない**

「テストが通った」ではなく、**そのテストは本当にその主張を検証しているか**を見る。
過去に「検査が測っていないことを『確認済み』と表示していた」問題が出ている。

## 数字の書き方

- **必ず主張範囲の分母で書く。** 別の範囲の数字を持ち込むと、その数字自体が嘘になる
- 実測でない数字を書かない。確率・確信度は出さない
- 実測値を残すときは、**いつ・どこで・どうやって測ったか**を再現できる形にする
- 全国の割合を、その場の一覧（8行）の下に書かない。分母が違う
- ⚠ **外向けの文章（記事・OGP・SNS・README）にも、同じ規則を適用する。**
  数字には**主張範囲の分母・測定日・測定条件**を添え、`docs/SPEC.md` §3 と
  検査結果に照合する。**同じ主張を画面と外向けで書くときは、同じ分母を使う。**
  ⚠ 別の範囲を扱ってよい。ただし**どの範囲の数字かを明示する**
  （例: 豊洲 533件 と、配っている 403,397件 は別の主張）。
  実際に踏んでいる: README が「545件/542件(99.4%)」を掲げていたが、
  画面は同じ主張を 533件/99.6% で出していた。数え方が違うだけだが、
  **README と OGP は共有先まで届く**ので、そこだけこの掟の外に出る
