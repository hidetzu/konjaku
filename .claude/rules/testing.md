# Testing

⚠ **`MUST` = 必須、`SHOULD` = 原則、`MAY` = 任意。**

⚠ **どの検査を、どの順で回すかは [`verify`](../skills/verify/SKILL.md) が正本。**⚠ ここには書かない。
⚠ **ここが持つのは「何を優先して確かめるか」だけ。**

## 目的

⚠ **「実装したこと」ではなく、⚠ 「利用者に必要な挙動が壊れていないこと」**を確かめる。

- MUST: ⚠ **テストが通ったことを、⚠ 検証の完了と呼ばない**（正本は `CLAUDE.md` §1）。

## 優先順位

1. Domain の変換・正規化
2. 状態の遷移
3. ⚠ **欠損・失敗のとき**
4. 利用者の主な操作
5. 見た目の細部

## Domain

- MUST: ⚠ **Source → Domain の変換に、代表ケースを持つ。**
- MUST: ⚠ **欠損値・空配列・知らない値**の扱いを確かめる。
- MUST: ⚠ **推定値と確定値を取り違えないこと**を確かめる。
- SHOULD: ⚠ **DOM 無しで確かめられる形**にする（⚠ `photos.js` などと同じ作り）。

## 画面

⚠ **測り方は [`ui-ux-review`](../skills/ui-ux-review/SKILL.md) が正本。**

- MUST: ⚠ **見えているだけでなく、⚠ 実際に操作できること。**
- MUST: ⚠ **目盛りやラベルの操作が、⚠ 背面の地図へ抜けないこと。**

## 直したとき

- MUST: ⚠ **直した不具合は、検査として残す**（正本は `CLAUDE.md` §2）。
- MUST: ⚠ **変更前に落ちて、⚠ 変更後に通ること**を確かめる。

## 増やしすぎない

- MUST NOT: ⚠ **実装の手順だけを固定する検査を、大量に足さない。**
- SHOULD: ⚠ **利用者から見た契約・Domain の契約・入出力**を中心に見る。
