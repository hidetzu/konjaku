## 自分で決める／人に聞く

⚠ **既定は「自分で決めて、最後まで進める」。** 手が止まるほうが損。
聞くのは、**間違えたときに取り返しがつかない**ものだけ。

| 自分で決める | 人に聞く |
|---|---|
| 実装の手順・切り出し方・検査の置き方 | ⚠ **画面に出る言葉**を変えるとき |
| 何をどう測るか | ⚠ **やることの範囲**が動くとき（`Non-goals` をまたぐ） |
| 直し方が 1 つに決まる不具合 | ⚠ **何が言えるか**（`docs/SPEC.md`）が変わるとき |
| 文書・コメント・検査を足す | 見せ方の案が 2 つ以上あって、**実測では決まらない**とき |

- 聞くときは **`AskUserQuestion`** を使う。⚠ **本文に混ぜて聞かない**（見落とされる）。
  これを使うと **Slack で聞いて、答えを受け取る**（`.claude/hooks/ask-slack.mjs`）。
  ⚠ **Slack へ出るのはこれだけ**。進捗も完了も失敗も送らない（埋もれさせない）
- ⚠ **測れば決まることを聞かない。** 先に測る（[`CLAUDE.md`](../../CLAUDE.md) §7 の 1）
- ⚠ **聞くと止まる。** 答えに依存しない仕事は、聞く**前に**終わらせておく
- ⚠ **聞いたことは記録する。** 決まったら、その理由を `docs/adr/` か `tmp/` に残す

## Issue を書き換えるとき

⚠ **AI が書き換えてよい**（2026-10-11。Owner 判断。`docs/adr/0120`）。
⚠ **起こすのもよい**（`docs/adr/0117`）。⚠ **閉じるのは人。**⚠ **ラベルも人**（上の節）。

⚠ **書き換えてよいのは、⚠ 実測で確かめたことだけ。**

| やってよい | ⚠ やってはいけない |
|---|---|
| 完了した項目に、⚠ 完了した日と PR を添える | ⚠ `Goal` / `Scope` / `Out of Scope` / `Owner Decisions` を変える |
| 事実と違う記述に、⚠ 訂正を追記する | ⚠ 元の字を消す・書き直す |
| 参照先が消えたものに、⚠ 消えたことを添える | ⚠ 推測で直す（⚠ 測っていないなら触らない） |
| ⚠ チェックを付ける（⚠ 実測で確かめたときだけ） | ⚠ 閉じる（⚠ 人が決める） |

⚠ **消さない。**⚠ **追記で直す**（⚠ なぜそう書いたかが読めなくなる）。
⚠ **古いから直すのではない。**⚠ **事実と違うから直す**
（⚠ 「時間が経った」を理由に触らない。⚠ 経緯は `docs/adr/0120`）。

### 追記は `## Updates` に集める

⚠ **2026-10-11。Owner 判断。**
⚠ **本文は当時の記録。**⚠ **`Updates` が現在との差分。**

```text
## Updates

### <日付> — <状態>        ⚠ 一部解決 ／ 解決 ／ 事実が変わった ／ 参照先が消えた

<何を確かめたか>（⚠ PR 番号つき。⚠ 実測なら数字も）

本文の「<該当箇所>」は作成時点の記録として残す。
⚠ ただし現在、<いまの事実>。

未解決:
- <残っていること>
```

⚠ **新しいものを上に積む**（⚠ 現在の事実を先に読めるように）。
⚠ **本文の該当箇所を名指す**（⚠ どこが古いのか分からないと、⚠ 読む人が本文を信じてしまう）。
⚠ **これが無いと、⚠ 長く残る Issue では訂正が散らばって、⚠ いまの事実が読めなくなる。**
