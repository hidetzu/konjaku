# Domain

⚠ **`MUST` = 必須、`SHOULD` = 原則、`MAY` = 任意。**

## 今昔が答える問い

今昔は「場所を選び、その場所の昔と今を比べ、深掘りする」道具。
機能を足すときは、⚠ **次のどれに答えるか**を先に言う。

1. どの場所を見るか
2. その場所は昔と今でどう変わったか
3. 選んだ場所を深掘りすると何が分かるか

- MUST NOT: ⚠ **この問いに答えないものを、便利そうという理由で足さない。**

## 3 つに分ける

```text
Source Data  →  Domain  →  Display  →  UI
```

⚠ **混ぜない。**

### Source Data（外から取れたもの）
国土地理院の土地条件・低湿地データ／建物／高さ／建設年／Wikidata／将来の Open Data。

- MUST: ⚠ **出典固有の形をそのまま UI へ流さない。**
- MUST NOT: ⚠ **表示の文言を持たせない。**
- SHOULD: 出典ごとの差は adapter で吸収する。

### Domain（今昔として意味のある形）
足元の判定・区分・集計。⚠ **数と意味だけを持つ。**

- MUST: ⚠ **文言を持たせない。**「543 件中 510 件が水域でした」ではなく `{water: 510, total: 543}` まで。
- MUST: ⚠ **取れた値と推定値を区別する**（正本は `CLAUDE.md` §1）。

### Display（どう見せるか）
文・並び・強調・年代の呼び名。

- MUST: ⚠ **文章化はここでやる。**
- MUST: ⚠ **言葉は 1 か所から借りる**（`public/words.js` / `public/prov.js`）。

⚠ **この分け方を実装へ寄せる作業は hidetzu/konjaku#181。**⚠ ここには構造の設計を書かない。

## 画面の責務

⚠ **画面やコンポーネントを足すときは、⚠ 責務を 1 文で言えること。**

- MUST: `/peel` は ⚠ **選んだ場所を深掘りする画面**。⚠ **別の場所を探す導線を足さない。**
- MUST: ⚠ **地図が主役。**
- SHOULD: HUD は ⚠ **年代の表示と操作だけ**（補足は別の層）。
- SHOULD: ⚠ **隠す操作を足す前に、⚠ 常時出せる大きさまで減らせないか見る。**

## 足す前に答えること

1. 利用者のどの問いに答えるか
2. 必須か、補助か
3. Source / Domain / Display のどこか
4. ⚠ **そのデータが無いとき、画面はどうなるか**
5. 別の出典を足しても構造が保てるか

- MUST NOT: ⚠ **将来使うかもしれない、という理由だけで抽象化しない。**
- SHOULD: ⚠ **2 つ目が実際に現れてから共通化する。**
